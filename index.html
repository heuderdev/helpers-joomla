Guia de uso baseado nos fontes recebidos. Os exemplos PHP ficam em blocos com botão de cópia, implementado em JavaScript puro, sem dependência externa.

Início e convenções

Os helpers usam o ambiente Joomla 3: JFactory, JFile, JFolder, JLog, JUri e, em operações de banco, o driver retornado por JFactory::getDbo(). Os arquivos iniciam com defined('_JEXEC') or die;; portanto devem ser carregados dentro de uma execução Joomla.

Contrato comum de resultado. Vários helpers de arquivo, importação, exportação, upload e fila retornam arrays no formato success, status, mensagem, data e, quando aplicável, errors. Sempre teste $resultado['success'] antes de acessar dados de sucesso.
Segurança. Os helpers de paths rejeitam NUL byte e sequências de traversal como ../. Ainda assim, defina diretórios-base específicos por domínio funcional e não exponha caminhos absolutos ao cliente.

ApiResponseHelper

Padroniza respostas JSON ou mensagens de sessão do Joomla. Uma requisição é considerada JSON quando format=json, X-Requested-With: XMLHttpRequest ou Accept: application/json estiverem presentes. O payload contém success, status, mensagem, data, errors e request_id; meta é incluído quando informado.

Configuração e detecção

setDefaultRedirect($url) · setCloseApplication($close) · setLogErrors($logErrors) · setLogCategory($category) · isJson()

setCloseApplication(true) é o padrão: em resposta JSON o helper chama $app->close(). Para testar ou continuar o fluxo após emitir o JSON, use a opção close => false ou configure a classe.

Respostas de sucesso

success($message = 'Operação realizada com sucesso.', $data = null, array $options = array()) · created(...) · updated(...) · deleted(...) · info(...) · warning(...)

created() força HTTP 201. As demais usam HTTP 200 salvo se options['http_status'] for informado. Opções reconhecidas: json, close, redirect, meta e http_status.

$cliente = array('id' => 81, 'nome' => 'Ana');

return ApiResponseHelper::created(
    'Cliente cadastrado com sucesso.',
    $cliente,
    array(
        'json' => true,
        'close' => true,
        'meta' => array('origem' => 'clientes.salvar')
    )
);

Respostas de erro

error($message = 'Não foi possível concluir a operação.', $data = null, array $errors = array(), array $options = array()) · validationError(array $errors, $message = 'Corrija os campos informados.', array $options = array())

badRequest(...) · unauthorized(...) · forbidden(...) · notFound(...) · methodNotAllowed(...) · conflict(...) · tooManyRequests(...) · internalError(...) · serviceUnavailable(...) · exception(Throwable $error, $publicMessage = ..., array $options = array()) · fromValidation(array $validation, ...)

Os atalhos definem os códigos HTTP esperados: 400, 401, 403, 404, 405, 409, 429, 500 e 503. validationError() responde 422 e desativa log por padrão. exception() registra o erro técnico, mas retorna uma mensagem pública.

$validacao = ValidationHelper::validate(
    array('email' => InputHelper::email('email')),
    array('email' => 'required|email')
);

if (!$validacao['valid']) {
    return ApiResponseHelper::fromValidation($validacao, 'Revise os campos.');
}

try {
    // Persistência do registro.
} catch (Throwable $e) {
    return ApiResponseHelper::exception(
        $e,
        'Não foi possível salvar o cliente.',
        array('json' => true, 'context' => array('modulo' => 'clientes'))
    );
}

InputHelper

Camada de leitura segura sobre JFactory::getApplication()->input. Aceita fontes request (padrão), get, post, files, server e cookie. Em falhas, registra em input_helper e retorna o padrão informado.

MétodosUso real
value($name, $default = null, $filter = 'cmd', $source = 'request')Leitura genérica usando o filtro Joomla passado.
string, raw, htmlTexto filtrado, texto raw ou HTML; string/raw podem aplicar trim.
int, uint, float, decimal, boolTipos primitivos; decimal() converte o formato brasileiro removendo pontos e trocando vírgula por ponto.
cmd, word, alnum, base64, email, username, pathFiltros especializados do Joomla; email ainda é sanitizado e validado com filter_var.
array, arrayOfIntLeitura de arrays; arrayOfInt elimina itens não numéricos e valores menores ou iguais a zero.
$id = InputHelper::uint('id', 0, 'post');
$preco = InputHelper::decimal('preco', 0, 'post'); // "1.234,56" => 1234.56
$ativo = InputHelper::bool('ativo', false, 'post');
$tags = InputHelper::arrayOfInt('tags', array(), 'post');
$descricaoHtml = InputHelper::html('descricao', '', 'post');

if ($id <= 0 || $preco <= 0) {
    return ApiResponseHelper::badRequest('ID ou preço inválido.');
}

ValidationHelper

Valida arrays de dados usando regras separadas por | ou arrays de regras. O retorno de validate() é valid, errors (por campo) e first_error. Mensagens podem ser personalizadas por regra (email) ou por campo/regra (email.required).

setMessages(array $messages) · setCustomMessages(array $messages) · setLabels(array $labels) · reset() · validate(array $data, array $rules, array $messages = array(), array $labels = array()) · firstError(array $errors) · passes(...) · fails(...)

cpf($cpf) · cnpj($cnpj) · email($email) · date($date, $format = 'Y-m-d') · file($file) · image($file)

Regras implementadas

required, string, integer|int, numeric, decimal, boolean|bool, email, url, cpf, cnpj, cpfcnpj, phone|telefone, cep, date, datebr, datetime, time, array, json, min, max, between, minlength, maxlength, length, in, notin, regex, same, different, requiredif, requiredwith, nullable, unique, exists, file, filesize, fileextension, filemime, image, imagedimensions, accepted, alpha, alphanum, alphadash, uuid, ip e callback.

Para unique, exists e callback, o parâmetro da regra deve ser um callback PHP chamável. Callables inseridos diretamente no array de regras também são executados com ($value, $data, $field).
$dados = array(
    'nome' => InputHelper::string('nome', '', 'post'),
    'email' => InputHelper::email('email', '', 'post'),
    'cpf' => InputHelper::string('cpf', '', 'post'),
    'aceite' => InputHelper::bool('aceite', false, 'post')
);

$validacao = ValidationHelper::validate(
    $dados,
    array(
        'nome' => 'required|string|minlength:3|maxlength:120',
        'email' => 'required|email',
        'cpf' => 'required|cpf',
        'aceite' => 'accepted'
    ),
    array('cpf.cpf' => 'Informe um CPF válido.'),
    array('cpf' => 'CPF')
);

if (!$validacao['valid']) {
    return ApiResponseHelper::validationError($validacao['errors']);
}

LogHelper

Escreve logs Joomla por categoria e nível, adiciona automaticamente request_id, usuário autenticado, método HTTP, URI e IP. Também mascara chaves sensíveis como senha, token, authorization, API key, cartão, CVV, cookie e sessão.

setEnabled($enabled) · setDefaultCategory($category) · setBaseDirectory($directory) · getBaseDirectory() · setDirectoryPermission($permission) · setRequestId($requestId) · getRequestId() · addSensitiveKey($key) · sanitize($context)

debug($message, $category = null, array $context = array(), $directory = null) · info(...) · notice(...) · warning(...) · error(...) · critical(...) · alert(...) · emergency(...) · exception(Throwable $error, ...) · database(Throwable $error, $query = null, ...) · security(...) · api(...) · upload(...) · queue(...) · audit(...) · payment(...)

O arquivo de saída segue o padrão {categoria}.{nivel}.php. Diretórios configurados precisam estar dentro de JPATH_SITE.

LogHelper::setBaseDirectory('logs/modulo-clientes');
LogHelper::addSensitiveKey('documento');

LogHelper::info(
    'Cliente atualizado.',
    'clientes',
    array('cliente_id' => 81, 'token' => 'segredo-nao-exposto')
);

try {
    // operação de banco
} catch (Throwable $e) {
    LogHelper::database($e, 'UPDATE #__clientes ...', array('cliente_id' => 81));
}

AuditHelper

Registra eventos de auditoria em tabela configurável, incluindo UUID, usuário Joomla, IP, user-agent, referer, método e URI da requisição. Os dados são sanitizados antes da serialização JSON; campos sensíveis são mascarados. Eventos só aceitam caracteres a-z A-Z 0-9 _ . : -.

Métodos públicos verificados: setTable($table) · setEnabled($enabled) · setLogCategory($category) · setMaxTextLength($length) · setMaxDataLength($length) · addSensitiveKey($key) · sanitize($data) · custom($event, array $options = array())

O helper também expõe atalhos de auditoria para ações de domínio e segurança, incluindo criação, atualização, exclusão, login, logout, acesso negado e eventos customizados. Use custom() quando o evento não se encaixar em um atalho.

AuditHelper::setTable('#__audit_logs');

AuditHelper::custom('cliente.atualizado', array(
    'category' => 'clientes',
    'entity_type' => 'cliente',
    'entity_id' => 81,
    'description' => 'Cadastro alterado pelo operador.',
    'metadata' => array(
        'antes' => array('status' => 'inativo'),
        'depois' => array('status' => 'ativo'),
        'authorization' => 'nao-sera-gravado-em-claro'
    )
));

DbTransactionHelper

Encapsula transações Joomla com suporte a profundidade e savepoints. Identifica como recuperáveis os códigos 1205 e 1213 e mensagens como deadlock found, lock wait timeout e serialization failure; quando configurado, faz retry com backoff exponencial, limitado a 5 segundos por espera.

setLogCategory($category) · setLogDirectory($directory) · setAuditEnabled($enabled) · setMaxRetries($maxRetries) · setRetryDelayMicroseconds($microseconds) · setRetryableErrorCodes(array $codes) · isActive() · depth() · begin() · commit() · rollback()

run($callback, array $options = array()) · attempt($callback, array $options = array()) · transaction($callback, array $options = array())

run() e transaction() lançam a exceção final. attempt() a captura e devolve um envelope de sucesso/erro. O callback recebe ($db, $attempt).

$resultado = DbTransactionHelper::attempt(
    function ($db, $attempt) {
        $registro = (object) array('nome' => 'Novo cliente', 'email' => 'ana@empresa.test');
        $db->insertObject('#__clientes', $registro, 'id');

        return array('cliente_id' => (int) $registro->id, 'attempt' => $attempt);
    },
    array(
        'retries' => 3,
        'audit_event' => 'cliente.criado',
        'context' => array('origem' => 'admin.clientes')
    )
);

if (!$resultado['success']) {
    return ApiResponseHelper::internalError($resultado['mensagem']);
}

OrmBase e OrmTables

OrmBase é um construtor de consultas e persistência sobre o driver Joomla. OrmTables cria ou registra instâncias reutilizáveis e sempre retorna clones, evitando manter filtros da consulta anterior.

OrmTables

table($table, array $options = array()) · make(...) · get($name, $table = null, array $options = array()) · register($name, $table, array $options = array()) · has($name) · forget($name) · flush() · all()

OrmBase: construção e leitura

__construct($table, array $options = array()) · table($table, array $options = array()) · db() · tabelaAtual() · newQuery() · select(...) · where(...) · orWhere(...) · whereIn(...) · whereNotIn(...) · whereNull(...) · whereNotNull(...) · whereBetween(...) · whereLike(...) · whereRaw(...)

OrmBase: escrita

create(array $data) · createMany(array $list) · firstOrCreate(array $conditions, array $additional = array()) · updateOrCreate(array $conditions, array $data) · update($id, array $data) · updateWhere(array $data) · increment($id, $column, $quantity = 1) · decrement(...) · touch($id) · delete($id) · deleteWhere() · restore($id) · forceDelete($id) · transaction(callable $callback)

Opções úteis: primaryKey, timestamps, createdAtColumn, updatedAtColumn, softDeletes, deletedAtColumn, casts, fillable e guarded. A lista fillable e guarded atua junto às colunas reais retornadas pelo banco.

$clientes = OrmTables::table('#__clientes', array(
    'softDeletes' => true,
    'casts' => array('ativo' => 'bool', 'config' => 'json'),
    'fillable' => array('nome', 'email', 'ativo', 'config')
));

$cliente = $clientes
    ->where('ativo', 1)
    ->whereLike('nome', 'Ana')
    ->orderBy('nome')
    ->first();

$novo = $clientes->create(array(
    'nome' => 'Ana Souza',
    'email' => 'ana@empresa.test',
    'ativo' => true,
    'config' => array('recebe_email' => true)
));
Evite montar whereRaw(), having() e condições de join() com dados de usuário. Esses trechos são SQL cru; os demais filtros do builder fazem quoting de valores.

UploadMaster

Upload seguro de arquivos, com validação de erro PHP, tamanho, extensão, MIME real via Fileinfo e compatibilidade extensão/MIME. A lista padrão aceita imagens, PDF, texto, CSV, planilhas, documentos Office, ZIP e alguns vídeos; extensões perigosas, como PHP, PHAR, scripts, executáveis, .env e SQL, são explicitamente proibidas.

setBaseDirectory($directory) · getBaseDirectory() · setMaxFileSize($bytes) · setAllowedExtensions(array $extensions) · setAllowedMimes(array $mimes) · setThrowExceptions($throwExceptions) · formatBytes($bytes, $precision = 2) · getFileFromInput($fieldName, $index = null)

Opções relevantes: baseDirectory, maxSize, allowedExtensions, allowedMimes, overwrite, prefix, keepOriginalName. thumbnail() exige extensão GD e aceita crop, quality, prefix, filename e overwrite.

$arquivo = UploadMaster::getFileFromInput('documento');

$resultado = UploadMaster::upload(
    $arquivo,
    'clientes/81/documentos',
    null,
    array(
        'baseDirectory' => 'media/app/uploads',
        'allowedExtensions' => array('pdf', 'jpg', 'jpeg', 'png'),
        'allowedMimes' => array('application/pdf', 'image/jpeg', 'image/png'),
        'maxSize' => 10 * 1024 * 1024,
        'prefix' => 'cliente_81'
    )
);

if (!$resultado['success']) {
    return ApiResponseHelper::validationError(array(
        'documento' => array($resultado['mensagem'])
    ));
}

$dadosArquivo = $resultado['data']; // path, relative_path, url, mime, size etc.

CsvHelper

Utilitário para criação, leitura e processamento de CSV com base autorizada, codificação UTF-8/UTF-8-SIG, remoção de BOM e conversão via mb_convert_encoding ou iconv quando disponíveis. Os delimitadores, encapsuladores e escapes são validados para terem um caractere — exceto escape, que pode ser vazio.

Configuração e métodos públicos: setBaseDirectory(...) · getBaseDirectory() · setLogDirectory(...) · setDelimiter(...) · setEnclosure(...) · setEscape(...) · setEncoding(...) · export(...) · import(...) · read(...) · write(...) · append(...) · download(...) · info(...)

Use uma base exclusiva para importar/exportar, e preserve o mesmo delimitador no lado que gera e no lado que consome o arquivo.

ExportHelper

Gera exportações CSV com proteção de paths dentro de JPATH_SITE, nome de arquivo saneado e extensão .csv. Normaliza valores: null vira string vazia, booleanos viram “Sim”/“Não”, DateTime vira Y-m-d H:i:s e estruturas complexas são serializadas.

Métodos públicos de configuração e exportação: setBaseDirectory(...) · getBaseDirectory() · setLogDirectory(...) · setDelimiter(...) · setEnclosure(...) · setEscape(...) · export(...) · download(...) · save(...) · stream(...)

        'baseDirectory' => 'media/app/exportacoes',

ChunkUploadHelper

Processa arquivos grandes em blocos de leitura, com offset e fingerprint do arquivo. Ele exige um callback válido de processamento e trabalha com paths restritos à base autorizada. É apropriado para importações CSV em múltiplas requisições, evitando timeout e memória excessiva.

Métodos públicos: setBaseDirectory(...) · getBaseDirectory() · setLogDirectory(...) · setDefaultReadSize(...) · setMinReadSize(...) · setMaxReadSize(...) · setDefaultRowsPerChunk(...) · process(...) · processCsv(...) · status(...) · reset(...)

O callback deve ser idempotente sempre que possível: uma chamada pode precisar ser repetida quando uma requisição falhar no meio do processamento.

$estado = ChunkUploadHelper::processCsv(
    'importacoes/clientes.csv',
    function (array $linhas, array $contexto) {
        foreach ($linhas as $linha) {
            // Faça upsert ou outra operação idempotente.
            // $contexto informa posição/fingerprint do processamento.
        }

        return array('processadas' => count($linhas));
    },
    array(
        'baseDirectory' => 'media/app/importacoes',
        'rowsPerChunk' => 500,
        'delimiter' => ';',
        'hasHeader' => true
    )
);

// O retorno informa sucesso, progresso/offset e se ainda há dados a processar.

QueueHelper

Fila persistida em banco. Estados: pending, processing, retry, completed, failed e cancelled. A reserva de trabalho cria um lock_token; heartbeat, progresso, conclusão e falha exigem esse token. Payload, resultado e erro possuem limites configurados e campos sensíveis são mascarados no log.

setTable($table) · setDefaultQueue($queue) · setLogCategory($category) · setLogDirectory($directory) · setDefaultMaxAttempts($attempts) · setDefaultTimeoutSeconds($seconds) · setDefaultRetryAfterSeconds($seconds) · setDefaultRetryDelaySeconds($seconds)

push($type, array $payload = array(), array $options = array()) · find($idOrUuid) · next(array $allowedTypes = array(), $queue = null, array $options = array()) · heartbeat($id, $lockToken) · progress($id, $lockToken, $progress, $total = null) · complete($id, $lockToken, array $result = array()) · release($id, $lockToken, array $options = array()) · fail($id, $lockToken, $errorMessage, array $options = array())

cancel($idOrUuid, $userId = null, $force = false) · retry($idOrUuid, $userId = null) · releaseExpiredLocks($defaultRetryAfterSeconds = null) · status($idOrUuid, $userId = null) · list(array $filters = array(), $limit = 50, $offset = 0) · count(array $filters = array()) · purge($dateBefore, array $statuses = array(), $limit = 1000)

$novo = QueueHelper::push('importar_clientes', array(
    'arquivo' => 'importacoes/clientes.csv',
    'usuario_id' => 15
), array(
    'queue' => 'importacoes',
    'prioridade' => 10,
    'maxTentativas' => 3,
    'usuarioId' => 15
));

// Em um worker/cron:
$job = QueueHelper::next(array('importar_clientes'), 'importacoes');
if ($job) {
    try {
        QueueHelper::progress($job->id, $job->locktoken, 10, 100);
        // Processar $job->payload.
        QueueHelper::complete($job->id, $job->locktoken, array('importados' => 100));
    } catch (Throwable $e) {
        QueueHelper::fail($job->id, $job->locktoken, $e->getMessage());
    }
}
Worker obrigatório. A classe enfileira e reserva jobs, mas não executa automaticamente um daemon. Crie um comando CLI ou cron que chame next(), processe o payload e termine sempre com complete(), fail() ou release().
