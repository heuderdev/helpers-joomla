OrmBase: configuração

Como criar uma instância do ORM e todas as opções que mudam o seu comportamento.

Criando uma instância

Todas as formas abaixo produzem o mesmo tipo de objeto e aceitam as mesmas opções:

// Pelo atalho (o mais comum)
$q = OrmTables::table('#__loja_produtos', $opcoes);

// Pelo construtor
$q = new OrmBase('#__loja_produtos', $opcoes);

// Pelo método estático
$q = OrmBase::tabela('#__loja_produtos', $opcoes);

// Por um model (a tabela vem da classe)
$q = ProdutoModel::query($opcoes);

Se a tabela não for informada nem pelo parâmetro nem pela propriedade $table de um model, o construtor lança InvalidArgumentException.

Opções

Só as opções informadas mudam algo. As outras mantêm o padrão ou o valor declarado no model. Opções com valor null são ignoradas, exceto connection.

casts: tipos dos valores

O banco devolve quase tudo como string. Com casts, o ORM converte os valores ao ler (get, first, find, paginate, chunk, e no retorno de create/update).

$pedidos = OrmTables::table('#__loja_pedidos', [
    'casts' => [
        'id' => 'int',
        'total' => 'float',
        'pago' => 'bool',
        'metadados' => 'json',
    ],
]);

$pedido = $pedidos->find(1);

var_dump($pedido->total);              // float(30.5)   em vez de "30.50"
var_dump($pedido->pago);               // bool(true)    em vez de "1"
echo $pedido->metadados['origem'];     // array         em vez de '{"origem":"site"}'

int, integer(int)sem conversão
float, double(float)sem conversão
bool, booleantrue/false. Entende 't'/'f' do PostgreSQL.1/0
string(string)sem conversão

fillable e guarded: colunas permitidas

Controlam quais colunas create, update, updateWhere, firstOrCreate e updateOrCreate podem gravar. Protegem contra gravar campos que vieram no POST sem você querer (por exemplo, id ou admin).

// Lista do que PODE ser gravado (recomendado)
$usuarios = OrmTables::table('#__loja_clientes', [
    'fillable' => ['nome', 'email', 'telefone'],
]);

// Lista do que NÃO pode ser gravado
$usuarios = OrmTables::table('#__loja_clientes', [
    'guarded' => ['id', 'saldo', 'admin'],
]);

// 'admin' é descartado em silêncio
$usuarios->create(['nome' => 'Ana', 'email' => 'ana@ex.com', 'admin' => 1]);

A ordem dos filtros, para cada coluna enviada:

  1. a coluna precisa existir na tabela (o ORM consulta as colunas uma vez por instância);
  2. se fillable não estiver vazio, precisa estar nele;
  3. não pode estar em guarded.

Colunas que não passam nos filtros são descartadas sem erro. Se um campo "não grava", confira o nome da coluna e as listas fillable/guarded.

timestamps: datas automáticas

OperaçãoO que é preenchido
create, createManycreated_at e updated_at
update, updateWhere, updateOrCreate (quando atualiza), touchupdated_at
increment, decrementnada

As datas são gravadas em UTC com DateHelper::nowSql(), como o restante do Joomla. Para mostrar no fuso do usuário, use DateHelper::toUser().

Vem ligado por padrão e o ORM não confere se as colunas existem. Em tabelas sem created_at/updated_at, desligue, senão create/update falham com erro de coluna desconhecida:

OrmTables::table('#__loja_logs', ['timestamps' => false]);

// Ou com outros nomes de coluna
OrmTables::table('#__legado_clientes', [
    'createdAtColumn' => 'data_cadastro',
    'updatedAtColumn' => 'data_alteracao',
]);

softDeletes: exclusão lógica

Com softDeletes, "excluir" grava a data em deleted_at e o registro some das consultas, mas continua no banco e pode ser restaurado.

$pedidos = OrmTables::table('#__loja_pedidos', ['softDeletes' => true]);

$pedidos->delete(10);           // UPDATE ... SET deleted_at = '2026-10-03 14:00:00'
$pedidos->find(10);             // null: some das consultas
$pedidos->restore(10);          // volta: deleted_at = NULL
$pedidos->forceDelete(10);      // DELETE de verdade
MétodoSem softDeletesCom softDeletes
get, first, find, count, paginate… (leitura)todos os registrossó os com deleted_at IS NULL
delete($id)DELETEUPDATE … SET deleted_at = agora
deleteWhere()DELETE … WHEREUPDATE … SET deleted_at = agora WHERE

Para listar os excluídos (uma "lixeira"), use uma instância sem softDeletes: OrmTables::table('#__loja_pedidos')->whereNotNull('deleted_at')->get(). Veja a receita da lixeira.

primaryKey: chave primária

Coluna usada por find, findOrFail, update, delete, restore, forceDelete, increment, decrement e touch, e para ler o id gerado em create.

$clientes = OrmTables::table('#__legado_clientes', ['primaryKey' => 'cliente_id']);
$cliente = $clientes->find(42);   // WHERE cliente_id = 42

Esses métodos convertem o id para inteiro. Chaves texto (UUID, códigos) não funcionam com eles: use where('codigo', $codigo)->first(), updateWhere() e deleteWhere().

connection: qual banco

OrmTables::table('#__clientes', ['connection' => 'erp']);          // nome registrado
OrmTables::table('#__clientes', ['connection' => $driver]);        // driver pronto
OrmTables::table('#__clientes', ['connection' => null]);           // Joomla (padrão)

Veja DbConnectionHelper e o guia de múltiplos bancos.

Métodos utilitários

db()

$orm->db(): object

Devolve o driver do Joomla usado pela instância. Útil para SQL que o ORM não cobre, na mesma conexão.

$db = $orm->db();
$db->setQuery('SELECT VERSION()');
$versao = $db->loadResult();

serverType()

$orm->serverType(): string

DbConnectionHelper::MYSQL ou DbConnectionHelper::POSTGRESQL, conforme o banco da instância.

tabelaAtual()

$orm->tabelaAtual(): string

O nome da tabela, como foi informado (com #__ e alias, se houver).

newQuery()encadeável

$orm->newQuery(): $this

Descarta os filtros acumulados (where, joins, ordem, limite, trava…). Raramente é necessário, porque os métodos finais já fazem isso.
