ChunkHelper

Processamento segmentado de arquivos gigantes, leitura sequencial em blocos de bytes ou linhas, divisão física de arquivos, e reprocessamento resiliente a quedas/timeouts via checkpoints JSON.

Visão geral

O ChunkHelper (fornecido pelo arquivo ChunkUploadHelper.php) é uma solução de alta performance projetada para processar arquivos massivos (de centenas de megabytes ou gigabytes, como dumps de bancos, planilhas CSV corporativas, ou logs brutos) sem estourar o limite de memória (memory_limit) ou de tempo de execução (max_execution_time) do servidor PHP.

Dentre as principais vantagens e arquitetura empregadas na ferramenta, destacam-se:

  • Portabilidade e Desacoplamento Total: Embora projetado inicialmente para Joomla, o helper foi desenvolvido com uma arquitetura agnóstica baseada em wrappers dinâmicos. Caso seja carregado fora do Joomla (em projetos Laravel, Symfony, scripts CLI puros ou microsserviços), ele detecta a ausência do framework e chaveia automaticamente todas as operações de log e de manipulação de disco para as funções nativas do PHP (is_dir, mkdir, unlink, rename, etc.).
  • Processamento Baseado em Bytes (`readBytes`): Lê trechos binários sequenciais de tamanho pré-definido, repassando o buffer a uma função callback.
  • Processamento Baseado em Linhas (`readLines`): Lê arquivos texto linha a linha, agrupa as linhas processadas em lotes (chunks) e dispara callbacks por lote. Ideal para leitura sob demanda de planilhas de dados gigantes de forma extremamente rápida.
  • Resiliência via Checkpoint JSON (`resumeLines`): Registra o progresso do processamento (linha atual, bytes lidos, métricas) em um arquivo de progresso em disco (checkpoint). Se o servidor cair, o script estourar o timeout ou a conexão cair, basta acionar a função novamente: ela lerá o checkpoint e **retomará o processamento exatamente do ponto onde parou**, evitando reprocessar registros e duplicar gravações!
  • Divisão Física de Arquivos (`splitFile`): Divide arquivos gigantes em vários pedaços físicos menores delimitados por quantidade de linhas ou tamanho de bytes, ideal para criar filas de uploads segmentados em background.

Configurações globais

Limites físicos de leitura, buffers de memória e pastas padrões de operação.

setBaseDirectory() / getBaseDirectory()estático

ChunkHelper::setBaseDirectory(string|null $directory): void
ChunkHelper::getBaseDirectory(): string|null

Define ou consulta o diretório raiz das operações físicas. Caminhos relativos fornecidos aos métodos serão resolvidos relativamente a esta pasta (sandbox de segurança JPATH_SITE).

setDefaultReadSize() / setMaxReadSize()estático

ChunkHelper::setDefaultReadSize(int $readSize): void
ChunkHelper::setMaxReadSize(int $readSize): void

Controla os buffers de tamanho padrão de leitura de blocos binários em bytes (padrão: 8MB; limite máximo aceitável: 64MB).

setDefaultRowsPerChunk()estático

ChunkHelper::setDefaultRowsPerChunk(int $rowsPerChunk): void

Altera a quantidade padrão de linhas agrupadas por bloco enviada a cada ciclo do callback em `readLines()` (padrão: 1000 linhas).

Leitura Segmentada de Arquivos

Métodos de stream para leitura fluida de arquivos e controle de memória.

readBytes()estático

ChunkHelper::readBytes(string $path, callable $callback, string|null $baseDirectory = null, array $options = []): array

Lê um arquivo de forma binária sequencial em blocos de bytes e repassa cada bloco para a função callback informada. Útil para fazer hashing incremental ou uploads em streaming de arquivos binários.

$resultado = ChunkHelper::readBytes('instalador.iso', function (string $buffer, array $status) {
    // Processar bloco binário de 8MB
    HashService::update($buffer);
}, null, [
    'read_size' => 8388608 // Buffer customizado de bytes
]);

readLines()estático

ChunkHelper::readLines(string $path, callable $callback, string|null $baseDirectory = null, array $options = []): array

Abre o arquivo físico, lê linha a linha utilizando ponteiros de baixo consumo de recursos, agrupa as linhas processadas em lotes de tamanho `rows_per_chunk` e dispara o callback fornecido.

O callback do usuário deve possuir a assinatura:

function (array $linhasDoLote, array $statusProcessamento): void

$resultado = ChunkHelper::readLines('planilha_usuarios.csv', function (array $linhas, array $status) {
    foreach ($linhas as $linha) {
        // Cada item é uma string de linha limpa sem o caractere newline '\n'
        UsuarioService::importarLinha($linha);
    }
}, null, [
    'rows_per_chunk' => 500 // Tamanho do lote
]);

Resiliência com Checkpoints

Garantia de processamento tolerante a falhas mecânicas, ideal para scripts pesados em cron de sincronização.

resumeLines()estático

ChunkHelper::resumeLines(string $path, string $checkpointPath, callable $callback, string|null $baseDirectory = null, array $options = []): array

Semelhante ao `readLines()`, mas o método cria e atualiza dinamicamente um arquivo JSON de checkpoint no caminho `checkpointPath` (salvando o estado a cada lote processado com sucesso).

Se o processo falhar no meio (timeout, falha de rede), bastará acionar o método novamente com os mesmos parâmetros: o `resumeLines()` lerá o checkpoint e saltará (via `fseek` rápido) os ponteiros diretamente para a linha física exata onde o último lote com sucesso foi processado, retomando a execução imediatamente!

Processamento tolerante a quedas
$arquivoPlanilha   = 'data/importacoes/cooperados_gigante.csv';
$arquivoCheckpoint = 'data/checkpoints/cooperados.json';

$resultado = ChunkHelper::resumeLines(
    $arquivoPlanilha, 
    $arquivoCheckpoint, 
    function (array $linhas, array $status) {
        foreach ($linhas as $linha) {
            SincronizarService::processar($linha);
        }
    },
    null,
    [
        'rows_per_chunk' => 1000,
        'checkpoint_interval' => 1 // Salva progresso a cada 1 lote concluído
    ]
);

// Se terminou com sucesso completo, exclui o checkpoint
if ($resultado['data']['status'] === 'completed') {
    ChunkHelper::deleteCheckpoint($arquivoCheckpoint);
    echo "Sincronização concluída com sucesso total!";
} else {
    echo "Processamento pausado ou interrompido. Reexecute para retomar!";
}

deleteCheckpoint()estático

ChunkHelper::deleteCheckpoint(string $checkpointPath, string|null $baseDirectory = null): bool

Remove de forma limpa o arquivo JSON de checkpoint do disco de operação.

Divisão Física de Arquivos (Split)

Segmentação física de arquivos massivos.

splitFile()estático

ChunkHelper::splitFile(string $sourcePath, string $destinationDirectory, string|null $baseDirectory = null, array $options = []): array

Divide um arquivo massivo de origem física em vários arquivos menores sequenciais dentro da pasta informada.

Opções aceitas no array:

Opção Tipo Padrão Descrição
'mode' string 'lines' Corte físico do arquivo. Use 'lines' para fatiar por contagem de linhas ou 'bytes' para fatiar por tamanho físico.
'chunk_size' int 50000 Se o modo for 'lines', indica o número de linhas físicas por arquivo resultante. Se o modo for 'bytes', indica o tamanho em bytes de cada arquivo resultante (ex: 10MB = 10485760).
'prefix' string 'chunk' Prefixo dos arquivos menores gerados (ex: 'chunk_0001.csv', 'chunk_0002.csv').
'keep_header' bool false Se true (no modo lines), o helper extrai a primeira linha (cabeçalho) do arquivo original e **copia automaticamente este cabeçalho no início de todos os mini-arquivos fatiados**, gerando pacotes independentes válidos para leitura!

Exemplo prático no Controller

Abaixo, veja um exemplo exaustivo de como utilizar o ChunkHelper em um Controller Joomla para realizar uma importação batch resiliente e assíncrona. O exemplo utiliza o InputHelper para capturar os caminhos, o ChunkHelper para realizar a importação em lotes salvando checkpoints de progresso, e o ApiResponseHelper para reportar o progresso em tempo real para um painel web SPA.

Exemplo: Controller de Importação com Retomada Resiliente (SPA Progress)
require_once JPATH_COMPONENT . '/helpers/IncludeHelper.php';

// Garantir o carregamento das dependências através do IncludeHelper de forma topológica!
IncludeHelper::load(['InputHelper', 'ApiResponseHelper', 'ChunkUploadHelper', 'FileHelper']);

class LojaControllerSincronismo extends JControllerLegacy
{
    /**
     * Executa ou retoma uma importação segmentada de grande porte reportando progresso parcial
     */
    public function processarSincronia()
    {
        JSession::checkToken('get') or jexit('Token inválido.');

        try {
            // 1. Caminhos de operação dentro do sandbox do FileHelper
            $arquivoPlanilha   = 'data/planilhas/estoque_gigante.txt';
            $arquivoCheckpoint = 'data/checkpoints/estoque_sincronia.json';

            $baseDir = JPATH_SITE . '/administrator/components/com_loja';
            FileHelper::setBaseDirectory($baseDir);

            // Verificar se o arquivo físico a ser processado existe
            if (!FileHelper::exists($arquivoPlanilha)) {
                return ApiResponseHelper::notFound('Arquivo de estoque gigante para processamento não encontrado.');
            }

            // 2. Chamar o ChunkHelper para ler/retomar em blocos com checkpoint ativo
            // O resumeLines detecta sozinho se o estoque_sincronia.json existe e lê a linha de reinício!
            $resultado = ChunkHelper::resumeLines(
                $arquivoPlanilha,
                $arquivoCheckpoint,
                function (array $linhasDoLote, array $status) {
                    // Este callback será executado em lotes de 1000 linhas
                    $registros = [];
                    foreach ($linhasDoLote as $linha) {
                        $colunas = explode('\t', $linha); // Supondo arquivo tabulado
                        if (count($colunas) >= 3) {
                            $registros[] = [
                                'sku' => trim($colunas[0]),
                                'preco' => (float) $colunas[1],
                                'estoque' => (int) $colunas[2]
                            ];
                        }
                    }

                    // Gravar o lote no banco de dados
                    if (!empty($registros)) {
                        EstoqueService::atualizarEmLote($registros);
                    }
                },
                $baseDir,
                [
                    'rows_per_chunk' => 1000,
                    'checkpoint_interval' => 1 // Salva o checkpoint em disco a cada lote de 1000 linhas concluído
                ]
            );

            // 3. Analisar o relatório do lote
            $statusFinal = $resultado['data']['status']; // 'completed' ou 'paused' (se atingisse limitação)
            
            // Métricas calculadas analiticamente pelo ChunkHelper
            $progresso = [
                'total_linhas' => $resultado['data']['total_lines'],
                'linhas_processadas' => $resultado['data']['processed_lines'],
                'porcentagem_concluida' => round(($resultado['data']['processed_lines'] / max(1, $resultado['data']['total_lines'])) * 100, 2),
                'tamanho_arquivo' => ChunkHelper::formatBytes($resultado['data']['file_size']),
                'bytes_lidos' => ChunkHelper::formatBytes($resultado['data']['bytes_read'])
            ];

            if ($statusFinal === 'completed') {
                // Se completou a leitura de todo o arquivo, limpamos o checkpoint
                ChunkHelper::deleteCheckpoint($arquivoCheckpoint, $baseDir);

                return ApiResponseHelper::success('Sincronização de estoque concluída com sucesso total!', [
                    'finalizado' => true,
                    'metricas' => $progresso
                ]);
            }

            // Caso o script tenha sido desenhado para pausar (parcialmente) para dar vazão à requisições Ajax
            return ApiResponseHelper::success('Lote de sincronização processado com sucesso parcial!', [
                'finalizado' => false,
                'metricas' => $progresso
            ]);

        } catch (Throwable $e) {
            return ApiResponseHelper::exception($e, 'Erro ao processar importação resiliente de estoque.');
        }
    }
}

Dica: O exemplo acima é excelente para acionamento sequencial via Ajax. Mas para o **melhor cenário de UX/Arquitetura**, o fluxo ideal deve ser dividido em duas etapas distintas:

  1. Etapa 1 (Upload do arquivo): O usuário envia a planilha física, o sistema a salva no disco de forma segura e registra um registro de controle (com status 'pendente', total de linhas, etc.) no banco de dados.
  2. Etapa 2 (Processamento assíncrono acionado por clique): O usuário aciona uma segunda view, que carrega o caminho salvo no banco e inicia o processamento dos lotes através do ChunkHelper, atualizando o progresso da importação em tempo real diretamente na tabela de controle para monitoramento.
Exemplo Avançado: Fluxo Completo de Upload, Registro e Processamento
require_once JPATH_COMPONENT . '/helpers/IncludeHelper.php';

// Garantir o ecossistema carregado via IncludeHelper!
IncludeHelper::load(['InputHelper', 'ApiResponseHelper', 'ChunkUploadHelper', 'FileHelper', 'OrmTables', 'AuditHelper']);

class LojaControllerImportacao extends JControllerLegacy
{
    /**
     * Etapa 1: Recebe o upload da planilha física, salva em pasta segura e cria o registro de controle no banco
     */
    public function uploadPlanilha()
    {
        JSession::checkToken() or jexit('Token inválido.');

        try {
            $arquivo = InputHelper::file('planilha_dados');

            if ($arquivo === null) {
                return ApiResponseHelper::validationError(['planilha' => ['Por favor, envie um arquivo válido.']]);
            }

            // 1. Configurar diretórios usando FileHelper
            $baseDir = JPATH_SITE . '/administrator/components/com_loja';
            FileHelper::setBaseDirectory($baseDir);
            FileHelper::ensureDirectory('uploads_planilhas');

            // 2. Gerar nome físico único e seguro
            $extensao = FileHelper::fileGetExt($arquivo['name']);
            $nomeFisico = FileHelper::randomFileName('import', $extensao);
            $caminhoRelativo = 'uploads_planilhas/' . $nomeFisico;

            // 3. Salvar o arquivo
            $salvar = FileHelper::move($arquivo['tmp_name'], $caminhoRelativo, null, $baseDir);

            if (!$salvar['success']) {
                throw new RuntimeException('Falha física ao salvar o arquivo enviado no servidor.');
            }

            // 4. Analisar rapidamente o arquivo para contar as fatias totais de linhas
            $info = ChunkHelper::info($caminhoRelativo, $baseDir);

            // 5. Registrar no banco via ORM para controle da view de monitoramento
            $importacao = OrmTables::table('#__loja_importacoes')->create([
                'caminho_arquivo' => $caminhoRelativo,
                'nome_original' => $arquivo['name'],
                'status' => 'pendente',
                'linhas_totais' => $info['data']['lines_count'],
                'linhas_processadas' => 0,
                'created_at' => JFactory::getDate()->toSql()
            ]);

            // Auditar ação de upload
            AuditHelper::created('importacao_planilha', $importacao->id, (array) $importacao, [
                'description' => 'Upload e registro da planilha de faturamento #' . $importacao->id
            ]);

            return ApiResponseHelper::success('Planilha enviada com sucesso! Pronto para iniciar o processamento.', [
                'import_id' => $importacao->id,
                'linhas_totais' => $importacao->linhas_totais
            ]);

        } catch (Throwable $e) {
            return ApiResponseHelper::exception($e, 'Não foi possível processar o upload do arquivo.');
        }
    }

    /**
     * Etapa 2: Acionada via clique do botão "Importar", processa as linhas da planilha em chunks resilientes
     */
    public function processarPlanilha()
    {
        JSession::checkToken('get') or jexit('Token inválido.');

        try {
            $importId = InputHelper::int('import_id');

            if ($importId <= 0) {
                return ApiResponseHelper::badRequest('ID de importação inválido.');
            }

            // 1. Localizar o registro de faturamento no banco de dados via ORM
            $ormImport = OrmTables::table('#__loja_importacoes');
            $import = $ormImport->find($importId);

            if (!$import) {
                return ApiResponseHelper::notFound('Registro de importação não cadastrado.');
            }

            if ($import->status === 'concluido') {
                return ApiResponseHelper::success('Esta importação já foi totalmente processada anteriormente!', [
                    'finalizado' => true
                ]);
            }

            // 2. Marcar o status como em andamento no banco de dados
            $ormImport->update($importId, ['status' => 'processando']);

            // 3. Definir sandbox e caminhos do faturamento e checkpoint
            $baseDir = JPATH_SITE . '/administrator/components/com_loja';
            $arquivoCheckpoint = 'data/checkpoints/import_' . $importId . '.json';

            // 4. Iniciar processamento por lotes com ChunkHelper
            $resultado = ChunkHelper::resumeLines(
                $import->caminho_arquivo,
                $arquivoCheckpoint,
                function (array $linhas, array $status) use ($importId) {
                    $loteClientes = [];
                    foreach ($linhas as $linha) {
                        $colunas = explode(';', $linha);
                        if (count($colunas) >= 2) {
                            $loteClientes[] = [
                                'nome' => trim($colunas[0]),
                                'documento' => trim($colunas[1])
                            ];
                        }
                    }

                    // Gravar os clientes do lote
                    if (!empty($loteClientes)) {
                        ClientesService::salvarEmLote($loteClientes);
                    }

                    // ATUALIZAÇÃO EM TEMPO REAL:
                    // Atualiza a tabela de controle com o progresso exato deste lote,
                    // permitindo que requisições Ajax de polling mostrem a barra de progresso real ao usuário!
                    OrmTables::table('#__loja_importacoes')->update($importId, [
                        'linhas_processadas' => $status['processed_lines']
                    ]);
                },
                $baseDir,
                [
                    'rows_per_chunk' => 1000,
                    'checkpoint_interval' => 1
                ]
            );

            // 5. Verificar estado de conclusão
            if ($resultado['data']['status'] === 'completed') {
                // Sincronia concluída com sucesso
                $ormImport->update($importId, [
                    'status' => 'concluido',
                    'linhas_processadas' => $resultado['data']['processed_lines']
                ]);

                ChunkHelper::deleteCheckpoint($arquivoCheckpoint, $baseDir);

                // Auditar conclusão
                AuditHelper::log('import_completed', [
                    'category' => 'importacao',
                    'entity_type' => 'importacao_planilha',
                    'entity_id' => $importId,
                    'description' => 'Processamento da planilha #' . $importId . ' concluído com sucesso total.'
                ]);

                return ApiResponseHelper::success('Importação de dados faturados finalizada com sucesso!', [
                    'finalizado' => true,
                    'linhas_processadas' => $resultado['data']['processed_lines']
                ]);
            }

            // Caso o lote tenha parado parcialmente (por limitações de execução ou requisição)
            return ApiResponseHelper::success('Lote processado, reexecute para continuar o progresso.', [
                'finalizado' => false,
                'linhas_processadas' => $resultado['data']['processed_lines']
            ]);

        } catch (Throwable $e) {
            // Em caso de quebra, salva o status de erro e registra na auditoria
            if (isset($importId) && $importId > 0) {
                OrmTables::table('#__loja_importacoes')->update($importId, ['status' => 'erro']);
                AuditHelper::exception($e, [
                    'category' => 'importacao',
                    'metadata' => ['import_id' => $importId]
                ]);
            }

            return ApiResponseHelper::exception($e, 'Erro fatal durante o processamento da planilha.');
        }
    }
}
