OrmBase: escrita

Inserir, atualizar e excluir, por id ou pelos filtros, com proteção contra alterações em massa acidentais.

Visão geral

Todos os métodos de gravação passam os dados pelos mesmos filtros: só colunas que existem na tabela e que fillable/guarded permitem; casts json e bool convertidos; datas automáticas preenchidas. Valores null viram NULL e true/false viram 1/0.

Inserindo

create()executa a consulta

$orm->create(array $dados): object|null

Insere um registro e o devolve lido de novo do banco, com o id gerado, as datas automáticas e os casts. No PostgreSQL usa INSERT … RETURNING; no MySQL, o id de auto incremento.

$pedido = OrmTables::table('#__loja_pedidos', [
    'casts' => ['metadados' => 'json'],
])->create([
    'cliente_id' => 7,
    'status' => 'aberto',
    'total' => 0,
    'metadados' => ['origem' => 'site', 'cupom' => null],   // vira JSON
]);

echo $pedido->id;

Devolve null se o registro não puder ser relido, por exemplo numa tabela sem auto incremento em que você não informou a chave.

createMany()executa a consulta

$orm->createMany(array $listaDeDados): array

Insere vários registros dentro de uma transação, na conexão da instância: ou todos são gravados, ou nenhum. Dentro de outra transação, vira um savepoint.

$itens = OrmTables::table('#__loja_pedido_itens', ['timestamps' => false])->createMany([
    ['pedido_id' => 1, 'produto_id' => 10, 'quantidade' => 2],
    ['pedido_id' => 1, 'produto_id' => 12, 'quantidade' => 1],
]);

echo count($itens);   // 2

Em caso de erro, lança RuntimeException ("Erro ao criar múltiplos registros…") e nada fica gravado. Insere um registro por vez: para milhares de linhas, divida em blocos.

firstOrCreate()executa a consulta

$orm->firstOrCreate(array $condicoes, array $dadosAdicionais = []): object|null

Procura o primeiro registro com todas as $condicoes (igualdade). Se não achar, cria com $condicoes + $dadosAdicionais. Descarta filtros montados antes.

$tag = OrmTables::table('#__loja_tags')->firstOrCreate(
    ['slug' => 'promocao'],                  // procura por isto
    ['nome' => 'Promoção', 'cor' => 'red']   // usa também isto ao criar
);

Entre a busca e a criação, outro request pode criar o mesmo registro. Para garantir que não haja duplicata, crie um índice UNIQUE nas colunas da condição. Com ele, o segundo request recebe um erro de duplicidade em vez de gravar uma cópia.

updateOrCreate()executa a consulta

$orm->updateOrCreate(array $condicoes, array $dados): object|null

Se existir um registro com as $condicoes, atualiza com $dados; senão, cria com $condicoes + $dados.

// Uma linha de configuração por chave
OrmTables::table('#__loja_config')->updateOrCreate(
    ['chave' => 'frete_gratis_acima'],
    ['valor' => '199.90']
);

A mesma ressalva de concorrência do firstOrCreate() vale aqui.

Atualizando

update()executa a consulta

$orm->update(int $id, array $dados): object|null

Atualiza um registro pela chave primária e devolve o registro atualizado. Preenche updated_at.

$produto = OrmTables::table('#__loja_produtos')->update($id, [
    'preco' => 3.20,
    'descricao' => null,      // grava NULL
]);

if ($produto === null) {
    // id inexistente (ou excluído, com softDeletes)
}

Não lança erro se o id não existir: devolve null.

updateWhere()executa a consulta

$orm->updateWhere(array $dados): int

Atualiza todos os registros que atendem aos filtros montados. Devolve o número de linhas afetadas.

$expirados = OrmTables::table('#__loja_pedidos')
    ->where('status', 'aberto')
    ->where('created_at', '<', date('Y-m-d H:i:s', strtotime('-7 days')))
    ->updateWhere(['status' => 'expirado']);

echo $expirados . ' pedidos expirados.';

Sem nenhum filtro, lança LogicException para você não alterar a tabela inteira por engano. Se for intencional, use allowMassOperation().

O MySQL conta só as linhas que realmente mudaram de valor; o PostgreSQL conta todas as que atenderam ao filtro. Com timestamps, updated_at sempre muda, e os dois contam igual.

increment() / decrement()executa a consulta

$orm->increment(int $id, string $coluna, int $quantidade = 1): object|null $orm->decrement(int $id, string $coluna, int $quantidade = 1): object|null

Soma ou subtrai direto no banco (estoque = estoque - 2). É uma operação atômica: dois requests ao mesmo tempo nunca perdem uma atualização, ao contrário de ler, calcular no PHP e gravar. Devolve o registro atualizado. Não altera updated_at.

$produtos = OrmTables::table('#__loja_produtos');

$produtos->increment(10, 'visualizacoes');
$produto = $produtos->decrement(10, 'estoque', 3);

echo $produto->estoque;

Não impede valores negativos. Para "só baixar se houver estoque", veja lockForUpdate() ou a receita de estoque.

touch()executa a consulta

$orm->touch(int $id): object|null

Atualiza só o updated_at do registro. Sem timestamps, apenas devolve o registro.

Excluindo

delete()executa a consulta

$orm->delete(int $id): bool

Exclui pela chave primária. Com softDeletes, só preenche deleted_at. Devolve true mesmo que o id não exista.

OrmTables::table('#__loja_produtos')->delete($id);

deleteWhere()executa a consulta

$orm->deleteWhere(): int

Exclui todos os registros que atendem aos filtros e devolve quantos foram afetados. Respeita softDeletes.

$removidos = OrmTables::table('#__loja_carrinhos')
    ->where('updated_at', '<', date('Y-m-d H:i:s', strtotime('-30 days')))
    ->deleteWhere();

Como updateWhere(): sem filtro, lança LogicException.

restore()executa a consulta

$orm->restore(int $id): object|null

Desfaz a exclusão lógica (deleted_at = NULL) e devolve o registro. Sem softDeletes, só devolve find($id).

forceDelete()executa a consulta

$orm->forceDelete(int $id): bool

Exclui de verdade (DELETE), mesmo com softDeletes ligado.

allowMassOperation()encadeável

$orm->allowMassOperation(): $this

Libera updateWhere()/deleteWhere() sem filtros, ou seja, na tabela inteira. Vale só para a próxima operação.

// Zera a flag de destaque de todos os produtos, de propósito
OrmTables::table('#__loja_produtos')
    ->allowMassOperation()
    ->updateWhere(['destaque' => 0]);

truncate()executa a consulta

$orm->truncate(bool $confirmar = false): array

Apaga todos os registros e reinicia o contador de id. Exige true explícito. A tabela precisa ser informada sem alias.

$resultado = OrmTables::table('#__loja_importacao_temp')->truncate(true);
// ['success' => true, 'tabela' => '#__loja_importacao_temp', 'registros_removidos_estimados' => 1520]

Irreversível. No MySQL, faz commit implícito: não volta com rollback e confirma qualquer transação aberta. No PostgreSQL é transacional e usa RESTART IDENTITY.

transaction() da instância

transaction()executa a consulta

$orm->transaction(callable $callback, array $opcoes = []): mixed

Atalho para DbTransactionHelper::run() na conexão desta instância. O callback recebe a própria instância. Por padrão não repete em deadlock (retries = 0); as $opcoes são as de run().

$produtos = OrmTables::table('#__loja_produtos');

$produtos->transaction(function ($q) {
    $q->update(10, ['preco' => 9.90]);
    $q->update(11, ['preco' => 4.90]);
});

Erros saem embrulhados numa RuntimeException ("Erro durante transação na tabela…"), com a original em getPrevious(). Se você lança exceções próprias e quer capturá-las pelo tipo, use DbTransactionHelper::run(), que relança a exceção original.
