OrmBase: models

Classes que guardam a configuração de uma tabela e dão nome às regras do domínio. Opcionais, mas úteis nas tabelas centrais.

Por que criar um model

Models são opcionais. Tudo o que um model faz também pode ser feito com OrmTables. Crie um quando a tabela é central no sistema e você quer:

  • declarar a configuração (casts, colunas permitidas, soft delete, conexão) uma vez só;
  • dar nome às regras do domínio, como PedidoModel::query()->pagos()->doCliente($id), em vez de repetir os where;
  • ter um lugar óbvio para constantes como status e tipos.

O model mínimo

class ProdutoModel extends OrmBase
{
    protected $table = '#__loja_produtos';
}

$produtos = ProdutoModel::query()->where('ativo', 1)->get();
$produto = ProdutoModel::query()->find(10);

Só $table é obrigatória. O resto usa os padrões: chave id, timestamps ligados, sem soft delete, conexão do Joomla.

Um model completo

models/PedidoModel.php
<?php

defined('_JEXEC') or die;

require_once JPATH_COMPONENT . '/helpers/OrmBase.php';

class PedidoModel extends OrmBase
{
    const STATUS_ABERTO = 'aberto';
    const STATUS_PAGO = 'pago';
    const STATUS_CANCELADO = 'cancelado';

    // Banco onde a tabela fica. Omita (ou null) para usar o do Joomla;
    // 'loja' precisa estar registrada no DbConnectionHelper (veja "Usando outro banco").
    protected $connection = 'loja';

    protected $table = '#__loja_pedidos';

    protected $softDeletes = true;

    protected $casts = [
        'cliente_id' => 'int',
        'total' => 'float',
        'metadados' => 'json',
    ];

    protected $fillable = [
        'cliente_id',
        'status',
        'total',
        'metadados',
    ];

    // ---- Scopes: filtros com nome ----

    public function doCliente($clienteId)
    {
        return $this->where('cliente_id', (int) $clienteId);
    }

    public function pagos()
    {
        return $this->where('status', self::STATUS_PAGO);
    }

    public function comStatus($status)
    {
        // Filtro opcional: vazio não filtra
        return $this->when($status, function ($q, $status) {
            $q->where('status', $status);
        });
    }

    public function recentes()
    {
        return $this->latest();
    }
}

Model com todas as configurações

Um model que usa tudo o que dá para customizar: outro banco (registrado pelo próprio model), chave primária e colunas de data com outros nomes, exclusão lógica, todos os tipos de casts, fillable e guarded, um ponto de extensão para gravação, scopes e uma regra de negócio com transação. Na prática, declare só o que difere do padrão.

models/NotaFiscalModel.php
<?php

defined('_JEXEC') or die;

require_once JPATH_COMPONENT . '/helpers/IncludeHelper.php';
IncludeHelper::load('OrmBase');   // traz DbConnectionHelper e DbTransactionHelper

class NotaFiscalModel extends OrmBase
{
    // ---- Constantes do domínio ----

    const CONEXAO = 'erp';

    const STATUS_RASCUNHO = 'rascunho';
    const STATUS_EMITIDA = 'emitida';
    const STATUS_CANCELADA = 'cancelada';

    // ---- Conexão ----

    // null = banco do Joomla. Um nome = conexão registrada no DbConnectionHelper
    // (aqui o próprio construtor registra). Pode ser trocada por consulta com
    // query(['connection' => ...]).
    protected $connection = self::CONEXAO;

    // ---- Tabela e chave ----

    // Obrigatória. O #__ vira o 'prefix' da conexão (no ERP: erp_notas_fiscais).
    // Só o nome, sem alias.
    protected $table = '#__notas_fiscais';

    // Padrão 'id'. Deve ser numérica e autoincremento: find(), update(),
    // delete() etc. convertem o valor com (int).
    protected $primaryKey = 'nota_id';

    // ---- Timestamps ----

    // Padrão true: create() preenche as duas colunas e update() a de
    // atualização. Com true, as colunas precisam existir na tabela.
    protected $timestamps = true;
    protected $createdAtColumn = 'criado_em';      // padrão 'created_at'; usado também por latest()/oldest()
    protected $updatedAtColumn = 'atualizado_em';  // padrão 'updated_at'

    // ---- Exclusão lógica ----

    // Padrão false. Com true, delete() grava a data em vez de apagar, as
    // consultas ignoram os excluídos, e restore()/forceDelete() ficam úteis.
    protected $softDeletes = true;
    protected $deletedAtColumn = 'excluido_em';    // padrão 'deleted_at'

    // ---- Conversão de tipos (leitura e gravação) ----

    protected $casts = [
        'cliente_id'    => 'int',       // ou 'integer'
        'valor_total'   => 'float',     // ou 'double'
        'enviada_sefaz' => 'bool',      // ou 'boolean'; grava 1/0, lê 't'/'f' do PostgreSQL
        'numero'        => 'string',
        'itens'         => 'json',      // ou 'array'; array -> JSON ao gravar, JSON -> array ao ler
        'emitida_em'    => 'datetime',  // ou 'date'; devolvido como string
    ];

    // ---- Colunas que create()/update() aceitam ----

    // Colunas que não existem na tabela são sempre descartadas, sem erro.
    // $fillable vazio = qualquer coluna existente. Preenchido = só essas.
    protected $fillable = [
        'cliente_id',
        'numero',
        'status',
        'valor_total',
        'enviada_sefaz',
        'itens',
        'emitida_em',
        'observacoes',
    ];

    // Aplicado depois do $fillable: estas nunca são gravadas a partir de
    // $dados. Na prática use um dos dois; aqui ficam os campos de auditoria,
    // preenchidos só por prepararDadosParaGravar() abaixo.
    protected $guarded = [
        'nota_id',
        'criado_por',
        'atualizado_por',
    ];

    // ---- Registro da conexão ----

    public function __construct($table = null, array $opcoes = [])
    {
        if (!DbConnectionHelper::has(self::CONEXAO)) {
            // Credenciais fora do código: aqui, dos parâmetros do componente.
            $params = JComponentHelper::getParams('com_loja');

            DbConnectionHelper::register(self::CONEXAO, [
                'driver'   => 'pgsql',      // mysql, mysqli, mariadb, pdomysql, pgsql, postgresql
                'host'     => $params->get('erp_host', 'localhost'),
                'port'     => (int) $params->get('erp_port', 5432),
                'user'     => $params->get('erp_user'),
                'password' => $params->get('erp_password'),
                'database' => $params->get('erp_database', 'erp'),
                'prefix'   => 'erp_',
            ]);
        }

        // Obrigatório: é aqui que as propriedades e as $opcoes são aplicadas.
        parent::__construct($table, $opcoes);
    }

    // ---- Ponto de extensão: preencher colunas em toda gravação ----

    // Roda em create(), createMany(), update() e updateWhere(), depois dos
    // filtros de colunas e dos timestamps.
    protected function prepararDadosParaGravar(array $dados, $criando)
    {
        $dados = parent::prepararDadosParaGravar($dados, $criando);

        $usuarioId = (int) JFactory::getUser()->id;

        if ($criando) {
            $dados['criado_por'] = $usuarioId;
        }

        $dados['atualizado_por'] = $usuarioId;

        return $dados;
    }

    // ---- Scopes: filtros com nome (public, devolvem $this) ----

    public function doCliente($clienteId)
    {
        return $this->where('cliente_id', (int) $clienteId);
    }

    public function emitidas()
    {
        return $this->where('status', self::STATUS_EMITIDA);
    }

    public function noPeriodo($inicio, $fim)
    {
        return $this->whereBetween('emitida_em', $inicio, $fim);
    }

    public function busca($termo)
    {
        // Filtro opcional: termo vazio não filtra. whereLike já envolve em %.
        return $this->when($termo, function ($q, $termo) {
            $q->whereGroup(function ($g) use ($termo) {
                $g->whereLike('numero', $termo)
                  ->orWhereLike('observacoes', $termo);
            });
        });
    }

    // ---- Regras de negócio ----

    public function emitir($notaId)
    {
        // A transação roda na conexão do model (o ERP).
        return $this->transaction(function (NotaFiscalModel $notas) use ($notaId) {
            // where()->first() mantém o lock; find() limparia o lockForUpdate().
            $nota = $notas->lockForUpdate()->where('nota_id', (int) $notaId)->first();

            if ($nota === null || $nota->status !== self::STATUS_RASCUNHO) {
                throw new RuntimeException('Só notas em rascunho podem ser emitidas.');
            }

            return $notas->update($notaId, [
                'status'     => self::STATUS_EMITIDA,
                'emitida_em' => date('Y-m-d H:i:s'),
            ]);
        });
    }
}

Usando o model:

// Uso normal: banco ERP, sem excluídas, com todos os casts
$notas = NotaFiscalModel::query()
    ->doCliente(7)
    ->emitidas()
    ->busca($termo)
    ->latest()                 // ORDER BY criado_em DESC
    ->paginate(20, $pagina);

$nota = NotaFiscalModel::query()->create([
    'cliente_id' => 7,
    'numero'     => '000123',
    'status'     => NotaFiscalModel::STATUS_RASCUNHO,
    'itens'      => [['sku' => 'A1', 'qtd' => 2]],  // gravado como JSON
    'criado_por' => 999,                             // ignorado: está em $guarded
]);

NotaFiscalModel::query()->emitir($nota->nota_id);

// Qualquer propriedade (menos $table) pode ser sobrescrita só nesta instância
$lixeira = NotaFiscalModel::query(['softDeletes' => false])
    ->whereNotNull('excluido_em')
    ->get();

$espelho = NotaFiscalModel::query(['connection' => 'erp_replica'])->emitidas()->count();

// Mesma configuração, outra tabela de mesmo formato
$antigas = NotaFiscalModel::tabela('#__notas_fiscais_2023')->emitidas()->get();

Sobrescrevendo métodos protected. prepararDadosParaGravar() é um bom ponto de extensão porque passa por todas as gravações. Ao sobrescrever qualquer método do OrmBase, mantenha a assinatura e chame o parent::. Sem isso, você perde os filtros de colunas, os timestamps e a conversão dos casts.

Usando: query()

query()estático

Model::query(array $opcoes = []): static

Ponto de entrada do model. Cada chamada devolve uma instância nova, sem filtros de consultas anteriores. As $opcoes sobrescrevem as propriedades da classe só nessa instância.

// Uso normal
$pedidos = PedidoModel::query()->pagos()->doCliente(7)->recentes()->get();

// Sobrescrevendo uma opção só nesta consulta: incluir excluídos
$todos = PedidoModel::query(['softDeletes' => false])->doCliente(7)->get();

// Mesmo model, outro banco (registrado antes: veja "Usando outro banco")
$arquivados = PedidoModel::query(['connection' => 'arquivo'])->pagos()->count();

Comece cada consulta com Model::query(). Guardar uma instância numa propriedade e reutilizá-la funciona, porque os métodos finais limpam os filtros, mas query() deixa claro que cada consulta é independente.

Também funcionam new PedidoModel() e PedidoModel::tabela('#__outra_tabela'), que usa a configuração do model numa tabela de mesmo formato.

Usando outro banco

Por padrão o model usa a conexão do Joomla. Para usar outro banco são dois passos: registrar a conexão com um nome no DbConnectionHelper e informar esse nome ao model. O nome 'arquivo' do exemplo acima é só isso: uma conexão registrada antes.

1. Registrar a conexão

Uma vez por requisição, antes do primeiro uso. O lugar natural é o arquivo de entrada do componente (veja onde registrar).

site/minhacomponente.php
DbConnectionHelper::register('erp', [
    'driver'   => 'pgsql',      // mysql, mysqli, mariadb, pdomysql, pgsql, postgresql
    'host'     => '10.0.0.5',
    'port'     => 5432,
    'user'     => 'app',
    'password' => '...',
    'database' => 'erp',
    'prefix'   => 'erp_',       // o #__ das consultas desta conexão vira erp_
]);

// Ou um driver já criado
DbConnectionHelper::register('arquivo', $driverDoArquivo);

A conexão só é aberta no primeiro uso e depois é reaproveitada. O nome 'default' é reservado para a conexão do Joomla.

2. Informar a conexão ao model

// a) Fixa no model: a tabela sempre fica nesse banco
class ClienteErpModel extends OrmBase
{
    protected $table = '#__clientes';   // vira erp_clientes
    protected $connection = 'erp';
}

ClienteErpModel::query()->where('ativo', 1)->get();

// b) Só nesta instância: tem prioridade sobre a propriedade $connection
PedidoModel::query(['connection' => 'arquivo'])->pagos()->count();
PedidoModel::tabela('#__pedidos_2023', ['connection' => 'arquivo']);

// c) Um driver no lugar do nome
PedidoModel::query(['connection' => $driver]);

connection aceita null (conexão do Joomla), o nome de uma conexão registrada ou um driver. Um nome não registrado lança InvalidArgumentException ao criar a instância.

Transações são por conexão. $model->transaction() usa sempre a conexão do próprio model, mas DbTransactionHelper::run() usa a do Joomla, a menos que você passe ['connection' => 'erp']. Uma transação num banco não protege gravações no outro, e lockForUpdate() exige transação ativa na mesma conexão do model. Veja Múltiplos bancos — transações.

O SQL se ajusta ao tipo de servidor de cada conexão (ILIKE, RETURNING etc.), então o mesmo model funciona em MySQL e PostgreSQL. Detalhes em MySQL e PostgreSQL.

Scopes: filtros com nome

Um scope é um método público do model que adiciona filtros e devolve $this. Ele mantém a cadeia fluente e dá nome às regras de negócio:

// Sem scopes: a regra se repete em todo lugar
OrmTables::table('#__loja_pedidos')->where('status', 'pago')->where('cliente_id', $id)->get();

// Com scopes: a regra tem nome e mora num lugar só
PedidoModel::query()->pagos()->doCliente($id)->get();

Regras para escrever scopes

  • Sempre return $this, ou o retorno de um método encadeável como where() ou when().
  • Um scope só monta filtros. Não chame get() nem count() dentro dele.
  • Para filtros opcionais, use when(): um valor vazio não filtra.
  • Scopes podem usar outros scopes e whereGroup().
public function emDestaque()
{
    return $this->where('ativo', true)
        ->whereGroup(function ($q) {
            $q->where('destaque', true)
              ->orWhere('estoque', '<=', 3);
        });
}

services/PedidoService.php
class PedidoService
{
    public static function cancelar($pedidoId)
    {
        return DbTransactionHelper::run(function () use ($pedidoId) {
            $pedido = PedidoModel::query()
                ->where('id', (int) $pedidoId)
                ->lockForUpdate()
                ->first();

            if ($pedido === null || $pedido->status !== PedidoModel::STATUS_ABERTO) {
                throw new RuntimeException('Só pedidos em aberto podem ser cancelados.');
            }

            PedidoModel::query()->update($pedido->id, ['status' => PedidoModel::STATUS_CANCELADO]);
            PedidoModel::query()->delete($pedido->id);

            return true;
        });
    }
}

Um exemplo completo, com models, exceções de negócio, service e controller, está em exemplos/ComoUsarOrm.php no repositório.

Cuidados

  • Não sobrescreva o construtor sem chamar parent::__construct($table, $opcoes).
  • Evite criar métodos com nomes já usados pelo OrmBase (get, count, delete…). Consulte a referência rápida.
  • Use em $table só o nome da tabela, sem alias: o alias quebra create/update/delete.
