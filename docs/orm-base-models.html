OrmBase: models

Classes que guardam a configuração de uma tabela e dão nome às regras do domínio. Opcionais, mas úteis nas tabelas centrais.

Por que criar um model

Models são opcionais. Tudo o que um model faz também pode ser feito com OrmTables. Crie um quando a tabela é central no sistema e você quer:

  • declarar a configuração (casts, colunas permitidas, soft delete, conexão) uma vez só;
  • dar nome às regras do domínio, como PedidoModel::query()->pagos()->doCliente($id), em vez de repetir os where;
  • ter um lugar óbvio para constantes como status e tipos.

O model mínimo

class ProdutoModel extends OrmBase
{
    protected $table = '#__loja_produtos';
}

$produtos = ProdutoModel::query()->where('ativo', 1)->get();
$produto = ProdutoModel::query()->find(10);

Só $table é obrigatória. O resto usa os padrões: chave id, timestamps ligados, sem soft delete, conexão do Joomla.

Um model completo

models/PedidoModel.php
<?php

defined('_JEXEC') or die;

require_once JPATH_COMPONENT . '/helpers/OrmBase.php';

class PedidoModel extends OrmBase
{
    const STATUS_ABERTO = 'aberto';
    const STATUS_PAGO = 'pago';
    const STATUS_CANCELADO = 'cancelado';

    protected $table = '#__loja_pedidos';

    protected $softDeletes = true;

    protected $casts = [
        'cliente_id' => 'int',
        'total' => 'float',
        'metadados' => 'json',
    ];

    protected $fillable = [
        'cliente_id',
        'status',
        'total',
        'metadados',
    ];

    // ---- Scopes: filtros com nome ----

    public function doCliente($clienteId)
    {
        return $this->where('cliente_id', (int) $clienteId);
    }

    public function pagos()
    {
        return $this->where('status', self::STATUS_PAGO);
    }

    public function comStatus($status)
    {
        // Filtro opcional: vazio não filtra
        return $this->when($status, function ($q, $status) {
            $q->where('status', $status);
        });
    }

    public function recentes()
    {
        return $this->latest();
    }
}

Usando: query()

query()estático

Model::query(array $opcoes = []): static

Ponto de entrada do model. Cada chamada devolve uma instância nova, sem filtros de consultas anteriores. As $opcoes sobrescrevem as propriedades da classe só nessa instância.

// Uso normal
$pedidos = PedidoModel::query()->pagos()->doCliente(7)->recentes()->get();

// Sobrescrevendo uma opção só nesta consulta: incluir excluídos
$todos = PedidoModel::query(['softDeletes' => false])->doCliente(7)->get();

// Mesmo model, outro banco
$arquivados = PedidoModel::query(['connection' => 'arquivo'])->pagos()->count();

Comece cada consulta com Model::query(). Guardar uma instância numa propriedade e reutilizá-la funciona, porque os métodos finais limpam os filtros, mas query() deixa claro que cada consulta é independente.

Também funcionam new PedidoModel() e PedidoModel::tabela('#__outra_tabela'), que usa a configuração do model numa tabela de mesmo formato.

Scopes: filtros com nome

Um scope é um método público do model que adiciona filtros e devolve $this. Ele mantém a cadeia fluente e dá nome às regras de negócio:

// Sem scopes: a regra se repete em todo lugar
OrmTables::table('#__loja_pedidos')->where('status', 'pago')->where('cliente_id', $id)->get();

// Com scopes: a regra tem nome e mora num lugar só
PedidoModel::query()->pagos()->doCliente($id)->get();

Regras para escrever scopes

  • Sempre return $this, ou o retorno de um método encadeável como where() ou when().
  • Um scope só monta filtros. Não chame get() nem count() dentro dele.
  • Para filtros opcionais, use when(): um valor vazio não filtra.
  • Scopes podem usar outros scopes e whereGroup().
public function emDestaque()
{
    return $this->where('ativo', true)
        ->whereGroup(function ($q) {
            $q->where('destaque', true)
              ->orWhere('estoque', '<=', 3);
        });
}

services/PedidoService.php
class PedidoService
{
    public static function cancelar($pedidoId)
    {
        return DbTransactionHelper::run(function () use ($pedidoId) {
            $pedido = PedidoModel::query()
                ->where('id', (int) $pedidoId)
                ->lockForUpdate()
                ->first();

            if ($pedido === null || $pedido->status !== PedidoModel::STATUS_ABERTO) {
                throw new RuntimeException('Só pedidos em aberto podem ser cancelados.');
            }

            PedidoModel::query()->update($pedido->id, ['status' => PedidoModel::STATUS_CANCELADO]);
            PedidoModel::query()->delete($pedido->id);

            return true;
        });
    }
}

Um exemplo completo, com models, exceções de negócio, service e controller, está em exemplos/ComoUsarOrm.php no repositório.

Cuidados

  • Não sobrescreva o construtor sem chamar parent::__construct($table, $opcoes).
  • Evite criar métodos com nomes já usados pelo OrmBase (get, count, delete…). Consulte a referência rápida.
  • Use em $table só o nome da tabela, sem alias: o alias quebra create/update/delete.
