ApiResponseHelper

Respostas padronizadas para JSON e páginas HTML: status HTTP corretos, erros por campo, mensagens seguras e um formato que o front-end sempre entende.

Visão geral

O ApiResponseHelper padroniza as respostas dos controllers. A mesma chamada funciona para os dois tipos de requisição:

  • Requisições JSON (fetch, axios, format=json): envia um JSON com formato fixo, o status HTTP certo e encerra a aplicação.
  • Requisições de página (formulário HTML comum): coloca a mensagem na fila de mensagens do Joomla e, se configurado, redireciona.
require_once JPATH_COMPONENT . '/helpers/ApiResponseHelper.php';

class LojaControllerProdutos extends JControllerLegacy
{
    public function salvar()
    {
        try {
            $produto = ProdutoService::salvar(InputHelper::array('produto', array(), 'post'));

            return ApiResponseHelper::success('Produto salvo.', $produto);
        } catch (Throwable $e) {
            return ApiResponseHelper::exception($e);   // log completo, mensagem genérica, HTTP 500
        }
    }
}

Formato da resposta JSON

Toda resposta JSON tem as mesmas chaves, de sucesso ou de erro. O front-end sempre sabe onde procurar:

Resposta JSON
{
    "success": false,
    "status": "erro",
    "mensagem": "O campo E-mail deve conter um e-mail válido.",
    "data": null,
    "errors": {
        "email": ["O campo E-mail deve conter um e-mail válido."],
        "itens.1.quantidade": ["O campo Quantidade (item 2) deve ser maior ou igual a 1."]
    },
    "request_id": "9f2c4e7a1b3d5f60718293a4b5c6d7e8",
    "meta": { "paginacao": { "total": 41, "por_pagina": 20, "pagina_atual": 3, "total_paginas": 3 } }
}
ChaveTipoConteúdo
successbooltrue em sucesso, informação e aviso; false em erro.
statusstringsucesso, info, aviso ou erro.
mensagemstringTexto para mostrar ao usuário.
dataqualquerOs dados enviados, exatamente como estão: números, booleanos e null mantêm o tipo.
errorsobjeto{"campo": ["mensagem", …]}. Erros gerais ficam em _general. Vazio ([]) em sucesso.
request_idstringIdentificador da requisição: o mesmo dos logs do LogHelper. Peça ao usuário ao investigar um problema.
metaobjetoSó aparece quando há dados extras: paginação, debug, ou o que você passar em meta.

Cabeçalhos enviados

CabeçalhoValor
StatusO código HTTP do método (200, 201, 422, 500…).
Content-Typeapplication/json; charset=utf-8
Cache-Controlno-store, no-cache, must-revalidate: respostas com dados do usuário não ficam em cache.
X-Request-IdO mesmo request_id do corpo.
Retry-AfterEm tooManyRequests() com retry_after.
outrosOs que você passar na opção headers.

Antes de enviar o JSON, o helper descarta o que já tinha sido impresso: Notices do PHP, espaços, HTML do componente. Isso evita o erro "Unexpected token < in JSON" no JavaScript. Se o UTF-8 de algum texto for inválido, o caractere é trocado por "�" em vez de a resposta sair vazia.

JSON ou página HTML?

A requisição é tratada como JSON quando qualquer uma destas condições vale:

SinalExemplo
Parâmetro format=jsonindex.php?option=com_loja&task=pedidos.salvar&format=json
Cabeçalho X-Requested-With: XMLHttpRequestjQuery $.ajax
Cabeçalho Accept com application/jsonfetch(url, { headers: { Accept: 'application/json' } })
Corpo enviado como JSON (Content-Type: application/json)fetch(url, { method: 'POST', body: JSON.stringify(dados), headers: {…} })

Para decidir sem depender da detecção, use a opção 'json' => true (ou false). Para perguntar antes, use isJson().

Comportamento em requisições de página

MétodoTipo da mensagem do Joomla
success, created, updated, deleted, paginatedmessage (verde)
infonotice (azul)
warningwarning (amarelo)
todos os de erroerror (vermelho)

Depois de colocar a mensagem na fila, o helper redireciona para a URL da opção redirect ou, sem ela, para a definida em setDefaultRedirect(). Sem nenhuma das duas, ele não redireciona: devolve o array da resposta e o controller continua.

// Formulário HTML tradicional
public function salvar()
{
    JSession::checkToken() or jexit('Token inválido.');

    try {
        ProdutoService::salvar($this->dadosDoFormulario());

        return ApiResponseHelper::success('Produto salvo.', null, array(
            'redirect' => 'index.php?option=com_loja&view=produtos',
        ));
    } catch (Throwable $e) {
        return ApiResponseHelper::exception($e, 'Não foi possível salvar o produto.', array(
            'redirect' => 'index.php?option=com_loja&view=produto&layout=edit',
        ));
    }
}

Só são aceitos redirecionamentos para URLs do próprio site. Uma URL externa é bloqueada e registrada no log, o que impede open redirect quando a URL vem da requisição (o clássico parâmetro return). Para um destino externo confiável, passe 'allow_external_redirect' => true.

A resposta JSON encerra a aplicação

Por padrão, depois de enviar o JSON o helper chama $app->close(): nenhum código depois da chamada é executado. É o que se espera de um endpoint, e por isso os exemplos usam return ApiResponseHelper::…, deixando claro que ali termina o fluxo.

ApiResponseHelper::success('Salvo.');
EmailHelper::enviar($pedido);          // NUNCA executa numa requisição JSON

// Faça o que precisar antes de responder:
EmailHelper::enviar($pedido);
return ApiResponseHelper::success('Salvo.');

Para continuar depois de responder (raro), use 'close' => false numa chamada, ou setCloseApplication(false) para todas. Nesse caso, o array da resposta é devolvido.

Respostas de sucesso

success()estático

ApiResponseHelper::success(string $message = 'Operação realizada com sucesso.', mixed $data = null, array $options = array())

Sucesso genérico, HTTP 200.

ParâmetroTipoDescrição
$messagestringMensagem para o usuário.
$datamixedDados da resposta: array, objeto, lista, valor.
$optionsarrayVeja opções.
$produto = OrmTables::table('#__loja_produtos')->find($id);

return ApiResponseHelper::success('Produto carregado.', $produto);

created() / updated() / deleted()estático

ApiResponseHelper::created(string $message = 'Registro criado com sucesso.', mixed $data = null, array $options = array()) ApiResponseHelper::updated(string $message = 'Registro atualizado com sucesso.', mixed $data = null, array $options = array()) ApiResponseHelper::deleted(string $message = 'Registro excluído com sucesso.', mixed $data = null, array $options = array())

Atalhos com mensagens prontas. created() responde HTTP 201; updated() e deleted() respondem 200.

$pedido = PedidoService::criar($dados);

return ApiResponseHelper::created('Pedido criado.', $pedido);

paginated()estático

ApiResponseHelper::paginated(array $result, string $message = 'Registros carregados.', array $options = array())

Resposta de listagem a partir do resultado de paginate() do ORM: os itens vão em data e os números em meta.paginacao. O objeto JPagination, inútil em JSON, é descartado.

$p = InputHelper::pagination(20, 100);

$resultado = OrmTables::table('#__loja_pedidos')
    ->latest()
    ->paginate($p['limit'], $p['page']);

return ApiResponseHelper::paginated($resultado, 'Pedidos carregados.');
// data: [...itens], meta: { paginacao: { total, por_pagina, pagina_atual, total_paginas } }

info() / warning()estático

ApiResponseHelper::info(string $message, mixed $data = null, array $options = array()) ApiResponseHelper::warning(string $message, mixed $data = null, array $options = array())

A operação funcionou, mas há algo a comunicar. Respondem HTTP 200 com success: true e status info ou aviso.

$resultado = ImportacaoService::importar($linhas);

if (!empty($resultado['ignorados'])) {
    return ApiResponseHelper::warning(
        count($resultado['ignorados']) . ' linhas foram ignoradas por duplicidade.',
        $resultado
    );
}

return ApiResponseHelper::success('Importação concluída.', $resultado);

Para não registrar um erro esperado (por exemplo, 404 de busca), passe 'log' => false.

validationError() / fromValidation()estático

ApiResponseHelper::validationError(array $errors, string $message = 'Corrija os campos informados.', array $options = array()) ApiResponseHelper::fromValidation(array $validation, string $message = 'Corrija os campos informados.', array $options = array())

Erro de validação, HTTP 422, com os erros por campo. fromValidation() recebe direto o resultado de ValidationHelper::validate() e usa a primeira mensagem de erro como mensagem.

$validacao = ValidationHelper::validate($dados, $regras);

if (!$validacao['valid']) {
    return ApiResponseHelper::fromValidation($validacao);
}

// Erros montados à mão
return ApiResponseHelper::validationError(array(
    'cupom' => array('Este cupom expirou.'),
));

Chame fromValidation() só quando a validação falhou. Com um resultado válido, ele responde sucesso ("Dados válidos.", ou success_message/data das opções) e, numa requisição JSON, encerra a aplicação.

badRequest() / conflict()estático

ApiResponseHelper::badRequest(string $message = 'Requisição inválida.', mixed $data = null, array $options = array()) ApiResponseHelper::conflict(string $message = '…conflito de dados.', mixed $data = null, array $options = array())

Erros causados pela requisição ou pelo estado dos dados. Aceitam $data para enviar detalhes ao front-end.

if ($pedido->status !== 'aberto') {
    return ApiResponseHelper::conflict('Este pedido já foi faturado.', array('status' => $pedido->status));
}

unauthorized() / forbidden() / notFound() / methodNotAllowed() / serviceUnavailable()estático

ApiResponseHelper::unauthorized(string $message = 'Usuário não autenticado.', array $options = array()) ApiResponseHelper::forbidden(string $message = 'Você não possui permissão para esta operação.', array $options = array()) ApiResponseHelper::notFound(string $message = 'Registro não encontrado.', array $options = array()) ApiResponseHelper::methodNotAllowed(string $message = 'Método de requisição não permitido.', array $options = array()) ApiResponseHelper::serviceUnavailable(string $message = 'Serviço temporariamente indisponível.', array $options = array())

Atalhos para os códigos HTTP correspondentes, sem $data.

if (!InputHelper::isPost()) {
    return ApiResponseHelper::methodNotAllowed();
}

if (!JSession::checkToken()) {
    return ApiResponseHelper::forbidden('Sessão expirada. Recarregue a página.');
}

if (JFactory::getUser()->guest) {
    return ApiResponseHelper::unauthorized();
}

if (!JFactory::getUser()->authorise('core.edit', 'com_loja')) {
    return ApiResponseHelper::forbidden();
}

tooManyRequests()estático

ApiResponseHelper::tooManyRequests(string $message = 'Muitas tentativas…', array $options = array())

HTTP 429. Com retry_after (segundos), envia o cabeçalho Retry-After, que bibliotecas HTTP usam para esperar antes de tentar de novo.

return ApiResponseHelper::tooManyRequests('Muitas tentativas de login. Aguarde 1 minuto.', array(
    'retry_after' => 60,
));

exception()estático

ApiResponseHelper::exception(Throwable $error, string $publicMessage = 'Ocorreu um erro interno ao processar a solicitação.', array $options = array())

Para erros técnicos inesperados: registra a exceção no log (classe, mensagem, arquivo, linha e, com o LogHelper carregado, a pilha de chamadas) e responde HTTP 500 com uma mensagem genérica. Detalhes como SQL e caminhos de arquivo nunca chegam ao usuário.

ParâmetroTipoDescrição
$errorThrowableA exceção capturada.
$publicMessagestringMensagem mostrada ao usuário.
$optionsarrayAlém das opções comuns: context (dados extras para o log) e log_category.
try {
    $pedido = PedidoService::criar($dados);

    return ApiResponseHelper::created('Pedido criado.', $pedido);
} catch (EstoqueInsuficienteException $e) {
    return ApiResponseHelper::conflict($e->getMessage());       // regra de negócio: mostra a mensagem
} catch (Throwable $e) {
    return ApiResponseHelper::exception($e, 'Não foi possível criar o pedido.', array(
        'context' => array('cliente_id' => $dados['cliente_id']),
    ));
}

Com o debug do Joomla ligado (Configuração Global → Sistema → Depurar sistema), a resposta inclui meta.debug com tipo, mensagem, arquivo e linha da exceção, o que ajuda no desenvolvimento. Deixe o debug desligado em produção.

exception() sempre responde 500. Uma exceção que representa "não encontrado" (por exemplo, a de findOrFail(), com código 404) deve ser tratada antes: if ($e->getCode() === 404) return ApiResponseHelper::notFound();

error()estático

ApiResponseHelper::error(string $message = 'Não foi possível concluir a operação.', mixed $data = null, array $errors = array(), array $options = array())

A base de todas as respostas de erro: HTTP 400 por padrão (ajustável com http_status), com dados e erros opcionais. Se $message vier vazia, usa a primeira mensagem de $errors.

return ApiResponseHelper::error('Pagamento recusado.', array('codigo' => 'cartao_expirado'), array(), array(
    'http_status' => 402,
));

// $errors aceita: array por campo, lista simples (vai para _general) ou uma string
return ApiResponseHelper::error('', null, array('Prazo encerrado.', 'Pedido bloqueado.'));

Opções

Todos os métodos de resposta aceitam um array $options:

OpçãoTipoEfeito
http_statusintTroca o código HTTP (em success, info, warning, error, validationError).
metaarrayDados extras em meta (totais, versão, filtros aplicados…).
headersarrayCabeçalhos extras: array('X-Total-Count' => 41).
jsonboolForça resposta JSON (true) ou HTML (false), ignorando a detecção.
closeboolEncerrar a aplicação depois do JSON. Padrão: true.
redirectstring|falseEm requisições HTML, para onde ir depois. false desliga o redirecionamento padrão.
allow_external_redirectboolPermite redirecionar para outro domínio.
logboolRegistrar o erro no log. Padrão: true nos erros, false em validationError.
retry_afterintSó em tooManyRequests(): segundos para o cabeçalho Retry-After.
context, log_categoryarray, stringSó em exception(): contexto e categoria do log.
success_message, datastring, mixedSó em fromValidation() com resultado válido.

Configuração global

setDefaultRedirect()estático

ApiResponseHelper::setDefaultRedirect(string $url): void

Destino padrão das respostas em requisições HTML. A opção redirect de cada chamada tem prioridade. String vazia desliga.

// No display() do controller do formulário de pedidos
ApiResponseHelper::setDefaultRedirect('index.php?option=com_loja&view=pedidos');

setCloseApplication()estático

ApiResponseHelper::setCloseApplication(bool $close): void

Define se as respostas JSON encerram a aplicação (padrão true). Use false só se o componente monta a resposta de outra forma, como em view.json.php com documento JSON do Joomla.

setLogErrors() / setLogCategory()estático

ApiResponseHelper::setLogErrors(bool $logErrors): void ApiResponseHelper::setLogCategory(string $category): void

Liga ou desliga o registro de erros (padrão ligado) e define a categoria do log (padrão api_response). Os erros vão para o LogHelper, se carregado, ou para o JLog. Os dados registrados passam pela sanitização do LogHelper (senhas e tokens mascarados), o que vale só para o log: a resposta ao cliente não é alterada.

isJson()estático

ApiResponseHelper::isJson(): bool

A requisição atual será respondida em JSON? Segue as regras de detecção.

if (!ApiResponseHelper::isJson()) {
    // requisição de página: exibe a view normalmente
    return parent::display();
}

Consumindo no front-end

Como o formato é sempre o mesmo, um único trecho de JavaScript trata todas as respostas:

JavaScript
async function enviar(url, dados) {
    const resposta = await fetch(url, {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify(dados)
    });

    const json = await resposta.json();

    if (json.success) {
        mostrarMensagem(json.mensagem, json.status === 'aviso' ? 'warning' : 'success');
        return json.data;
    }

    if (resposta.status === 422) {
        // erros por campo: { "email": ["..."], "itens.1.quantidade": ["..."] }
        Object.entries(json.errors).forEach(([campo, mensagens]) => marcarCampo(campo, mensagens[0]));
    }

    mostrarMensagem(json.mensagem + ' (código: ' + json.request_id.slice(0, 8) + ')', 'error');
    throw new Error(json.mensagem);
}

Mostrar parte do request_id no erro ajuda o suporte: com ele, você encontra no log exatamente aquela requisição.

Padrão completo no controller

controllers/pedidos.php
public function criar()
{
    if (!InputHelper::isPost()) {
        return ApiResponseHelper::methodNotAllowed();
    }

    if (!JSession::checkToken('get')) {
        return ApiResponseHelper::forbidden('Sessão expirada. Recarregue a página.');
    }

    $dados = array(
        'cliente_id' => InputHelper::uint('cliente_id', null),
        'itens' => InputHelper::array('itens'),
    );

    $validacao = ValidationHelper::validate($dados, array(
        'cliente_id' => 'required',
        'itens' => 'required|array|min:1',
        'itens.*.produto_id' => 'required|integer',
        'itens.*.quantidade' => 'required|integer|min:1',
    ));

    if (!$validacao['valid']) {
        return ApiResponseHelper::fromValidation($validacao);                    // 422
    }

    try {
        $pedido = PedidoService::criar($dados['cliente_id'], $dados['itens']);

        return ApiResponseHelper::created('Pedido criado.', $pedido);           // 201
    } catch (EstoqueInsuficienteException $e) {
        return ApiResponseHelper::conflict($e->getMessage());                    // 409
    } catch (PedidoException $e) {
        return ApiResponseHelper::badRequest($e->getMessage());                  // 400
    } catch (Throwable $e) {
        if ($e->getCode() === 404) {
            return ApiResponseHelper::notFound('Produto não encontrado.', array('log' => false));
        }

        return ApiResponseHelper::exception($e, 'Não foi possível criar o pedido.');   // 500
    }
}

Cuidados

  • Escolha os dados enviados. data vai ao cliente exatamente como está, sem mascaramento automático. Não devolva registros inteiros com colunas sensíveis (senha, hash, tokens internos): selecione as colunas com select() do ORM ou monte o array de resposta.
  • Mensagens de exceção não são para o usuário. Use exception() para erros técnicos e mostre $e->getMessage() só de exceções de regra de negócio que você mesmo lançou.
  • Depois de responder, nada mais roda numa requisição JSON (veja encerramento).
  • Redirecionamentos só para o próprio site, a menos que allow_external_redirect seja passado.
  • Debug do Joomla desligado em produção: com ele ligado, exception() expõe detalhes do erro.
