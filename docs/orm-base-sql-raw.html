OrmBase: SQL raw

SQL escrito à mão, com os valores passados por bindings, para o que o builder não cobre: CTE, UNION, subquery, funções do banco e relatórios.

Visão geral

O builder (where, join, groupBy…) resolve a maior parte dos casos e já adapta o SQL entre MySQL e PostgreSQL. Quando ele não alcança, use os métodos raw: você escreve o SQL inteiro e passa os valores separados, em $bindings. O ORM coloca cada valor no lugar do seu placeholder já escapado, então o SQL continua protegido contra injeção.

Existem em toda instância do ORM (models e OrmTables::table()) e também como atalhos estáticos em OrmTables, que não pedem tabela.

$resumo = OrmTables::raw(
    'SELECT status, COUNT(*) AS total, SUM(total) AS valor
       FROM #__loja_pedidos
      WHERE created_at >= ?
      GROUP BY status',
    ['2026-10-01 00:00:00']
);

foreach ($resumo as $linha) {
    echo $linha->status . ': ' . $linha->total;
}

Use raw como exceção. Se dá para fazer com o builder, prefira o builder: ele aplica softDeletes, casts e as diferenças entre os bancos sozinho.

Bindings: como passar os valores

Escreva um placeholder no lugar de cada valor e passe os valores no segundo parâmetro. Há dois estilos, que não podem ser misturados no mesmo SQL.

Posicionais: ?

Cada ? recebe o próximo valor da lista, na ordem.

OrmTables::raw(
    'SELECT * FROM #__loja_pedidos WHERE status = ? AND total > ? LIMIT ?',
    ['pago', 100, 20]
);
// ... WHERE status = 'pago' AND total > 100 LIMIT 20

Nomeados: :nome

Mais legível quando há muitos valores ou o mesmo valor aparece várias vezes. A chave pode vir com ou sem os dois-pontos ('inicio' ou ':inicio').

OrmTables::raw(
    'SELECT * FROM #__loja_pedidos
      WHERE created_at BETWEEN :inicio AND :fim
         OR pago_em BETWEEN :inicio AND :fim',
    ['inicio' => '2026-10-01 00:00:00', 'fim' => '2026-10-31 23:59:59']
);

Listas para IN

Passe um array: ele vira os valores separados por vírgula. Os parênteses ficam no SQL.

OrmTables::raw(
    'SELECT * FROM #__loja_pedidos WHERE id IN (:ids) AND status IN (:status)',
    ['ids' => [10, 11, 12], 'status' => ['pago', 'enviado']]
);
// ... WHERE id IN (10, 11, 12) AND status IN ('pago', 'enviado')

Array vazio lança InvalidArgumentException, porque IN () é SQL inválido. Trate antes: if (empty($ids)) { return []; }.

Valor no PHPNo SQL

null vira NULL literal, então coluna = ? com null gera coluna = NULL, que nunca é verdadeiro. Para comparar com nulo, escreva coluna IS NULL no SQL.

O que não é placeholder

O ORM lê o SQL e só troca placeholders que estão no código SQL. Ficam intactos:

  • ? e :nome dentro de strings ('...'), de identificadores ("...", `...`) e de comentários (-- ..., /* ... */);
  • o cast do PostgreSQL, ::: created_at::date = :dia funciona;
  • o prefixo #__, que é trocado pelo prefixo do Joomla na execução, como no restante do ORM.

Métodos

raw()executa a consulta

$orm->raw(string $sql, array $bindings = []): array

Executa o SQL e devolve todas as linhas como stdClass[]. Sem resultado, devolve [].

$maisVendidos = PedidoModel::query()->raw(
    'SELECT p.id, p.nome, SUM(i.quantidade) AS vendidos
       FROM #__loja_pedido_itens i
       JOIN #__loja_produtos p ON p.id = i.produto_id
      WHERE i.created_at >= :desde
      GROUP BY p.id, p.nome
      ORDER BY vendidos DESC
      LIMIT :limite',
    ['desde' => '2026-10-01', 'limite' => 10]
);

Os métodos raw não usam os filtros montados na instância (where, join, orderBy…), não aplicam casts e não filtram softDeletes: escreva deleted_at IS NULL no SQL se precisar. Os valores voltam como o driver entrega (normalmente strings).

rawFirst()executa a consulta

$orm->rawFirst(string $sql, array $bindings = []): object|null

Primeira linha do resultado, ou null.

$ultimo = OrmTables::rawFirst(
    'SELECT * FROM #__loja_pedidos WHERE cliente_id = ? ORDER BY created_at DESC LIMIT 1',
    [$clienteId]
);

if ($ultimo === null) {
    // cliente sem pedidos
}

Não adiciona LIMIT. Sem ele, o banco busca todas as linhas e o PHP descarta as outras: coloque LIMIT 1 no SQL.

rawValue()executa a consulta

$orm->rawValue(string $sql, array $bindings = []): mixed

Primeira coluna da primeira linha, ou null. Ideal para contagens e somas.

$faturamento = (float) OrmTables::rawValue(
    'SELECT COALESCE(SUM(total), 0) FROM #__loja_pedidos WHERE status = ? AND pago_em >= ?',
    ['pago', '2026-10-01 00:00:00']
);

O valor vem como o driver entrega, em geral como string. Converta com (int) ou (float).

rawExecute()executa a consulta

$orm->rawExecute(string $sql, array $bindings = []): int

Para comandos que não devolvem linhas: INSERT, UPDATE, DELETE, CREATE, ALTER… Devolve quantas linhas foram afetadas.

// UPDATE com JOIN (o builder não faz)
$afetadas = OrmTables::rawExecute(
    'UPDATE #__loja_pedidos p
       JOIN #__loja_clientes c ON c.id = p.cliente_id
        SET p.prioridade = 1
      WHERE c.vip = ? AND p.status = ?',
    [true, 'pendente']
);

// INSERT ... SELECT
OrmTables::rawExecute(
    'INSERT INTO #__loja_pedidos_arquivo SELECT * FROM #__loja_pedidos WHERE created_at < ?',
    ['2025-01-01']
);

Não devolve o id inserido. Para isso, prefira create(). Se precisar mesmo de INSERT raw: no PostgreSQL use rawValue('INSERT ... RETURNING id', ...); no MySQL, leia $orm->db()->insertid() logo depois, na mesma instância.

Ao contrário de updateWhere()/deleteWhere(), aqui não há proteção contra UPDATE/DELETE sem WHERE. Revise o SQL antes de rodar.

rawSql()

$orm->rawSql(string $sql, array $bindings = []): string

Devolve o SQL com os bindings já aplicados, sem executar. Útil para depurar ou registrar em log. O #__ ainda não foi trocado pelo prefixo.

echo OrmTables::rawSql(
    'SELECT * FROM #__loja_pedidos WHERE id IN (?) AND status = ?',
    [[1, 2], "it's"]
);
// SELECT * FROM #__loja_pedidos WHERE id IN (1, 2) AND status = 'it\'s'

Sem model: OrmTables

Para SQL que não pertence a uma tabela só (relatórios, UNION entre tabelas), use os atalhos estáticos. O terceiro parâmetro aceita connection, para rodar em outro banco.

OrmTables::raw(string $sql, array $bindings = [], array $opcoes = []): array OrmTables::rawFirst(string $sql, array $bindings = [], array $opcoes = []): object|null OrmTables::rawValue(string $sql, array $bindings = [], array $opcoes = []): mixed OrmTables::rawExecute(string $sql, array $bindings = [], array $opcoes = []): int OrmTables::rawSql(string $sql, array $bindings = [], array $opcoes = []): string
// banco do Joomla
$total = (int) OrmTables::rawValue('SELECT COUNT(*) FROM #__users WHERE block = ?', [0]);

// outro banco registrado no DbConnectionHelper
$clientes = OrmTables::raw(
    'SELECT codigo, razao_social FROM clientes WHERE uf = ?',
    ['SP'],
    ['connection' => 'erp']
);

Num model, o raw usa a conexão do próprio model (protected $connection):

class PedidoModel extends OrmBase
{
    protected $table = '#__loja_pedidos';

    public function resumoPorMes($ano)
    {
        return $this->raw(
            'SELECT MONTH(created_at) AS mes, COUNT(*) AS qtd, SUM(total) AS valor
               FROM #__loja_pedidos
              WHERE YEAR(created_at) = ? AND deleted_at IS NULL
              GROUP BY MONTH(created_at)
              ORDER BY mes',
            [(int) $ano]
        );
    }
}

$meses = (new PedidoModel())->resumoPorMes(2026);

Segurança

Binding protege valores. Nomes de tabela, nomes de coluna, ASC/DESC e palavras-chave não podem ser bindings: se vierem da tela, valide contra uma lista fixa.

// ERRADO: injeção de SQL
OrmTables::raw("SELECT * FROM #__loja_pedidos WHERE status = '" . $_GET['status'] . "'");

// CERTO: valor por binding
OrmTables::raw('SELECT * FROM #__loja_pedidos WHERE status = ?', [$status]);

// ordenação vinda da tela: lista fixa
$colunas = ['created_at' => 'created_at', 'total' => 'total'];
$coluna = $colunas[$ordem] ?? 'created_at';
$direcao = strtoupper($direcao) === 'ASC' ? 'ASC' : 'DESC';

OrmTables::raw(
    "SELECT * FROM #__loja_pedidos WHERE status = ? ORDER BY $coluna $direcao LIMIT ?",
    [$status, 50]
);

Nunca concatene nada que veio do usuário no $sql, nem "só um número". Valores vão em $bindings; identificadores, só de uma lista fixa sua.

Dentro de transações

Os métodos raw rodam na conexão da instância, então entram na transação dela. Misture à vontade com os métodos do builder:

PedidoModel::query()->transaction(function ($pedidos) use ($pedidoId) {
    $pedidos->update($pedidoId, ['status' => 'cancelado']);

    $pedidos->rawExecute(
        'UPDATE #__loja_produtos p
           JOIN #__loja_pedido_itens i ON i.produto_id = p.id
            SET p.estoque = p.estoque + i.quantidade
          WHERE i.pedido_id = ?',
        [$pedidoId]
    );
});

Com DbTransactionHelper::run() numa conexão nomeada, passe a mesma conexão no raw: OrmTables::rawExecute($sql, $bindings, ['connection' => 'erp']).

MySQL e PostgreSQL

O SQL raw vai como você escreveu: o ORM não adapta funções nem sintaxe. YEAR(), UPDATE ... JOIN e crases só existem no MySQL; ILIKE, RETURNING e :: só no PostgreSQL. Se o componente roda nos dois, escolha o SQL pelo banco:

$orm = PedidoModel::query();

$sql = $orm->serverType() === DbConnectionHelper::POSTGRESQL
    ? 'SELECT EXTRACT(MONTH FROM created_at) AS mes, COUNT(*) AS qtd FROM #__loja_pedidos WHERE created_at >= ? GROUP BY 1'
    : 'SELECT MONTH(created_at) AS mes, COUNT(*) AS qtd FROM #__loja_pedidos WHERE created_at >= ? GROUP BY 1';

$porMes = $orm->raw($sql, ['2026-01-01']);
Limitação no PostgreSQLComo contornar
Operadores JSONB ?, ?|, ?& são lidos como placeholderUse as funções equivalentes: jsonb_exists(col, ?), jsonb_exists_any(col, ?), jsonb_exists_all(col, ?)
Strings com $$...$$ não são reconhecidasUse aspas simples, ou rode o DDL sem bindings

Mais diferenças em MySQL e PostgreSQL.

ExceçãoQuando
InvalidArgumentExceptionSQL vazio; mais ? do que valores ou mais valores do que ?; :nome sem valor ou valor nomeado não usado; ? misturado com :nome; array vazio ou array dentro de array; aspa sem fechamento; objeto que não vira texto. Lançada antes de ir ao banco.
RuntimeExceptionErro do banco (sintaxe, tabela inexistente, constraint…). Mensagem "Erro ao executar SQL raw: …", com a exceção original em getPrevious(). Código 500.
try {
    $linhas = OrmTables::raw($sql, $bindings);
} catch (InvalidArgumentException $e) {
    // erro de programação: SQL e bindings não batem
} catch (RuntimeException $e) {
    LogHelper::error('Relatório falhou', 'relatorios', ['erro' => $e->getMessage()]);
}
