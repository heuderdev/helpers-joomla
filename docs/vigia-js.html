Vigia.js

Validação no navegador, máscaras e requisições com axios para componentes Joomla, falando a mesma língua do ValidationHelper e do ApiResponseHelper. Esta página cobre cada tipo de campo, cada regra, listas, arquivos (inclusive grandes) e o que acontece em cada etapa do envio.

Visão geral

O Vigia.js é um micro framework JavaScript (um arquivo, sem build) que cuida do formulário de ponta a ponta:

  • Valida no navegador com as mesmas regras e mensagens do ValidationHelper: required|cpf|max_length:150 funciona igual nos dois lados.
  • Mostra os erros do servidor no campo certo: a resposta 422 do ApiResponseHelper::fromValidation() aparece embaixo de cada campo, inclusive itens.1.quantidade → itens[1][quantidade].
  • Máscaras brasileiras: CPF, CNPJ, CPF/CNPJ, telefone, CEP, data, hora, dinheiro, placa, cartão, PIS e padrões próprios.
  • Requisições com axios: token CSRF do Joomla automático, objetos convertidos em multipart/form-data que o PHP entende, resposta normalizada e erros padronizados.
  • Alpine.js opcional: x-data="vigia" com erros reativos e x-mask.

A validação no navegador é conforto, não segurança: qualquer um pode desligar o JavaScript ou chamar a URL direto. O controller sempre valida com o ValidationHelper.

Instalação

Copie js/vigia.js e js/vigia.css do repositório para a pasta de mídia do componente (ex.: media/com_loja/js/) e carregue o axios antes do Vigia. O CSS é opcional com Bootstrap (Joomla 4/5 e a maioria dos templates).

HTML
<script src="https://cdnjs.cloudflare.com/ajax/libs/axios/1.7.7/axios.min.js"></script>
<script src="/media/com_loja/js/vigia.js"></script>
<link rel="stylesheet" href="/media/com_loja/js/vigia.css">

<!-- Opcional, depois do Vigia -->
<script defer src="https://cdn.jsdelivr.net/npm/alpinejs@3.14.1/dist/cdn.min.js"></script>

// Na view do Joomla (3, 4 e 5)
JHtml::_('script', 'https://cdnjs.cloudflare.com/ajax/libs/axios/1.7.7/axios.min.js');
JHtml::_('script', 'com_loja/vigia.js', array('relative' => true, 'version' => 'auto'));

Não há init() para chamar: ao carregar a página, o Vigia ativa todo <form data-vigia> (e todo [data-vigia-form]) e todo campo com data-mask, inclusive os adicionados depois por JavaScript (um MutationObserver acompanha o <body>).

Para ver tudo funcionando sem Joomla, abra js/exemplo.html do repositório no navegador: um servidor falso responde como o ApiResponseHelper. O exemplo completo de controller e view está em exemplos/ComoUsarVigia.php.

public function salvar()
{
    try {
        if (!JSession::checkToken()) {
            return ApiResponseHelper::forbidden('Sua sessão expirou. Recarregue a página.');
        }

        $dados = InputHelper::post(array('nome' => 'string', 'email' => 'string', 'cpf' => 'string'));

        $validacao = ValidationHelper::validate($dados, array(
            'nome' => 'required|min_length:3',
            'email' => 'required|email',
            'cpf' => 'required|cpf',
        ));

        if (!$validacao['valid']) {
            return ApiResponseHelper::fromValidation($validacao);   // 422: o Vigia mostra nos campos
        }

        // ... grava

        return ApiResponseHelper::created('Cliente cadastrado com sucesso.', array('id' => $id));
    } catch (Throwable $e) {
        return ApiResponseHelper::exception($e);
    }
}

Ciclo de vida do envio

Saber a ordem exata evita a maior parte das surpresas (por que um campo não validou, onde injetar dados extras, quando o botão volta ao normal):

  1. Carregamento. O formulário recebe novalidate (os balões nativos do navegador somem), os erros de data-vigia-errors são mostrados e as máscaras formatam os valores que vieram do servidor.
  2. Digitação. Com validateOn: 'blur' (padrão), o campo é validado ao perder o foco; depois do primeiro erro, a cada tecla, até ficar válido. Checkbox, rádio, <select> e arquivo validam já no change. Mudar um campo revalida os campos com erro que dependem dele (same, confirmed, required_if, after:inicio…).
  3. Envio. Se já houver um envio em andamento, o clique é ignorado. Com data-vigia-confirm, a confirmação vem primeiro.
  4. Validação completa. Todos os campos são validados (regras síncronas e assíncronas). Com erro: nada é enviado, o foco vai para o primeiro campo inválido e dispara vigia:invalid.
  5. vigia:before. Último ponto para cancelar (preventDefault() ou onBefore devolvendo false) ou ajustar campos ocultos: o corpo da requisição é montado depois deste evento.
  6. Requisição. O corpo é montado a partir dos campos (FormData), o botão clicado entra com name/value, os botões são desabilitados, data-loading-text aparece e [data-vigia-progress] acompanha o upload.
  7. Resposta. 2xx com success: true: limpa os erros, mostra a mensagem, dispara vigia:success, aplica reset/redirect. 4xx/5xx, success: false, rede ou timeout: erros nos campos, mensagem geral para o resto, vigia:error.
  8. vigia:complete. Sempre, no fim: botões e texto voltam ao normal.

vigia.submit() nunca rejeita: resolve com a resposta normalizada, com { valid: false, errors } (validação local falhou), ou com null (cancelado, confirmação negada ou envio já em andamento).

Como os campos viram dados

O Vigia lê o formulário como o PHP lê o $_POST: o name decide a estrutura. A mesma estrutura serve para validar (getData()), enviar (toFormData()) e casar os erros do servidor com os campos.

Regras gerais, iguais às do navegador num envio comum:

  • Checkbox e rádio desmarcados não existem nos dados (nem no envio). Para sempre receber um valor, use o padrão do Joomla: <input type="hidden" name="x" value="0"> antes do checkbox com value="1".
  • disabled fica de fora: não é validado nem enviado. Para mostrar sem deixar editar e ainda enviar, use readonly.
  • Campos fora do <form> com form="id-do-form" entram normalmente.
  • type="hidden" entra e é validado se tiver regra.
  • Arquivo vazio não é enviado (o PHP não vê a chave).
  • Com data-unmask, o valor validado e enviado é o sem máscara (veja Máscaras e regras).

Nunca use itens[][campo] para linhas com mais de um campo. Cada [] abre um item novo, no navegador e no PHP: itens[][sku] + itens[][qtd] viram [{ sku }, { qtd }], dois itens pela metade. Use sempre o índice explícito: itens[0][sku], itens[0][qtd]. Veja Listas e linhas dinâmicas.

<input id="nome" name="nome" class="form-control" required minlength="3" maxlength="80">

<input name="email" type="email" class="form-control" required>

Os atributos nativos (required, minlength, maxlength, pattern, type) viram regras sozinhos e se somam ao data-rules. Tamanhos contam caracteres, não bytes: "ação" tem 4. Um texto só de espaços conta como vazio para o required.

Números e dinheiro

<!-- Inteiro nativo: vira numeric + min + max -->
<input name="quantidade" type="number" min="1" max="99" step="1" class="form-control" required>

<!-- Inteiro com máscara (1.234.567), enviado sem pontos -->
<input name="estoque" data-mask="integer" data-unmask data-rules="required|integer|min:0">

<!-- Dinheiro: a pessoa vê R$ 1.234,56, o servidor recebe 1234.56 -->
<input name="preco" data-mask="money" data-unmask data-rules="required|numeric|min:0.01|max:99999.99">

<!-- Percentual com 1 casa -->
<input name="desconto" data-mask="percent" data-mask-decimals="1" data-unmask data-rules="numeric|between:0,100">

<!-- Peso com 3 casas e sufixo -->
<input name="peso" data-mask="decimal" data-mask-decimals="3" data-mask-suffix=" kg" data-unmask data-rules="numeric|min:0.001">
  • min/max/between comparam o valor quando o dado é número ("1.234,56" e "R$ 99,90" também contam), o tamanho quando é texto e a quantidade quando é lista.
  • integer não aceita 1.000 (com ponto). Com máscara integer, use data-unmask.
  • numeric é o is_numeric() do PHP (1234.56, não 1.234,56); decimal aceita o formato brasileiro.
  • type="number" devolve "" quando o texto não é número: nesse caso só o required acusa.

Valor vindo do banco em campo com máscara numérica Imprima sempre com as casas decimais: value="<?php echo number_format($preco, 2, '.', ''); ?>". A máscara lê "1234.50" como R$ 1.234,50, mas lê "5" como R$ 0,05 (dígitos digitados entram pela direita, como numa maquininha).

Datas e horários

<!-- Nativo: o navegador entrega Y-m-d (2026-10-05) -->
<input name="inicio" type="date" required data-rules="after_or_equal:today">
<input name="fim" type="date" required data-rules="after_or_equal:inicio">

<!-- Com máscara: a pessoa digita 05/10/2026 -->
<input name="nascimento" data-mask="date" data-rules="required|date_br|before:today">

<!-- Com máscara, mas enviando Y-m-d: aí a regra é date, não date_br -->
<input name="vencimento" data-mask="date" data-unmask data-rules="required|date|after:today">

<input name="hora" type="time" required>                               <!-- time: H:i ou H:i:s -->
<input name="hora_abertura" data-mask="time" data-rules="time">          <!-- 14:30 -->
<input name="agendado_para" type="datetime-local" required>             <!-- datetime:Y-m-d\TH:i -->
<input name="evento" data-mask="datetime" data-rules="datetime:d/m/Y H:i">
<input name="competencia" type="month" data-rules="regex:/^\d{4}-(0[1-9]|1[0-2])$/">
  • As datas são estritas: 31/02/2026 é inválida, assim como 5/10/2026 em date_br.
  • after, after_or_equal, before e before_or_equal aceitam o nome de outro campo (after:inicio), today, now, tomorrow, yesterday ou uma data fixa (2026-01-01, 01/01/2026). Datas dd/mm/aaaa são lidas sempre no formato brasileiro.
  • Formatos aceitos em date:, datetime: e time:: d j m n Y y H G i s, com \ para escapar (Y-m-d\TH:i).
  • type="month", week e color não geram regra automática: use regex.
  • "Hoje" é o relógio do navegador; o servidor usa o fuso dele. Perto da meia-noite os dois podem discordar: veja o DateHelper.

Campos ocultos e dados montados em JavaScript

Para enviar estado que não é um campo (um carrinho, coordenadas de um mapa, a ordem de uma lista arrastável), grave-o num oculto. A validação roda antes de vigia:before, então preencha o oculto quando o estado mudar, ou valide-o com uma regra:

<input type="hidden" name="carrinho" id="carrinho" data-rules="required|json" data-msg-required="Adicione ao menos um produto.">

<script>
function atualizarCarrinho(itens) {
    document.getElementById('carrinho').value = itens.length ? JSON.stringify(itens) : '';
}
</script>
$carrinho = InputHelper::json('carrinho');   // array decodificado ou array() se inválido

Senha e confirmação

<input type="password" name="senha" autocomplete="new-password" data-rules="required|password:10">
<input type="password" name="senha_confirmation" autocomplete="new-password" data-rules="required|same:senha" data-label="Confirmação da senha">

<!-- Alternativa: a regra fica no campo principal -->
<input type="password" name="senha" data-rules="required|password|confirmed">   <!-- compara com senha_confirmation -->

password e confirmed existem só no navegador. No servidor, use same:senha no campo de confirmação e uma closure para a força da senha. Ao digitar na senha, a confirmação com erro é revalidada sozinha.

Editores de texto (TinyMCE, editor do Joomla)

Editores ricos escrevem num <textarea> só quando mandados. Sincronize antes da validação, com um ouvinte de submit na fase de captura (roda antes do Vigia):

<?php echo $this->form->getInput('descricao'); ?>   <!-- textarea name="jform[descricao]" -->

<script>
const form = document.getElementById('adminForm');

form.addEventListener('submit', function () {
    if (window.tinymce) {
        window.tinymce.triggerSave();   // copia o HTML do editor para o textarea
    }
}, true);   // true = captura: antes da validação do Vigia

Vigia.form(form, {
    rules: { 'jform.descricao': 'required|min_length:20' }
});
</script>

O min_length conta o HTML (<p> incluso). Para contar só o texto, use uma regra-função que remove as tags. A mensagem aparece depois do <textarea> (oculto pelo editor): coloque um <div data-error-for="jform.descricao"></div> abaixo do editor.

Campos do JForm (jform[...])

Formulários do Joomla ($this->form->getInput()) usam name="jform[email]" e id="jform_email". Para o Vigia a chave é jform.email, e o <label for="jform_email"> do JForm vira o nome nas mensagens. Duas situações:

  • Regras no navegador: use jform.email nas regras do JavaScript, ou acrescente o prefixo às regras do PHP antes do clientConfig().
  • Erros do servidor com chave email (porque o controller validou InputHelper::array('jform')): ponha data-field="email" no campo, ou acrescente o prefixo às chaves de erro.
// Prefixa as chaves de regras, mensagens e rótulos: 'email' -> 'jform.email'
function prefixarChaves(array $lista, $prefixo)
{
    $resultado = array();

    foreach ($lista as $chave => $valor) {
        $resultado[$prefixo . '.' . $chave] = $valor;
    }

    return $resultado;
}

$vigia = ValidationHelper::clientConfig(
    prefixarChaves(ClienteRegras::regras(), 'jform'),
    prefixarChaves(ClienteRegras::mensagens(), 'jform'),   // 'email.unique' -> 'jform.email.unique'
    prefixarChaves(ClienteRegras::rotulos(), 'jform')
);
// Controller
$dados = InputHelper::array('jform');
$validacao = ValidationHelper::validate($dados, ClienteRegras::regras());

if (!$validacao['valid']) {
    $validacao['errors'] = prefixarChaves($validacao['errors'], 'jform');   // 'email' -> 'jform.email'

    return ApiResponseHelper::fromValidation($validacao);
}

Campos fora do formulário e vários botões de envio

<form id="pedido" data-vigia action="..." method="post">
    ...
    <button type="submit" name="acao" value="salvar">Salvar</button>
    <button type="submit" name="acao" value="salvar_e_novo" data-loading-text="Salvando…">Salvar e novo</button>
</form>

<!-- Fora do <form>, num modal ou numa barra fixa: entra no envio -->
<textarea name="observacao" form="pedido"></textarea>
<button type="submit" form="pedido" name="acao" value="salvar_e_fechar">Salvar e fechar</button>

O botão clicado vai no corpo (acao=salvar_e_novo), como num envio nativo, e só ele recebe o data-loading-text. O valor do botão não está em getData(): regras não podem depender dele. Botões fora do <form> entram no envio, mas não são desabilitados durante o carregamento: use :disabled="loading" (Alpine) ou o evento vigia:complete.

Sintaxe e ordem de execução

  • Todas as regras do campo rodam, na ordem declarada (não para no primeiro erro). A tela mostra a primeira mensagem; Vigia.config({ firstErrorOnly: false }) mostra todas; errors sempre tem todas.
  • Regras assíncronas (remote, image_dimensions, funções que devolvem Promise) rodam em sequência dentro do campo; campos diferentes rodam em paralelo. Se a pessoa digita de novo antes da resposta, a resposta antiga é descartada.
  • Regra desconhecida passa (como no PHP): um erro de digitação em data-rules="requried" não acusa nada. Confira com Vigia.rules.has('requried').
  • Nomes de regra não diferenciam maiúsculas; parâmetros sim (in:SP,RJ não aceita sp).
  • regex e remote recebem tudo depois do : como um único parâmetro, com vírgulas e |.

Mensagens e rótulos

As mensagens são as mesmas do ValidationHelper (O campo :field é obrigatório.), com :field, :value, :min, :max, :other, :date e :values. A mensagem de uma regra é escolhida nesta ordem (a primeira que existir):

  1. messages['campo.regra'] (email.required, itens.2.qtd.min);
  2. messages['padrão.regra'] (itens.*.qtd.min);
  3. messages['regra'] (vale para o formulário todo);
  4. atributo data-msg-regra no campo (_ vira -: data-msg-min-length, data-msg-file-size);
  5. Vigia.config({ messages }) (site todo);
  6. a mensagem de Vigia.rules.add(nome, fn, mensagem);
  7. a padrão do Vigia (igual à do PHP).

O nome no lugar de :field vem, nesta ordem:

  1. dos rótulos do PHP/JS (labels, inclusive itens.*.quantidade);
  2. do atributo data-label do campo;
  3. do texto do <label for> (sem a estrela * do Joomla) ou do <label> em volta;
  4. do aria-label;
  5. do nome do campo, como no PHP: data_nascimento → "Data nascimento".

Campos de lista ganham o número do item: itens.1.quantidade → "Quantidade (item 2)".

public function enviar()
{
    try {
        if (!JSession::checkToken()) {
            return ApiResponseHelper::forbidden('Sua sessão expirou. Recarregue a página.');
        }

        $contrato = InputHelper::file('contrato');   // array do $_FILES ou null
        $fotos = InputHelper::files('fotos');         // lista de arrays do $_FILES (vazia se nada veio)

        $validacao = ValidationHelper::validate(
            array('contrato' => $contrato, 'fotos' => $fotos),
            array(
                'contrato' => 'required|file|file_size:10M|file_extension:pdf|file_mime:application/pdf',
                'fotos' => 'required|array|max:5',
                'fotos.*' => 'file|file_size:3M|file_extension:jpg,jpeg,png,webp|image|image_dimensions:4000,4000',
            ),
            array(),
            array('fotos.*' => 'Foto')
        );

        if (!$validacao['valid']) {
            // 'fotos.2' aparece embaixo do campo fotos[]
            return ApiResponseHelper::fromValidation($validacao);
        }

        $resultado = UploadMaster::upload($contrato, 'contratos', null, array('allowed_extensions' => array('pdf')));
        $envioFotos = UploadMaster::uploadMany($fotos, 'fotos', array('allowed_extensions' => array('jpg', 'jpeg', 'png', 'webp')));

        if (!$resultado['success'] || !$envioFotos['success']) {
            return ApiResponseHelper::error($resultado['success'] ? $envioFotos['mensagem'] : $resultado['mensagem']);
        }

        return ApiResponseHelper::created('Documentos enviados.', array(
            'contrato' => UploadMaster::publicData($resultado['data']),
        ));
    } catch (Throwable $e) {
        return ApiResponseHelper::exception($e);
    }
}

4. Acima do limite do servidor: envio em partes

Quando o arquivo é maior do que o servidor aceita numa requisição (ou a conexão é instável), divida-o no navegador com Blob.slice() e mande uma parte por requisição. Cada parte é um upload pequeno, que passa por todos os limites, pode ser reenviada sozinha se falhar e mostra progresso real.

partes.js
/*
 * Envia um File em partes de 5 MB. Cada parte tenta até 3 vezes.
 * Resolve com a resposta do "finalizar" (dados do arquivo montado).
 */
async function enviarEmPartes(arquivo, { urlParte, urlFinalizar, tamanhoParte = 5 * 1048576, aoProgredir, signal } = {}) {
    // 24 caracteres hexadecimais aleatórios (getRandomValues funciona também sem HTTPS)
    const uploadId = Array.from(crypto.getRandomValues(new Uint8Array(12)), b => b.toString(16).padStart(2, '0')).join('');
    const total = Math.ceil(arquivo.size / tamanhoParte);

    for (let indice = 0; indice < total; indice++) {
        const parte = arquivo.slice(indice * tamanhoParte, (indice + 1) * tamanhoParte);

        for (let tentativa = 1; ; tentativa++) {
            try {
                await Vigia.http.post(urlParte, { upload_id: uploadId, indice, total, parte }, { timeout: 120000, signal });
                break;
            } catch (erro) {
                // Cancelado, inválido (422) ou proibido (403): não adianta tentar de novo
                if (erro.isCancel || erro.httpStatus === 422 || erro.httpStatus === 403 || tentativa === 3) {
                    throw erro;
                }

                await new Promise(r => setTimeout(r, 1000 * tentativa));
            }
        }

        if (aoProgredir) {
            aoProgredir(Math.round(((indice + 1) / total) * 100));
        }
    }

    return Vigia.http.post(urlFinalizar, { upload_id: uploadId, total, nome: arquivo.name, tamanho: arquivo.size }, { timeout: 0, signal });
}

class LojaControllerArquivo extends JControllerLegacy
{
    const TAMANHO_MAXIMO = 2147483648;                     // 2 GB
    const EXTENSOES = array('mp4' => 'video/mp4', 'zip' => 'application/zip', 'pdf' => 'application/pdf');

    // Uma pasta por pessoa e por envio: ninguém completa o upload de outro
    private function pastaDoEnvio($uploadId)
    {
        return JPATH_ROOT . '/tmp/envios/' . (int) JFactory::getUser()->id . '-' . $uploadId;
    }

    public function parte()
    {
        try {
            if (!JSession::checkToken()) {
                return ApiResponseHelper::forbidden('Sua sessão expirou. Recarregue a página.');
            }

            $dados = InputHelper::post(array('upload_id' => 'cmd', 'indice' => 'int', 'total' => 'int'));
            $dados['parte'] = InputHelper::file('parte');

            $validacao = ValidationHelper::validate($dados, array(
                'upload_id' => 'required|regex:/^[a-f0-9]{24}$/',
                'indice' => 'integer|min:0',
                'total' => 'required|integer|min:1|max:1000',
                'parte' => 'required|file|file_size:8M',   // folga sobre os 5 MB do JS
            ));

            if (!$validacao['valid']) {
                return ApiResponseHelper::fromValidation($validacao);
            }

            if ($dados['indice'] >= $dados['total']) {
                return ApiResponseHelper::badRequest('Parte fora da sequência.');
            }

            $pasta = $this->pastaDoEnvio($dados['upload_id']);

            if (!is_dir($pasta) && !mkdir($pasta, 0750, true) && !is_dir($pasta)) {
                throw new RuntimeException('Não foi possível criar a pasta temporária.');
            }

            // Um arquivo por parte: reenviar a mesma parte só a substitui

            if (!move_uploaded_file($dados['parte']['tmp_name'], $destino)) {
                throw new RuntimeException('Não foi possível gravar a parte.');
            }

            return ApiResponseHelper::success('Parte recebida.', array('indice' => $dados['indice']));
        } catch (Throwable $e) {
            return ApiResponseHelper::exception($e);
        }
    }

    {
        try {
            if (!JSession::checkToken()) {
                return ApiResponseHelper::forbidden('Sua sessão expirou. Recarregue a página.');
            }

            $dados = InputHelper::post(array('upload_id' => 'cmd', 'total' => 'int', 'nome' => 'string', 'tamanho' => 'int'));

            $validacao = ValidationHelper::validate($dados, array(
                'upload_id' => 'required|regex:/^[a-f0-9]{24}$/',
                'total' => 'required|integer|min:1|max:1000',
                'nome' => 'required|max_length:255',
                'tamanho' => 'required|integer|min:1|max:' . self::TAMANHO_MAXIMO,

                return ApiResponseHelper::fromValidation($validacao);
            }

            $extensao = strtolower(pathinfo($dados['nome'], PATHINFO_EXTENSION));
            $extensoes = self::EXTENSOES;

            if (!isset($extensoes[$extensao])) {
                return ApiResponseHelper::validationError(array('video' => array('Tipo de arquivo não permitido.')));
            }

            $pasta = $this->pastaDoEnvio($dados['upload_id']);
            $partes = glob($pasta . '/*.part') ?: array();
            sort($partes);

            if (count($partes) !== $dados['total']) {
                return ApiResponseHelper::conflict('O envio está incompleto. Tente enviar o arquivo de novo.');
            }

            // Fora da pasta pública (ou bloqueada por .htaccess): entregue com UploadMaster::stream()
            $pastaFinal = JPATH_ROOT . '/arquivos-privados/aulas';
            $nomeFinal = bin2hex(random_bytes(16)) . '.' . $extensao;

            if (!is_dir($pastaFinal) && !mkdir($pastaFinal, 0750, true) && !is_dir($pastaFinal)) {
                throw new RuntimeException('Não foi possível criar a pasta de destino.');
            }

            $saida = fopen($pastaFinal . '/' . $nomeFinal, 'wb');

            foreach ($partes as $arquivoParte) {
                $entrada = fopen($arquivoParte, 'rb');
                stream_copy_to_stream($entrada, $saida);   // copia em blocos: memória constante
                fclose($entrada);
            }

            fclose($saida);

            // Confere tamanho e conteúdo real do arquivo montado
            $caminho = $pastaFinal . '/' . $nomeFinal;
            $finfo = finfo_open(FILEINFO_MIME_TYPE);
            $mime = finfo_file($finfo, $caminho);
            finfo_close($finfo);

            array_map('unlink', $partes);
            rmdir($pasta);

            if (filesize($caminho) !== $dados['tamanho'] || $mime !== $extensoes[$extensao]) {
                unlink($caminho);

                return ApiResponseHelper::validationError(array('video' => array('O arquivo enviado está corrompido ou não é do tipo informado.')));
            }

            // Lembra quem enviou: o controller do formulário só aceita video_arquivo que estiver aqui
            JFactory::getSession()->set('com_loja.envio.' . $nomeFinal, true);

            return ApiResponseHelper::created('Arquivo recebido.', array(
                'arquivo' => $nomeFinal,
                'tamanho' => UploadMaster::formatBytes(filesize($caminho)),
            ));
        } catch (Throwable $e) {
            return ApiResponseHelper::exception($e);
        }
    }
}
  • Tamanho da parte: 2 a 10 MB. Abaixo disso, o custo de cada requisição domina; acima, uma falha reenvia muito. Precisa caber com folga no upload_max_filesize.
  • Limpeza: envios abandonados deixam pastas em tmp/envios. Apague as antigas num cron: find /caminho/tmp/envios -mindepth 1 -maxdepth 1 -mmin +1440 -exec rm -rf {} +.
  • Retomar depois de recarregar a página: guarde o uploadId no localStorage e crie uma task que liste as partes já recebidas; o laço pula os índices existentes.
  • Para ler o arquivo montado em blocos (CSV gigante, por exemplo), use o ChunkHelper; para entregá-lo, UploadMaster::stream().

Formulários clássicos do Joomla

Para formulários que recarregam a página (task save com redirect), use data-vigia-submit="native": o Vigia valida e, se estiver tudo certo, deixa o navegador enviar. O token vai pelo campo do form.token, como sempre.

<form data-vigia data-vigia-submit="native" action="<?php echo JRoute::_('index.php?option=com_loja'); ?>" method="post"
      data-vigia-errors='<?php echo htmlspecialchars(json_encode($this->erros ?: new stdClass), ENT_QUOTES, 'UTF-8'); ?>'>

data-vigia-errors mostra, ao carregar, os erros que o controller guardou (veja Erros depois de recarregar). Na barra de ferramentas do administrador, que envia com Joomla.submitbutton, valide antes:

Joomla.submitbutton = function (task) {
    const form = document.getElementById('adminForm');

    if (task === 'item.cancel') {
        return Joomla.submitform(task, form);

    Vigia.form(form).validate().then(function (r) {
        if (r.valid) {
            Joomla.submitform(task, form);
        } else {
            Vigia.form(form).focusFirstError();
        }
    });
};

Regras e máscaras próprias

// Regra síncrona: (valor, parâmetros, contexto) — contexto.data tem todos os dados, contexto.field a chave
Vigia.rules.add('multiplo', function (valor, params) {
    return Number(valor) % Number(params[0]) === 0 || 'O campo :field deve ser múltiplo de ' + params[0] + '.';
});
// data-rules="required|integer|multiplo:5"

// Regra que compara com outro campo
Vigia.rules.add('menor_que', function (valor, params, contexto) {
    return Number(valor) < Number(contexto.data[params[0]]);
}, 'O campo :field deve ser menor que o valor máximo.');
// data-rules="menor_que:valor_maximo"

// Regra assíncrona (Promise)
Vigia.rules.add('cep_existe', function (valor) {
    return fetch('https://viacep.com.br/ws/' + valor.replace(/\D/g, '') + '/json/')
        .then(r => r.json())
        .then(d => !d.erro || 'CEP não encontrado.');
});

// Testar uma regra isolada
await Vigia.rules.test('cpf', '123.456.789-09');            // true
await Vigia.rules.test('multiplo', '7', ['5']);              // 'O campo :field deve ser múltiplo de 5.'
Vigia.rules.parse('required|max:5|regex:/^a|b$/');           // [{ name, params }, ...]

A assinatura muda conforme o lugar: em Vigia.rules.add a função recebe (valor, parâmetros, contexto); uma função direto em rules recebe (valor, dados, campo). Como o nome da outra regra está nos parâmetros, menor_que:valor_maximo se revalida sozinha quando valor_maximo muda.

Depuração

No console do navegador, com o formulário na tela:

const v = Vigia.form('#meu-form');

v.rules();        // regras finais por campo: confira se a regra que você espera está lá
v.getData();      // exatamente o que é validado (com data-unmask, já sem máscara)
await v.validate();           // { valid, errors } completo, inclusive erros sem campo na tela
[...v.toFormData()];          // pares [nome, valor] que serão enviados
Vigia.rules.has('requried');  // false: erro de digitação numa regra passa em silêncio

Na aba Rede (Network), confira na resposta: o status HTTP, o corpo JSON (success, mensagem, errors) e o request_id, que leva à linha do log do servidor. Avisos [Vigia] no console indicam JSON inválido em data-vigia ou regex mal escrita.

Erros comuns

SintomaCausa e solução
Vigia.js precisa do axiosO axios não foi carregado antes do Vigia (ou não carregou). Inclua o script do axios antes.
Envio bloqueado com "O campo X é obrigatório" na mensagem geral, sem campo X na telaHá uma regra (geralmente vinda do PHP pelo clientConfig()) para um campo que não está no formulário. Remova a chave das regras enviadas ao navegador.
"O servidor enviou uma resposta inesperada."O controller respondeu HTML ou texto (ex.: jexit(), aviso do PHP antes do JSON). Responda sempre com o ApiResponseHelper e confira se a URL leva format=json quando o componente exige.
403 em todo envioToken: falta JHtml::_('form.token') no formulário (Joomla 3) ou a sessão expirou. Com json: true, o JSession::checkToken() do Joomla 3 não lê o corpo JSON: use o envio padrão (multipart).
403 "sessão expirou" só com arquivos grandesO envio passou do post_max_size e o PHP descartou tudo, inclusive o token. Veja Arquivos grandes.
"O servidor demorou para responder" em uploadsTimeout de 30 s. Use request: { timeout: 0 } no formulário.
O erro do servidor não aparece no campoA chave em errors não corresponde ao name do campo (comum com jform[...]). Confira a tabela de correspondência, use data-field ou data-error-for.
Só chega um arquivo no PHPFalta [] no nome: name="fotos[]" multiple.
Linhas chegam "pela metade" no PHPNomes itens[][campo]: use índice explícito itens[0][campo].
Preço do banco aparece como R$ 0,05O valor foi impresso sem casas decimais (5). Use number_format($v, 2, '.', '').
date_br sempre inválidoO campo tem data-unmask, então o valor validado é Y-m-d: use date.
max:100 num percentual não acusa 150%Sem data-unmask, "150,00%" não é número e max mede o tamanho do texto. Use data-unmask + numeric.
Checkbox obrigatório passa desmarcadoHá um oculto value="0" com o mesmo nome. Use accepted.
Regra-função não rodaO campo está vazio (funções só rodam com valor). Combine com required ou veja a receita pelo menos um.
A regra funciona no navegador e não no servidorÉ uma regra só do navegador (remote, confirmed, password, placa…). Valide também no PHP.
Rótulo diferente entre navegador e servidorO navegador usa o <label>; o servidor, os rótulos do ValidationHelper. Passe os rótulos pelo clientConfig() para ficarem iguais.
Envio duplicadoNão junte @submit.prevent do Alpine ou outro onsubmit com o Vigia: ele já trata o envio e ignora cliques durante o carregamento.
A barra de progresso não andaA barra não tem data-vigia-progress. Em respostas muito rápidas (arquivos pequenos), ela pode pular direto para 100%.

  • Joomla 3.4.5+, 4 e 5. Token pelo campo do form.token (3) e pelo cabeçalho X-CSRF-Token e Joomla.getOptions('csrf.token') (4/5); mensagens pelo Joomla.renderMessages quando não há área no formulário.
