Guia: MySQL e PostgreSQL

O que o ORM adapta sozinho entre MySQL e PostgreSQL, e as poucas regras que você precisa conhecer.

Resumo

O mesmo código funciona nos dois bancos. O ORM detecta o banco de cada conexão (DbConnectionHelper::serverType()) e adapta o SQL que ele gera. O que você escreve como SQL cru (whereRaw, having, select, condições de join) não é adaptado, e é aí que moram as diferenças.

A regra mais importante: transação abortada

No PostgreSQL, depois de qualquer erro de SQL dentro de uma transação, ela fica abortada: todo comando seguinte falha com "current transaction is aborted" até um rollback. No MySQL, só o comando que falhou é desfeito e a transação continua.

Isso só importa quando você captura um erro de banco e quer continuar na mesma transação. A solução, que funciona igual nos dois bancos, é colocar o trecho que pode falhar num run() aninhado. Ele vira um savepoint, e o rollback do savepoint limpa o estado abortado.

// ERRADO no PostgreSQL: depois do primeiro duplicado, todos os seguintes falham
DbTransactionHelper::run(function () use ($clientes) {
    foreach ($clientes as $cliente) {
        try {
            OrmTables::table('#__clientes')->create($cliente);
        } catch (RuntimeException $e) {
            // duplicado: ignora... mas a transação ficou abortada
        }
    }
});

// CERTO nos dois bancos
DbTransactionHelper::run(function () use ($clientes) {
    foreach ($clientes as $cliente) {
        try {
            DbTransactionHelper::run(function () use ($cliente) {   // savepoint
                OrmTables::table('#__clientes')->create($cliente);
            }, ['retries' => 0]);
        } catch (RuntimeException $e) {
            // só este cliente foi desfeito; a transação continua válida
        }
    }
});

O que você precisa cuidar

TemaCuidadoComo fazer
Nomes de tabela e colunaO ORM coloca aspas nos nomes. No PostgreSQL, com aspas, "Nome" e "nome" são colunas diferentes.Crie tabelas e colunas em minúsculas (snake_case).
SQL cru com crasesCrases (`coluna`) são só do MySQL.Em whereRaw/select, escreva o nome sem aspas ou use $orm->db()->quoteName('coluna').
Texto entre aspas duplasNo PostgreSQL, "texto" é nome de coluna, não texto.Use aspas simples para textos em SQL cru.
FunçõesNOW() existe nos dois; YEAR(), IFNULL(), DATE_FORMAT() só no MySQL.Prefira filtros do ORM (whereBetween com datas) ou COALESCE(), que existe nos dois.
GROUP BYO PostgreSQL exige que toda coluna não agregada do select esteja no groupBy.Liste todas no groupBy().
whereLike em número/dataO PostgreSQL não aplica ILIKE em colunas numéricas ou de data.Use where/whereBetween nessas colunas.
Comparação de tiposO PostgreSQL é estrito: where('id', 'abc') numa coluna inteira dá erro (no MySQL, vira 0).Converta valores da tela (InputHelper::uint, (int)).
lockForUpdate + agregaçãoO PostgreSQL não aceita FOR UPDATE com COUNT/SUM.O ORM recusa nos dois bancos; trave com get().
DDL em transaçãoNo MySQL, CREATE/ALTER/TRUNCATE fazem commit implícito; no PostgreSQL, não.Não misture DDL com gravações na mesma transação.

MySQL
CREATE TABLE `#__loja_pedidos` (
  `id` INT AUTO_INCREMENT PRIMARY KEY,
  `cliente_id` INT NOT NULL,
  `status` VARCHAR(20) NOT NULL,
  `total` DECIMAL(10,2) NOT NULL DEFAULT 0,
  `pago` TINYINT(1) NOT NULL DEFAULT 0,
  `metadados` JSON NULL,
  `created_at` DATETIME NULL,
  `updated_at` DATETIME NULL,
  `deleted_at` DATETIME NULL
) ENGINE=InnoDB;
PostgreSQL
CREATE TABLE jos_loja_pedidos (
  id INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  cliente_id INTEGER NOT NULL,
  status VARCHAR(20) NOT NULL,
  total NUMERIC(10,2) NOT NULL DEFAULT 0,
  pago BOOLEAN NOT NULL DEFAULT FALSE,
  metadados JSONB NULL,
  created_at TIMESTAMP NULL,
  updated_at TIMESTAMP NULL,
  deleted_at TIMESTAMP NULL
);

Com GENERATED ALWAYS AS IDENTITY, o PostgreSQL recusa um id informado por você. Se precisar gravar ids explícitos (migrações, importações), use GENERATED BY DEFAULT AS IDENTITY.

Escrevendo código específico de um banco

Quando for inevitável, pergunte à conexão qual é o banco:

$orm = OrmTables::table('#__loja_pedidos', ['connection' => $conexao]);

$mesExpr = $orm->serverType() === DbConnectionHelper::POSTGRESQL
    ? "to_char(created_at, 'YYYY-MM')"
    : "DATE_FORMAT(created_at, '%Y-%m')";

$porMes = $orm
    ->select([$mesExpr . ' AS mes', 'SUM(total) AS total'])
    ->where('status', 'pago')
    ->groupBy('mes')
    ->get();

groupBy() coloca aspas no nome ("mes"), o que funciona porque mes é um alias do select. No PostgreSQL, agrupar por alias é permitido no GROUP BY.
