InputHelper

Leia os dados da requisição (formulário, URL, JSON e arquivos) já no tipo certo, com defaults previsíveis e sem exceções.

Visão geral

O InputHelper lê os dados da requisição (formulário, query string, corpo JSON, arquivos, cabeçalhos) já convertidos para o tipo certo. Ele substitui $_GET, $_POST e $input->get() nos controllers.

require_once JPATH_COMPONENT . '/helpers/InputHelper.php';

$id = InputHelper::uint('id');                          // int ≥ 0
$nome = InputHelper::string('nome');                    // texto sem HTML, sem espaços nas pontas
$preco = InputHelper::decimal('preco');                 // "1.234,56" → 1234.56
$ativo = InputHelper::bool('ativo');                    // "sim", "true", "1", "on" → true
$status = InputHelper::oneOf('status', array('aberto', 'pago'), 'aberto');
$email = InputHelper::email('email');                   // e-mail válido em minúsculas, ou ''
$itens = InputHelper::array('itens');                   // lista

As três regras que valem para todos os métodos

  1. Nunca lança exceção. Na pior hipótese, devolve o $default e registra o problema no log (categoria input_helper).
  2. Campo ausente ou inválido devolve o $default. "Inválido" depende do tipo: "abc" num int(), "talvez" num bool(), um e-mail malformado num email().
  3. Leitura não é validação. O InputHelper converte e limpa. Regras como "obrigatório", "máximo de 150 caracteres" ou "CPF válido" ficam com o ValidationHelper. Veja o padrão recomendado.

Fontes: de onde o valor é lido

Quase todos os métodos aceitam $source como último parâmetro:

$sourceLê deQuando usar
'request' (padrão)Query string + formulário e, se o campo não estiver lá e o corpo for JSON, o corpo JSONQuase sempre.
'get'Só a query string (?pagina=2)Filtros e paginação de listagens.
'post'Só o formulário enviado por POSTGravações, quando o valor não pode vir da URL.
'json'Só o corpo JSON da requisiçãoAPIs que recebem apenas JSON.
'files'Arquivos enviadosPrefira file()/files().
'server'Variáveis do servidorPrefira server(), ip()…
'cookie'CookiesLer preferências salvas em cookie.

Requisições JSON (fetch, axios)

Quando o JavaScript envia Content-Type: application/json, o PHP não preenche $_POST. Na fonte 'request', o InputHelper procura o campo no corpo JSON quando ele não vem no formulário. O mesmo controller atende formulários e fetch() sem nenhuma mudança:

Front-end
// JavaScript: o token CSRF vai na URL (funciona no Joomla 3 e 4)
var token = Joomla.getOptions('csrf.token');

fetch('index.php?option=com_loja&task=pedidos.criar&format=json&' + token + '=1', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ cliente_id: 7, itens: [{ produto_id: 10, quantidade: 2 }] })
});
Controller
// PHP: igual para formulário ou JSON
if (!JSession::checkToken('get')) {        // token veio na URL
    return ApiResponseHelper::forbidden('Token inválido.');
}

$clienteId = InputHelper::uint('cliente_id');
$itens = InputHelper::array('itens');

Se o campo existir nos dois lugares, vale o do formulário/query string. Tipos nativos do JSON (números, true/false) são aceitos diretamente por int(), float(), decimal() e bool().

Usando null para saber se o campo veio

Nos métodos numéricos e no bool(), o $default pode ser null. Assim dá para diferenciar "não informado" de 0/false:

$clienteId = InputHelper::uint('cliente_id', null);   // null se não veio ou é inválido
$ativo = InputHelper::bool('ativo', null);            // true, false ou null

$pedidos = OrmTables::table('#__loja_pedidos')
    ->when($clienteId !== null, function ($q) use ($clienteId) {
        $q->where('cliente_id', $clienteId);
    })
    ->when($ativo !== null, function ($q) use ($ativo) {
        $q->where('ativo', $ativo);
    })
    ->get();

Textos

string()estático

InputHelper::string(string $name, string $default = '', string $source = 'request', bool $trim = true): string

Texto sem HTML: o filtro do Joomla remove as tags e decodifica entidades (&amp; vira &). Remove espaços nas pontas. Ideal para campos curtos: nome, título, cidade.

ParâmetroTipoDescrição
$namestringNome do campo.
$defaultstringValor se ausente.
$sourcestringDe onde ler. Padrão 'request'. Veja fontes.
$trimboolRemover espaços nas pontas.
$nome = InputHelper::string('nome');                // " <b>Ana</b> " → "Ana"
$cidade = InputHelper::string('cidade', 'São Paulo', 'get');

O filtro trata qualquer trecho entre < e > como tag: "a < b e b > c" vira "a c". Em textos livres, onde o usuário pode escrever <, use text().

text()estático

InputHelper::text(string $name, string $default = '', string $source = 'request', bool $trim = true): string

Texto livre preservado como foi digitado, inclusive < e >. Remove só caracteres de controle (mantém quebras de linha e tabulação). Texto com UTF-8 inválido devolve o $default.

$observacao = InputHelper::text('observacao');      // "Entregar se valor < 100" preservado

O valor não é seguro para imprimir como HTML. Escape na saída: htmlspecialchars($valor, ENT_QUOTES, 'UTF-8') ou $this->escape($valor) nas views do Joomla. Gravar no banco pelo ORM e devolver em JSON é seguro.

raw()estático

InputHelper::raw(string $name, string $default = '', string $source = 'request', bool $trim = true): string

O valor exatamente como chegou, sem filtro algum (só remove espaços nas pontas, se $trim). Use para conteúdo que você vai processar: tokens, assinaturas, JSON em texto, senhas.

$senha = InputHelper::raw('senha', '', 'post', false);   // sem trim: espaços contam
$assinatura = InputHelper::raw('signature', '', 'server');

html()estático

InputHelper::html(string $name, string $default = '', string $source = 'request'): string

HTML vindo de um editor. Aplica os Filtros de texto da Configuração Global do Joomla (Sistema → Configuração Global → Filtros de texto) para o grupo do usuário logado: no padrão, remove <script>, <iframe>, atributos como onclick, e mantém a formatação. Não remove espaços.

$conteudo = InputHelper::html('conteudo');
// '<p onclick="x">Olá <b>mundo</b></p><script>...</script>' → '<p>Olá <b>mundo</b></p>'

O resultado depende da configuração do site: super usuários costumam ter "Sem filtragem". Fora do CMS (sem JComponentHelper), todas as tags são removidas.

cmd() / word() / alnum()estático

InputHelper::cmd(string $name, string $default = '', string $source = 'request'): string InputHelper::word(string $name, string $default = '', string $source = 'request'): string InputHelper::alnum(string $name, string $default = '', string $source = 'request'): string

Identificadores técnicos. Removem tudo o que não é permitido, inclusive acentos.

$task = InputHelper::cmd('task');        // "pedidos.salvar"    (A-Z a-z 0-9 . _ -)
$view = InputHelper::word('view');       // "pedidos"           (letras e _)
$codigo = InputHelper::alnum('codigo');  // "ABC123"            (letras e números)
MétodoMantém"Olá Mundo!" vira
cmd()letras sem acento, números, . _ - (sem ponto no início)"OlMundo"
word()letras sem acento e _"OlMundo"
alnum()letras sem acento e números"OlMundo"

Nunca use em textos digitados por pessoas. Para opções de uma lista, prefira oneOf(), que recusa valores fora da lista em vez de "limpá-los".

username() / base64() / path()estático

InputHelper::username(string $name, string $default = '', string $source = 'request'): string InputHelper::base64(string $name, string $default = '', string $source = 'request'): string InputHelper::path(string $name, string $default = '', string $source = 'request'): string

Filtros específicos do Joomla: username() remove < > " ' % & e caracteres de controle; base64() mantém só caracteres de base64; path() mantém caminhos de arquivo.

$usuario = InputHelper::username('usuario');    // "ana<script>" → "anascript"
$token = InputHelper::base64('token');

path() não bloqueia ../: "/var/www/../etc" passa intacto. Nunca monte caminhos de arquivo com valores do usuário sem confirmar que o resultado está dentro da pasta permitida (realpath() + comparação de prefixo), ou use um nome de arquivo com cmd().

Números e booleanos

int()estático

InputHelper::int(string $name, ?int $default = 0, string $source = 'request'): ?int

Inteiro. Aceita só um número inteiro completo, com sinal opcional e espaços nas pontas. Qualquer outra coisa devolve o $default.

InputHelper::int('ajuste');          // "-5" → -5     "42" → 42
InputHelper::int('ajuste', 0);       // "abc" → 0     "12abc" → 0     "1.9" → 0     "" → 0
InputHelper::int('ajuste', null);    // ausente → null

uint()estático

InputHelper::uint(string $name, ?int $default = 0, string $source = 'request'): ?int

Inteiro maior ou igual a zero. Valor negativo conta como inválido e devolve o $default. É o método certo para ids, quantidades e páginas.

$id = InputHelper::uint('id');                  // "-5" → 0 (default)
$pagina = InputHelper::uint('pagina', 1);       // "?pagina=" → 1     "?pagina=0" → 0
$quantidade = InputHelper::uint('quantidade', 1, 'post');

0 é um valor válido. Se a página não pode ser 0, use max(1, InputHelper::uint('pagina', 1)), ou deixe o paginate() do ORM, que já trata valores menores que 1.

decimal()estático

InputHelper::decimal(string $name, ?float $default = 0.0, string $source = 'request'): ?float

Número digitado por pessoas, no formato brasileiro ou americano, com ou sem símbolo de moeda. O separador decimal é o último que aparece.

$preco = InputHelper::decimal('preco');
EntradaResultadoObservação
"1.234,56"1234.56brasileiro com milhar
"1,234.56"1234.56americano com milhar
"10,5"10.5
"10.5"10.5como o <input type="number"> envia
"R$ 99,90"99.9R$, US$, $, € e espaços são ignorados
"1.500.000"1500000.0vários pontos: milhar
"1.500"1.5um único ponto: decimal
"abc", ""$default

O caso ambíguo é "1.500". Se o seu campo usa máscara brasileira, configure-a para sempre enviar os centavos ("1.500,00"), e o valor será lido sem ambiguidade.

float()estático

InputHelper::float(string $name, ?float $default = 0.0, string $source = 'request'): ?float

Número no formato de máquina: ponto como decimal, notação científica aceita ("1e3"). "10,50" é inválido e devolve o $default. Para valores digitados por pessoas, use decimal().

$latitude = InputHelper::float('lat', null);     // "-23.5505" → -23.5505

bool()estático

InputHelper::bool(string $name, ?bool $default = false, string $source = 'request'): ?bool

Booleano, entendendo as formas comuns em português e inglês. Valores não reconhecidos devolvem o $default.

$ativo = InputHelper::bool('ativo');                     // checkbox marcado ("on") → true; desmarcado (não vem) → false
$notificar = InputHelper::bool('notificar', true);      // padrão true quando não vem
ResultadoEntradas (sem diferenciar maiúsculas)
true1, true, on, yes, y, sim, s
false0, false, off, no, n, nao, não, vazio
$defaultcampo ausente ou qualquer outro valor

Listas permitidas, e-mail, documentos e datas

oneOf()estático

InputHelper::oneOf(string $name, array $allowed, mixed $default = null, string $source = 'request'): mixed

O valor só é aceito se estiver em $allowed. Comparação exata, diferenciando maiúsculas. Devolve o item da lista, com o tipo dele, ou o $default.

$status = InputHelper::oneOf('status', array('aberto', 'pago', 'cancelado'), '');
$porPagina = InputHelper::oneOf('por_pagina', array(10, 25, 50), 25);   // "50" → 50 (int)

$pedidos = OrmTables::table('#__loja_pedidos')
    ->when($status, function ($q, $status) {
        $q->where('status', $status);
    })
    ->paginate($porPagina, InputHelper::uint('pagina', 1));

email()estático

InputHelper::email(string $name, string $default = '', string $source = 'request'): string

E-mail válido, em minúsculas. Um e-mail inválido devolve o $default: ele nunca é "consertado".

$email = InputHelper::email('email');    // " Ana@Ex.com " → "ana@ex.com"     "ana silva@ex.com" → ""

Como inválido e ausente devolvem o mesmo '', para avisar "e-mail inválido" ao usuário leia com string() e valide com o ValidationHelper (regra email).

cpf() / cnpj() / phone()estático

InputHelper::cpf(string $name, string $default = '', string $source = 'request'): string InputHelper::cnpj(string $name, string $default = '', string $source = 'request'): string InputHelper::phone(string $name, string $default = '', string $source = 'request'): string

Removem a máscara e deixam só os dígitos. Sem nenhum dígito, devolvem o $default. Não validam dígito verificador nem tamanho: use ValidationHelper::cpf() e ValidationHelper::cnpj().

$cpf = InputHelper::cpf('cpf');             // "123.456.789-09" → "12345678909"
$cnpj = InputHelper::cnpj('cnpj');          // "12.345.678/0001-95" → "12345678000195"
$telefone = InputHelper::phone('telefone'); // "(11) 99999-0000" → "11999990000"

if ($cpf !== '' && !ValidationHelper::cpf($cpf)) {
    return ApiResponseHelper::badRequest('CPF inválido.');
}

date() / dateBr()estático

InputHelper::date(string $name, string $default = '', string $source = 'request'): string InputHelper::dateBr(string $name, string $default = '', string $source = 'request'): string

Datas válidas de calendário. date() aceita AAAA-MM-DD (o formato do <input type="date">); dateBr() aceita DD/MM/AAAA e devolve AAAA-MM-DD, pronto para o banco. Datas inexistentes (30/02) devolvem o $default.

$de = InputHelper::date('de');               // "2026-10-01" → "2026-10-01"    "2026-02-30" → ""
$nascimento = InputHelper::dateBr('nasc');   // "28/02/1990" → "1990-02-28"

$pedidos = OrmTables::table('#__loja_pedidos')
    ->when($de, function ($q, $de) {
        $q->where('created_at', '>=', $de . ' 00:00:00');
    })
    ->get();

Listas

array()estático

InputHelper::array(string $name, array $default = array(), string $source = 'request'): array

Um campo que é lista ou estrutura (itens[0][produto_id], ou um array no JSON). Valor escalar vira lista de um item ("5" → ["5"]).

$itens = InputHelper::array('itens');

foreach ($itens as $item) {
    $produtoId = isset($item['produto_id']) ? (int) $item['produto_id'] : 0;
    $quantidade = isset($item['quantidade']) ? max(1, (int) $item['quantidade']) : 1;
}

Os valores dentro do array vêm sem filtro. Converta cada item, como acima, ou use arrayOfInt()/arrayOfString(), ou map() com filtros por campo.

arrayOfInt()estático

InputHelper::arrayOfInt(string $name, array $default = array(), string $source = 'request', bool $unique = true): int[]

Lista de ids: mantém só os valores numéricos maiores que zero, convertidos para inteiro, sem repetição (com $unique).

// <input type="checkbox" name="ids[]" value="3"> ...
$ids = InputHelper::arrayOfInt('ids');      // ["3", "x", "-1", "3", "8"] → [3, 8]

$removidos = OrmTables::table('#__loja_produtos')
    ->whereIn('id', $ids)          // lista vazia não remove nada
    ->deleteWhere();

arrayOfString()estático

InputHelper::arrayOfString(string $name, array $default = array(), string $source = 'request', bool $unique = true): string[]

Lista de textos: remove espaços nas pontas, descarta vazios e itens que não são texto, sem repetição.

$tags = InputHelper::arrayOfString('tags');   // [" a ", "", "b", "a"] → ["a", "b"]

Não remove HTML ("<b>a</b>" continua igual). Escape ao exibir.

Vários campos de uma vez

only()estático

InputHelper::only(array $fields, string $source = 'request'): array

Monta um array com os campos pedidos. Cada campo pode ter um filtro do Joomla; sem filtro, usa string. Campos ausentes vêm como null. Aceita estruturas aninhadas.

$dados = InputHelper::only(array(
    'nome',                                         // filtro 'string'
    'email',
    'idade' => 'int',
    'endereco' => array('rua' => 'string', 'numero' => 'int'),
), 'post');

// ['nome' => ' Ana ', 'email' => 'ana@ex.com', 'idade' => 30,
//  'endereco' => ['rua' => 'Rua A', 'numero' => 10]]

Usa os filtros do Joomla diretamente: não remove espaços e tem as regras do Joomla para cada tipo (veja value()). Para campos que precisam da conversão cuidadosa dos métodos individuais (decimal, bool, email), monte o array chamando cada método.

map() / post() / query() / request()estático

InputHelper::map(array $map, string $source = 'request'): array InputHelper::post(array $map): array // map($map, 'post') InputHelper::query(array $map): array // map($map, 'get') InputHelper::request(array $map): array // map($map, 'request')

Como only(), mas todo campo precisa de um filtro: ['campo' => 'filtro']. Mapa vazio devolve [].

$filtros = InputHelper::query(array(
    'status' => 'cmd',
    'cliente_id' => 'uint',
    'periodo' => array('de' => 'string', 'ate' => 'string'),
));

filters()estático

InputHelper::filters(array $map, string $source = 'request', bool $removeEmpty = true): array

Como map(), removendo os campos null, '' e listas vazias. Pensado para filtros de listagem: só sobra o que o usuário preencheu.

// ?status=pago&busca=&cliente=
$filtros = InputHelper::filters(array('status' => 'cmd', 'busca' => 'string', 'cliente' => 'string'));
// ['status' => 'pago']

Com o filtro int/uint do Joomla, um campo enviado vazio vira 0 e não é removido: ?cliente_id= gera ['cliente_id' => 0], e um where('cliente_id', 0) não encontraria nada. Para números opcionais, use InputHelper::uint('cliente_id', null).

Paginação e ordenação de listagens

pagination()estático

InputHelper::pagination(int $defaultLimit = 20, int $maxLimit = 100, string $source = 'request'): array

Lê page e limit da requisição. A página nunca é menor que 1, e o limite fica entre 1 e $maxLimit, o que impede um ?limit=1000000.

Retorna: ['page' => int, 'limit' => int, 'offset' => int]

// ?page=3&limit=50
$p = InputHelper::pagination(20, 100);     // ['page' => 3, 'limit' => 50, 'offset' => 100]

$resultado = OrmTables::table('#__loja_pedidos')
    ->latest()
    ->paginate($p['limit'], $p['page']);

Os nomes dos parâmetros são fixos: page e limit. Use os mesmos no front-end.

sorting()estático

InputHelper::sorting(array $allowedFields, string $defaultField, string $defaultDirection = 'ASC', string $source = 'request'): array

Lê sort e direction da requisição, aceitando só colunas de $allowedFields e direção ASC/DESC. Qualquer outro valor cai no padrão. É a forma segura de deixar o usuário escolher a ordenação.

Retorna: ['field' => string, 'direction' => 'ASC'|'DESC']

// ?sort=total&direction=desc
$ordem = InputHelper::sorting(array('created_at', 'total', 'status'), 'created_at', 'DESC');

$pedidos = OrmTables::table('#__loja_pedidos')
    ->orderBy($ordem['field'], $ordem['direction'])
    ->get();

Arquivos

file()estático

InputHelper::file(string $name, mixed $default = null): array|mixed

Um arquivo enviado (<input type="file" name="documento">), no formato ['name', 'type', 'tmp_name', 'error', 'size']. Campo enviado sem arquivo devolve o $default.

$arquivo = InputHelper::file('documento');

if ($arquivo === null) {
    return ApiResponseHelper::badRequest('Selecione um arquivo.');
}

if ($arquivo['error'] !== UPLOAD_ERR_OK) {
    return ApiResponseHelper::badRequest('Falha no envio do arquivo.');
}

O InputHelper só entrega o arquivo. Tipo, tamanho e conteúdo precisam ser validados: use o UploadMaster/FileHelper ou as regras file, file_size e file_extension do ValidationHelper. Nunca confie em name nem em type, que vêm do navegador.

files()estático

InputHelper::files(string $name, array $default = array()): array

Lista de arquivos de um campo múltiplo (<input type="file" name="anexos[]" multiple>). Campos sem arquivo são ignorados. Com um único arquivo, devolve uma lista de um item.

foreach (InputHelper::files('anexos') as $anexo) {
    if ($anexo['error'] === UPLOAD_ERR_OK) {
        // validar e mover $anexo['tmp_name']
    }
}

Corpo JSON completo

json()estático

InputHelper::json(string|null $name = null, array $default = array(), string $source = 'request'): array

Sem $name, decodifica o corpo inteiro da requisição. Com $name, decodifica um campo que contém JSON em texto. Devolve o $default se o conteúdo não for um objeto/array JSON válido.

$corpo = InputHelper::json();                          // corpo inteiro como array
$config = InputHelper::json('configuracao', array());  // campo com '{"tema":"escuro"}'

Para ler campos do corpo JSON, você não precisa de json(): os métodos comuns (uint(), string()…) já leem do corpo. Veja requisições JSON.

Informações da requisição

has()estático

InputHelper::has(string $name, string $source = 'request'): bool

O campo foi enviado? Campo vazio (?x=) conta como enviado.

if (InputHelper::has('preco', 'post')) {
    $dados['preco'] = InputHelper::decimal('preco', 0, 'post');   // só atualiza se veio
}

method() / isPost() / isGet()estático

InputHelper::method(): string // "GET", "POST", "PUT"... InputHelper::isPost(): bool InputHelper::isGet(): bool

Método HTTP da requisição.

if (!InputHelper::isPost()) {
    return ApiResponseHelper::methodNotAllowed();
}

isAjax() / expectsJson()estático

InputHelper::isAjax(): bool InputHelper::expectsJson(): bool // mesmo resultado

true se a requisição tem X-Requested-With: XMLHttpRequest, format=json ou Accept: application/json. Útil para responder JSON ou HTML no mesmo controller.

server() / ip() / userAgent() / referer()estático

InputHelper::server(string $name, string $default = ''): string InputHelper::ip(): string|null InputHelper::userAgent(): string InputHelper::referer(): string

Dados do servidor e do cliente. ip() devolve REMOTE_ADDR se for um IP válido, ou null.

$contexto = array(
    'ip' => InputHelper::ip(),
    'navegador' => InputHelper::userAgent(),
    'origem' => InputHelper::referer(),
);

Atrás de proxy reverso, CDN ou balanceador, ip() devolve o IP do proxy. O IP real vem em X-Forwarded-For, mas esse cabeçalho pode ser forjado pelo cliente: só use server('HTTP_X_FORWARDED_FOR') se a requisição tiver passado por um proxy que você controla. referer() e userAgent() também são informados pelo cliente: nunca os use para segurança.

Filtros do Joomla direto: value()

value()estático

InputHelper::value(string $name, mixed $default = null, string $filter = 'cmd', string $source = 'request'): mixed

Aplica um filtro do Joomla pelo nome. É o método usado por only() e map(). Repare que o filtro padrão é cmd.

$valor = InputHelper::value('campo', null, 'string');
FiltroComportamento do JoomlaPrefira

Os métodos individuais (int(), bool(), decimal()…) existem justamente para corrigir essas armadilhas. Use value(), only() e map() sabendo dessas regras.

Padrão recomendado no controller

Ler com o InputHelper, validar com o ValidationHelper, gravar com o ORM e responder com o ApiResponseHelper. Cada helper faz uma coisa:

controllers/clientes.php
public function salvar()
{
    if (!JSession::checkToken()) {
        return ApiResponseHelper::forbidden('Token inválido.');
    }

    // 1. Ler: cada campo com o tipo certo
    $id = InputHelper::uint('id', 0, 'post');
    $dados = array(
        'nome' => InputHelper::string('nome', '', 'post'),
        'email' => InputHelper::string('email', '', 'post'),      // string: a validação diz se é inválido
        'cpf' => InputHelper::cpf('cpf', '', 'post'),
        'limite_credito' => InputHelper::decimal('limite_credito', 0, 'post'),
        'ativo' => InputHelper::bool('ativo', false, 'post'),
        'tipo' => InputHelper::oneOf('tipo', array('pf', 'pj'), 'pf', 'post'),
        'observacao' => InputHelper::text('observacao', '', 'post'),
    );

    // 2. Validar: regras e mensagens para o usuário
    $validacao = ValidationHelper::validate($dados, array(
        'nome' => 'required|max_length:150',
        'email' => 'required|email',
        'cpf' => 'required|cpf',
        'limite_credito' => 'numeric|min:0',
    ));

    if (!$validacao['valid']) {
        return ApiResponseHelper::fromValidation($validacao);
    }

    // 3. Gravar e 4. Responder
    try {
        $clientes = OrmTables::table('#__loja_clientes', array(
            'fillable' => array_keys($dados),
        ));

        $cliente = $id > 0
            ? $clientes->update($id, $dados)
            : $clientes->create($dados);

        return ApiResponseHelper::success('Cliente salvo.', $cliente);
    } catch (Throwable $e) {
        return ApiResponseHelper::exception($e);
    }
}

Checklist de segurança

  • Confira o token CSRF em toda ação que grava: JSession::checkToken() quando ele vem no formulário, JSession::checkToken('get') quando vem na URL (requisições JSON).
  • Leia gravações com a fonte 'post', ou 'json' numa API, nunca da URL.
  • Colunas de ordenação e valores de lista só via sorting() e oneOf().
  • Texto de text(), raw(), array() e arrayOfString(): escape ao exibir em HTML.
  • Arquivos: valide tipo e tamanho e gere um nome novo. Nunca use name do upload como caminho.
  • Caminhos: path() não impede ../.
  • Permissões não são dados de entrada: confira com o PermissionHelper ou com JFactory::getUser()->authorise().
