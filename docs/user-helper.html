UserHelper

Usuário, grupos e perfil num lugar só, sobre as tabelas do Joomla (#__users, #__usergroups e #__user_usergroup_map): "está no grupo Gerentes?", membros de um grupo, perfil seguro para JSON, máscaras de CPF e e-mail (LGPD) e filtro de consultas pela cooperativa do usuário.

Visão geral

controller.php
IncludeHelper::load(['UserHelper', 'ApiResponseHelper', 'PermissionHelper']);

// Uma vez, no início do componente: nomes estáveis no lugar de ids fixos
UserHelper::setGroupAliases([
    'gerentes' => 'Gerentes',
    'ti'       => [25, 26],
]);

public function aprovar()
{
    if (!PermissionHelper::requireToken() || !UserHelper::requireGroup(['gerentes', 'ti'])) {
        return;   // 403 padronizado, com log e auditoria
    }

    $limite = UserHelper::valueByGroup([
        'Diretoria' => 100000,
        'gerentes'  => 20000,
    ], 1000);

    // ...
}

public function perfil()
{
    return ApiResponseHelper::success('Perfil carregado.', UserHelper::toApi());   // sem senha, CPF e e-mail mascarados
}
  • Grupo por id, nome ou apelido: inGroup(15), inGroup('Gerentes') ou inGroup('gerentes'). O nome ignora maiúsculas, acentos e espaços repetidos.
  • Herança como no ACL do Joomla: quem está em Gerentes Regionais (filho de Gerentes) também conta como membro de Gerentes. Para olhar só o grupo em que o usuário foi colocado, use inGroupDirect().
  • Falha fechada: grupo inexistente nunca libera acesso. A checagem dá false e vai um aviso para o log.
  • Nada sensível sai: as linhas de #__users passam por uma lista de campos permitidos. password, activation, otpKey, otep, params e afins nunca são devolvidos, e uma coluna nova na tabela não vaza sozinha.
  • Uma consulta por requisição: o catálogo de grupos e os usuários lidos ficam em memória; com setCacheSeconds() o catálogo vai para o CacheHelper.

Depende do OrmTables (carregado sozinho). Usa, se estiverem carregados, o LogHelper (avisos), o PermissionHelper (respostas 403), o AuditHelper (mudanças de grupo), o CacheHelper e o DateHelper. Funciona no Joomla 4.4, 5 e 6 e também fora dele, com uma conexão registrada no DbConnectionHelper.

Quem é o usuário: o parâmetro $user

Quase todos os métodos recebem o usuário no último parâmetro, opcional. Sem ele, vale o usuário logado. Ele aceita id, username, e-mail, JUser, objeto ou array com id:

UserHelper::inGroup('Gerentes');                 // usuário logado
UserHelper::inGroup('Gerentes', 152);            // pelo id
UserHelper::inGroup('Gerentes', 'maria');        // pelo username
UserHelper::inGroup('Gerentes', 'maria@x.com');  // pelo e-mail
UserHelper::inGroup('Gerentes', $pedido->user);  // objeto com ->id
MétodoDevolve
current($user = null)o JUser logado; fora do Joomla, a linha segura de #__users ou null
id($user = null)o id (0 = visitante ou não encontrado)
isLoggedIn() / isGuest()bool
isCurrent($user)é o usuário logado? (ex.: "não pode excluir a si mesmo")

Procura no nome, username e e-mail. Feito para autocomplete e campos de "escolher usuário".

valueByGroup() / whenInGroup()estático

UserHelper::valueByGroup(array $mapa, mixed $padrao = null, $user = null): mixed UserHelper::whenInGroup($grupo, callable $entao, ?callable $senao = null, $user = null): mixed

valueByGroup devolve o valor do primeiro grupo do mapa em que o usuário estiver (ordene do mais alto para o mais baixo). Valor ou padrão que seja Closure é executado. whenInGroup executa um dos callbacks, que recebem o usuário.

$limiteDeAprovacao = UserHelper::valueByGroup([
    'Diretoria' => 100000,
    'Gerentes'  => 20000,
    'Registered'=> 1000,
], 0);

UserHelper::whenInGroup('TI', function ($usuario) {
    JFactory::getDocument()->addScript('media/com_loja/js/debug.js');
});

Exigir grupo no controller: requireGroup() / requireAllGroups()

UserHelper::requireGroup($grupos, string $mensagem = '...', ?string $redirect = null, array $contexto = []): bool UserHelper::requireAllGroups(array $grupos, string $mensagem = '...', ?string $redirect = null, array $contexto = []): bool

Com o PermissionHelper carregado, segue o mesmo fluxo dele: registra no log e na auditoria, responde 401/403 (JSON encerra; HTML mostra a mensagem e redireciona se houver $redirect) e devolve false. Sem o PermissionHelper, lança RuntimeException com código 403.

if (!UserHelper::requireGroup('Gerentes', 'Só gerentes aprovam crédito.', JRoute::_('index.php?option=com_credito', false))) {
    return;
}

Esconder o botão na view não protege nada: a task do controller precisa do requireGroup. E, como no PermissionHelper, sempre escreva if (!...) { return; }: em HTML o Joomla não encerra a requisição.

Grupo é bom para regras de negócio ("limite do gerente", "fila da TI"). Para "pode editar/excluir" prefira ações da ACL (PermissionHelper::can('core.edit')), que o administrador concede a qualquer grupo sem mexer no código.

Apelidos: sem id fixo espalhado pelo código

O id de um grupo muda de um site para outro (desenvolvimento, homologação, produção), e o nome pode ser renomeado pelo administrador. Defina os apelidos uma vez, no início do componente, e use só eles no resto do código:

site/credito.php
UserHelper::setGroupAliases([
    'gerentes'  => 15,                        // id
    'ti'        => [25, 26],                  // vários grupos: qualquer um deles
    'diretoria' => 'Diretoria Executiva',     // nome
    'gestao'    => ['gerentes', 'diretoria'], // apelido de apelidos
]);

UserHelper::inGroup('gestao');

O segundo parâmetro ($merge = true) soma aos apelidos já definidos; false substitui todos. Apelidos que apontam um para o outro em ciclo lançam LogicException. groupAliases() devolve os definidos.

Alterar grupos

MétodoDevolve
addToGroup($user, $grupos)ids efetivamente adicionados (quem já estava fica de fora)
removeFromGroup($user, $grupos)ids removidos
syncGroups($user, $grupos)['added' => [...], 'removed' => [...]]: deixa o usuário exatamente nesses grupos

No Joomla usam o JUserHelper (mantém a sessão em dia); fora dele, gravam direto em #__user_usergroup_map. Cada mudança vai para o AuditHelper (evento user.group.add/user.group.remove) ou, sem ele, para o log.

Na escrita o helper é estrito: grupo desconhecido lança InvalidArgumentException (em vez de ser ignorado), usuário inexistente também, e tirar o último grupo do usuário lança LogicException. Confira o token e a permissão (core.admin ou requireGroup) antes: quem altera grupos altera acessos.

public function salvarGrupos()
{
    if (!PermissionHelper::requireToken() || !PermissionHelper::require('core.admin')) {
        return;
    }

    try {
        $mudou = UserHelper::syncGroups(InputHelper::int('user_id'), InputHelper::arrayOfInt('grupos'));

        return ApiResponseHelper::success('Grupos atualizados.', $mudou);
    } catch (InvalidArgumentException | LogicException $e) {
        return ApiResponseHelper::error($e->getMessage(), null, [], ['http_status' => 422]);
    } catch (Throwable $e) {
        return ApiResponseHelper::exception($e);
    }
}

Perfil e dados pessoais

O perfil junta #__users com os dados pessoais do usuário (sexo, data_nascimento, cpf, central, singular, pa, estado...). Os dados pessoais vêm de JFactory::getDadosPessoais() quando o Joomla do projeto tem esse método (só para o usuário logado). Para os demais usuários, ou num Joomla sem ele, informe de onde ler:

UserHelper::setDadosPessoaisResolver(function ($userId) {
    return OrmTables::table('#__dados_pessoais')->findBy('user_id', $userId);   // array ou objeto
});

Cooperativa e escopo de consultas

cooperativa() devolve ['central' => '300', 'singular' => '0300', 'pa' => '0', 'uf' => 'DF'] a partir dos dados pessoais (campo vazio vira null). Há atalhos para cada parte e checagens que ignoram zeros à esquerda ('0300' = 300):

UserHelper::central();  UserHelper::singular();  UserHelper::pa();  UserHelper::uf();   // 'DF' em maiúsculas

UserHelper::inSingular([300, 3001]);
UserHelper::inPa(0);
UserHelper::inUf(['DF', 'GO']);

scopeQuery()estático

UserHelper::scopeQuery(OrmBase $consulta, array $colunas, array $gruposLiberados = [], $user = null): OrmBase

Limita a consulta aos dados da cooperativa do usuário: cada chave (central, singular, pa ou uf) vira um where na coluna informada. Falha fechada: se o usuário não tiver o código, a consulta não devolve nada. Quem está em um dos $gruposLiberados vê tudo. Chave desconhecida lança InvalidArgumentException.

$propostas = OrmTables::table('#__credito_propostas AS p');

UserHelper::scopeQuery($propostas, [
    'singular' => 'p.cod_singular',
    'pa'       => 'p.cod_pa',
], ['Diretoria', 'TI']);

$lista = $propostas->orderBy('p.created_at', 'DESC')->paginate(20, $pagina);

Use o scopeQuery também no find do registro (editar, excluir, baixar): é a proteção contra IDOR para "cada PA só vê as suas propostas", no mesmo espírito do resolvedor de entidades do PermissionHelper.

Tipo do usuário: CCS, central, singular ou PA

O tipo sai dos códigos da singular e do PA nos dados pessoais, nesta ordem:

RegraTipoRótulo (userTypeLabel())
singular na lista do CCS (6004, 300, 1, 9805, 310, 382, 9986, 309)'CCS'Centro Cooperativo Sicoob
singular entre 1001 e 2999'CENTRAL'Cooperativa Central
singular acima de 3000 e PA maior que 0'PA'Posto de Atendimento
singular acima de 3000 e PA igual a 0'SINGULAR'Cooperativa Singular

UserHelper::userType();                         // 'PA'
UserHelper::userType() === UserHelper::TYPE_PA; // use as constantes TYPE_CCS, TYPE_CENTRAL, TYPE_SINGULAR, TYPE_PA, TYPE_OUTRO
UserHelper::userTypeLabel();                    // 'Posto de Atendimento'

UserHelper::isCcs();  UserHelper::isCentral();  UserHelper::isSingular();  UserHelper::isPa();

// Tudo junto, no formato do antigo verificarTipoUsuario()
UserHelper::userTypeInfo();
// ['ROLE' => 'PA', 'ROLE_LABEL' => 'Posto de Atendimento', 'CENTRAL' => 300, 'SINGULAR' => 3001, 'PA' => 2, 'NOME' => 'Maria da Silva Souza']

isSingular() é só quem está na sede da singular (PA = 0). Para "a singular e os seus PAs", use isType(['SINGULAR', 'PA']).

requireType()estático

UserHelper::requireType($tipos, $mensagem = 'Você não possui permissão para esta operação.', $redirect = null, array $contexto = []): bool

Barra quem não é de um dos tipos, no mesmo fluxo do requireGroup(): com o PermissionHelper carregado responde 401/403 e devolve false; sem ele lança RuntimeException com código 403.

if (!UserHelper::requireType(['CCS', 'CENTRAL'])) {
    return;
}

A lista de códigos do CCS pode ser trocada no bootstrap: UserHelper::setCcsCodes([6004, 300, 1]); ccsCodes() devolve a lista em uso.

Saídas prontas: perfil para API, log e LGPD

profile() / toApi()estático

UserHelper::profile($user = null, array $opcoes = []): ?array

Perfil seguro: id, nome, nome_curto, primeiro_nome, iniciais, username, email e cpf mascarados, sexo, idade, aniversario_hoje, cooperativa, tipo (ver Tipo do usuário), bloqueado, cadastrado_em, ultimo_acesso, timezone, idioma e grupos ([{id, nome, direto}]). null se o usuário não existir.

OpçãoPadrãoO que faz
groupstrueinclui a lista de grupos
sensitivefalsetrue devolve e-mail e CPF sem máscara e a data de nascimento
fields[]restringe às chaves informadas
return ApiResponseHelper::success('OK', UserHelper::toApi(null, ['fields' => ['nome', 'iniciais', 'grupos']]));

// Contexto mínimo para LogHelper/AuditHelper: user_id, username, singular, pa, tipo, ip, user_agent
LogHelper::info('Proposta aprovada.', 'credito', UserHelper::snapshot() + ['proposta' => $id]);

// Tirar campos sensíveis de qualquer usuário (JUser, objeto, array) antes de serializar
$seguro = UserHelper::sanitize(JFactory::getUser());

Máscaras soltas, para qualquer valor: maskCpf('12345678909') → '***.456.789-**', maskEmail('maria.silva@x.com') → 'ma*********@x.com', maskName('Maria da Silva Souza') → 'Maria da S. S.'. ip() devolve o REMOTE_ADDR (cabeçalhos de proxy não são considerados confiáveis).

Use 'sensitive' => true só para o próprio usuário (UserHelper::isCurrent($id)) ou para quem tem permissão de ver dados pessoais. Em listagens e telas de terceiros, devolva o perfil mascarado.
