RateLimitHelper

Limita tentativas por chave e janela de tempo (login, formulário de contato, envio de código por SMS, "esqueci minha senha", endpoints públicos) com contador atômico no banco e resposta 429 com Retry-After.

Visão geral

require_once JPATH_COMPONENT . '/helpers/RateLimitHelper.php';

public function enviarContato()
{
    // 5 mensagens por hora por IP; a 6ª recebe 429 "Muitas tentativas. Tente novamente em 42 minutos."
    if (!RateLimitHelper::enforce('contato:' . RateLimitHelper::ip(), 5, 3600)) {
        return;
    }

    // ...
}
  • Atômico: o incremento é um único INSERT ... ON DUPLICATE KEY UPDATE (MySQL/MariaDB) ou ON CONFLICT (PostgreSQL 9.5+). Testado com 20 pedidos simultâneos e limite 5: exatamente 5 passam.
  • Vale entre servidores: o contador está no banco, não na memória ou em arquivo de um servidor.
  • Chave como hash: e-mail e IP não ficam em claro na tabela.
  • Tabela criada sozinha no primeiro uso (#__helpers_rate_limits), com limpeza ocasional das chaves vencidas. Sem permissão de CREATE: rode tables/rateLimitHelper.sql (ou .postgresql.sql).

Métodos

hit()estático

RateLimitHelper::hit(string $key, int $max, int $seconds): array

Conta uma tentativa e devolve o estado:

ChaveO que é
allowedesta tentativa está dentro do limite
hits / limit / remainingtentativas na janela, limite e quantas restam
retry_aftersegundos até liberar (0 se permitido)
reset_attimestamp do fim da janela

enforce()estático

RateLimitHelper::enforce(string $key, int $max, int $seconds, string|null $message = null): bool

Como hit(); passou do limite: registra no log security, responde ApiResponseHelper::tooManyRequests() (HTTP 429 com Retry-After) e devolve false. Sempre: if (!RateLimitHelper::enforce(...)) { return; }. O Vigia.js mostra a mensagem 429 no formulário.

attempts() / tooManyAttempts()estático

RateLimitHelper::attempts(string $key): int RateLimitHelper::tooManyAttempts(string $key, int $max): bool

Consulta sem contar (ex.: mostrar captcha a partir da 3ª tentativa errada).

clear() / prune()estático

RateLimitHelper::clear(string $key): bool RateLimitHelper::prune(): bool

Zera uma chave (login certo apaga as tentativas erradas); apaga as vencidas (roda sozinho em 1% das tentativas).

ip() / setTrustedProxies()estático

RateLimitHelper::ip(): string RateLimitHelper::setTrustedProxies(array $ips): void

O IP de quem chamou. O cabeçalho X-Forwarded-For só é usado quando a conexão vem de um proxy seu (Cloudflare, load balancer): sem isso, um atacante manda um IP diferente a cada tentativa e nunca é limitado.

// Atrás de um load balancer em 10.0.0.2
RateLimitHelper::setTrustedProxies(array('10.0.0.2'));

Escolhendo a chave e o limite

CasoChaveLimite sugerido
Login (força bruta numa conta)'login:' . strtolower($usuario)5 por 15 min
Login (muitas contas de um IP)'login-ip:' . RateLimitHelper::ip()30 por 15 min
Esqueci minha senha'senha:' . strtolower($email) e por IP3 por hora
Código por SMS/WhatsApp (custa dinheiro)'sms:' . $telefone e 'sms-ip:' . $ip3 por hora / 10 por dia
Formulário de contato'contato:' . $ip5 por hora
API pública / busca pesada'api:' . $token ou IP60 por minuto
remote do Vigia.js (checar e-mail)'email-livre:' . $ip30 por minuto

Combine duas chaves quando o atacante pode variar uma delas: por conta e por IP.

Receitas

Login com bloqueio e desbloqueio

public function entrar()
{
    try {
        if (!JSession::checkToken()) {
            return ApiResponseHelper::forbidden('Sua sessão expirou. Recarregue a página.');
        }

        $usuario = strtolower(InputHelper::string('usuario', '', 'post'));
        $chaveConta = 'login:' . $usuario;

        if (!RateLimitHelper::enforce('login-ip:' . RateLimitHelper::ip(), 30, 900)) {
            return;
        }

        if (RateLimitHelper::tooManyAttempts($chaveConta, 5)) {
            return ApiResponseHelper::tooManyRequests('Muitas tentativas para este usuário. Aguarde 15 minutos ou redefina a senha.');
        }

        $ok = JFactory::getApplication()->login(array(
            'username' => $usuario,
            'password' => InputHelper::raw('senha', '', 'post'),
        ), array('silent' => true));

        if (!$ok) {
            RateLimitHelper::hit($chaveConta, 5, 900);   // conta só as erradas

            return ApiResponseHelper::unauthorized('Usuário ou senha incorretos.');
        }

        RateLimitHelper::clear($chaveConta);

        return ApiResponseHelper::success('Bem-vindo!', array('redirect' => JRoute::_('index.php?option=com_loja&view=painel', false)));
    } catch (Throwable $e) {
        return ApiResponseHelper::exception($e);
    }
}

A mensagem de bloqueio não deve confirmar se o usuário existe. "Usuário ou senha incorretos" para os dois casos; e o bloqueio por conta vale também para usuários que não existem.

Decidir sem responder

$estado = RateLimitHelper::hit('busca:' . RateLimitHelper::ip(), 60, 60);

if (!$estado['allowed']) {
    return ApiResponseHelper::tooManyRequests('Muitas buscas seguidas.', array('retry_after' => $estado['retry_after']));
}

header('X-RateLimit-Remaining: ' . $estado['remaining']);   // opcional, para clientes de API

Comportamento

  • Janela fixa: a janela começa na primeira tentativa e termina $seconds depois, sem se estender. Tentativas bloqueadas também contam (aparecem em hits), mas não adiam o fim da janela.
  • Banco fora do ar: por padrão libera (setFailOpen(true)), para não bloquear todo mundo por uma falha; o erro vai para o log rate_limit. Para limites críticos (SMS pago): setFailOpen(false) bloqueia.
  • Outro banco: setConnection('nome') (do DbConnectionHelper); outra tabela: setTable('#__minha_tabela').
  • O limite protege o servidor; a regra de negócio ("só 1 cupom por CPF") continua no banco, com unique.

Veja também

  • ApiResponseHelper: a resposta 429.
  • CryptoHelper: tokens e assinaturas.
  • LockHelper: uma execução por vez.
