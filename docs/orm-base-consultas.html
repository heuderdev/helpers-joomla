OrmBase: montando consultas

Filtros, grupos, joins, ordenação e travas: tudo o que define quais linhas a consulta vai buscar ou alterar.

Visão geral

Os métodos desta página só montam a consulta: devolvem a própria instância ($this) para você encadear o próximo. Nada vai ao banco até um método de leitura (get, first, count…) ou de escrita em massa.

$pedidos = OrmTables::table('#__loja_pedidos')
    ->select(['id', 'cliente_id', 'total', 'status'])
    ->where('status', 'pago')
    ->where('total', '>=', 100)
    ->whereBetween('created_at', '2026-01-01 00:00:00', '2026-12-31 23:59:59')
    ->orderBy('total', 'DESC')
    ->limit(10)
    ->get();

Colunas: select()

select()encadeável

$orm->select(array $colunas): $this $orm->select(string $coluna1, string $coluna2, ...): $this

Define as colunas do SELECT. Sem select(), busca todas (*). Chamadas seguidas acumulam colunas.

->select(['id', 'nome', 'preco'])
->select('id', 'nome')                              // mesma coisa
->select(['p.nome', 'COUNT(i.id) AS itens'])        // expressões e alias

Os itens vão para o SQL sem escape, para permitir expressões. Nunca coloque dados do usuário aqui.

Filtros: where()

where() / orWhere()encadeável

$orm->where(string $coluna, mixed $valor): $this $orm->where(string $coluna, string $operador, mixed $valor): $this $orm->orWhere(...mesmos parâmetros...): $this

Compara uma coluna com um valor. Com dois parâmetros, o operador é =. O valor é sempre escapado.

->where('status', 'pago')                 // status = 'pago'
->where('total', '>', 100)                // total > '100'
->where('status', '!=', 'cancelado')      // status != 'cancelado'
->orWhere('prioridade', 1)                // OR prioridade = '1'

->where('ativo', true)                    // ativo = '1'
->where('ativo', false)                   // ativo = '0'

->where('deleted_at', null)               // deleted_at IS NULL
->where('aprovado_em', '!=', null)        // aprovado_em IS NOT NULL
Operadores aceitosCom null
= != <> > < >= <== vira IS NULL; != e <> viram IS NOT NULL; os outros lançam InvalidArgumentException.

Qualquer outro operador (LIKE, IN…) lança InvalidArgumentException. Use os métodos próprios: whereLike, whereIn.

AND, OR e parênteses

Os filtros são unidos na ordem em que são chamados: where adiciona com AND, orWhere com OR. Como no SQL, AND tem precedência sobre OR:

->where('ativo', 1)->where('estoque', 0)->orWhere('preco', 0)
// ativo = 1 AND estoque = 0 OR preco = 0
// = (ativo = 1 AND estoque = 0) OR preco = 0   ← inclui produtos INATIVOS com preço 0

Para agrupar do jeito certo, use whereGroup(). O conjunto dos seus filtros é sempre colocado entre parênteses, então o filtro automático de softDeletes nunca se mistura com os seus OR.

Outros filtros

whereIn() / orWhereIn() / whereNotIn()encadeável

$orm->whereIn(string $coluna, array $valores): $this $orm->orWhereIn(string $coluna, array $valores): $this $orm->whereNotIn(string $coluna, array $valores): $this

A coluna está (ou não está) na lista.

->whereIn('status', ['aberto', 'pago'])     // status IN ('aberto','pago')
->whereNotIn('id', [3, 7])                  // id NOT IN ('3','7')

Lista vazia é tratada com segurança: whereIn('id', []) não encontra nada (1 = 0) e whereNotIn('id', []) não filtra nada (1 = 1).

whereNull() / orWhereNull() / whereNotNull()encadeável

$orm->whereNull(string $coluna): $this $orm->orWhereNull(string $coluna): $this $orm->whereNotNull(string $coluna): $this

Coluna vazia (IS NULL) ou preenchida (IS NOT NULL).

->whereNull('pago_em')            // ainda não pagos
->whereNotNull('enviado_em')      // já enviados

whereBetween()encadeável

$orm->whereBetween(string $coluna, mixed $inicio, mixed $fim): $this

Valor entre dois limites, inclusive.

->whereBetween('total', 100, 500)
->whereBetween('created_at', '2026-10-01 00:00:00', '2026-10-31 23:59:59')

whereLike() / orWhereLike()encadeável

$orm->whereLike(string $coluna, string $texto): $this $orm->orWhereLike(string $coluna, string $texto): $this

A coluna contém o texto (LIKE '%texto%'). Os caracteres % e _ digitados pelo usuário são tratados como texto comum. No PostgreSQL vira ILIKE, sem diferenciar maiúsculas, como no MySQL.

->whereLike('nome', 'caneta')       // nome LIKE '%caneta%'
->whereLike('codigo', '50%')        // procura literalmente "50%"

whereRaw()encadeável

$orm->whereRaw(string $sql): $this

Condição em SQL puro, para o que os outros métodos não cobrem. Entra com AND.

->whereRaw('estoque < estoque_minimo')
->whereRaw('YEAR(created_at) = 2026')           // só MySQL

O SQL vai como está. Nunca concatene dados do usuário. Ele também não é adaptado entre MySQL e PostgreSQL: funções como YEAR() só existem no MySQL.

Grupos e filtros condicionais

whereGroup() / orWhereGroup()encadeável

$orm->whereGroup(callable $callback): $this $orm->orWhereGroup(callable $callback): $this

Coloca as condições criadas dentro do callback entre parênteses. O callback recebe a própria instância. Grupos podem conter outros grupos.

// ativo = 1 AND (estoque <= 5 OR preco <= 0)
->where('ativo', 1)
->whereGroup(function ($q) {
    $q->where('estoque', '<=', 5)
      ->orWhere('preco', '<=', 0);
})

// status = 'pago' OR (status = 'aberto' AND total > 1000)
->where('status', 'pago')
->orWhereGroup(function ($q) {
    $q->where('status', 'aberto')
      ->where('total', '>', 1000);
})

// Busca em várias colunas
->whereGroup(function ($q) use ($termo) {
    $q->whereLike('nome', $termo)
      ->orWhereLike('email', $termo)
      ->orWhereLike('documento', $termo);
})

Dentro do callback, use apenas métodos where*. Um grupo vazio é ignorado.

when()encadeável

$orm->when(mixed $valor, callable $callback, callable|null $senao = null): $this

Aplica $callback só se $valor for verdadeiro; senão, aplica $senao (se houver). O callback recebe a instância e o valor. Ideal para filtros opcionais vindos da tela, sem quebrar a cadeia com if.

$resultado = OrmTables::table('#__loja_pedidos')
    ->when($filtros['status'], function ($q, $status) {
        $q->where('status', $status);
    })
    ->when($filtros['de'], function ($q, $de) {
        $q->where('created_at', '>=', $de);
    })
    ->when($filtros['ordenar_por_total'], function ($q) {
        $q->orderBy('total', 'DESC');
    }, function ($q) {
        $q->latest();                               // senão: mais recentes
    })
    ->paginate(20, $pagina);

"Verdadeiro" segue as regras do PHP: 0, '0', '', null e [] contam como falso. Para um filtro em que 0 é válido, use uma condição explícita: when($valor !== '', …), e use $valor com use dentro do callback.

Joins

join() e atalhosencadeável

$orm->join(string $tabela, string|null $condicao = null, string $tipo = 'INNER'): $this $orm->innerJoin(string $tabela, string $condicao): $this $orm->leftJoin(string $tabela, string $condicao): $this $orm->leftOuterJoin(string $tabela, string $condicao): $this $orm->rightJoin(string $tabela, string $condicao): $this $orm->rightOuterJoin(string $tabela, string $condicao): $this $orm->crossJoin(string $tabela): $this

Junta outra tabela. Use alias nas duas tabelas e prefixe as colunas com o alias em select, where e orderBy.

$itens = OrmTables::table('#__loja_pedido_itens AS i')
    ->select(['i.quantidade', 'i.preco_unitario', 'p.nome AS produto'])
    ->innerJoin('#__loja_produtos AS p', 'p.id = i.produto_id')
    ->leftJoin('#__loja_categorias AS c', 'c.id = p.categoria_id')
    ->where('i.pedido_id', $pedidoId)
    ->orderBy('p.nome')
    ->get();
RegraDetalhe
Tipos aceitosINNER, LEFT, LEFT OUTER, RIGHT, RIGHT OUTER, CROSS (também com o sufixo JOIN).
CondiçãoObrigatória, exceto em CROSS. É SQL cru: escreva só texto fixo.
FULL OUTER JOINNão suportado: lança RuntimeException.
Soft deleteO filtro deleted_at IS NULL usa a coluna sem prefixo. Se a outra tabela também tiver deleted_at, a coluna fica ambígua. Nesse caso, use uma instância sem softDeletes e filtre com whereNull('i.deleted_at').

Ordenação, agrupamento e limite

orderBy() / latest() / oldest()encadeável

$orm->orderBy(string $coluna, string $direcao = 'ASC'): $this $orm->latest(string|null $coluna = null): $this $orm->oldest(string|null $coluna = null): $this

Ordena o resultado. Qualquer direção diferente de DESC vira ASC. latest() e oldest() ordenam por created_at (ou pela coluna informada), decrescente e crescente.

->orderBy('nome')                    // ASC
->orderBy('total', 'desc')           // DESC
->latest()                           // created_at DESC
->latest('pago_em')                  // pago_em DESC

groupBy() / having()encadeável

$orm->groupBy(string $coluna): $this $orm->having(string $sql): $this

Agrupamento. having() recebe SQL cru.

$porStatus = OrmTables::table('#__loja_pedidos')
    ->select(['status', 'COUNT(*) AS quantidade', 'SUM(total) AS valor'])
    ->groupBy('status')
    ->having('COUNT(*) > 10')
    ->get();

No PostgreSQL, toda coluna do select que não é agregada precisa estar no groupBy.

limit()encadeável

$orm->limit(int $quantidade, int $offset = 0): $this

Quantidade máxima de linhas e quantas pular. Para páginas, prefira paginate().

->limit(10)          // 10 primeiros
->limit(10, 20)      // 10 linhas, pulando 20 (3ª página de 10)

Trava de linhas: lockForUpdate()

lockForUpdate()encadeável

$orm->lockForUpdate(): $this

Gera SELECT … FOR UPDATE: as linhas lidas ficam travadas até o fim da transação. Outra transação que tente travar ou alterar essas linhas espera. É o jeito correto de fazer "ler, conferir, gravar" sem que dois usuários ao mesmo tempo leiam o mesmo valor.

DbTransactionHelper::run(function () use ($produtoId, $quantidade) {
    $produtos = OrmTables::table('#__loja_produtos');

    $produto = $produtos->where('id', $produtoId)->lockForUpdate()->first();

    if ($produto === null || $produto->estoque < $quantidade) {
        throw new RuntimeException('Estoque insuficiente.');
    }

    // Ninguém altera este produto entre a leitura acima e esta linha
    $produtos->decrement($produtoId, 'estoque', $quantidade);
});
RegraPor quê
Só dentro de uma transação da mesma conexão; fora dela, lança LogicException.Sem transação, a trava seria liberada no mesmo instante.
Funciona com get, first, value, pluck, exists.
Com count, sum, avg, min, max, lança LogicException.O PostgreSQL não aceita FOR UPDATE com agregação. Trave com get() e calcule no PHP.
Vale só para a próxima consulta.É limpo junto com os outros filtros.
