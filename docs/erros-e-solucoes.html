Erros e soluções

O que significa cada mensagem de erro, por que aparece e como resolver.

As mensagens abaixo são as que os helpers produzem, ou as mais comuns do banco ao usá-los. Use Ctrl+F com um trecho da mensagem que você recebeu.

Mensagens de erro

A tabela deve ser informada ao instanciar …

Causa: Instância criada sem tabela: new OrmBase(), OrmBase::query() direto, ou um model sem protected $table.

Solução: Informe a tabela no parâmetro ou declare $table no model. query() só funciona em models.

Conexão de banco não registrada: "…"

Causa: Uso de connection => 'nome' (ou $connection no model) antes de DbConnectionHelper::register().

Solução: Registre a conexão no carregamento do componente, antes de qualquer consulta. Confira se o nome está escrito igual nos dois lugares.

Operador de comparação inválido: LIKE

Causa: where() aceita só =, !=, <>, >, <, >=, <=.

Solução: Use o método próprio: whereLike(), whereIn(), whereNull(), whereBetween().

// Errado
->where('nome', 'LIKE', '%ana%')
// Certo
->whereLike('nome', 'ana')

O operador > não pode ser usado com null.

Causa: Comparação de ordem com null (where('total', '>', null)), que não tem significado em SQL.

Solução: Verifique o valor antes, ou use when() para só filtrar quando houver valor.

Operação deleteWhere sem where na tabela … atingiria todos os registros.

Causa: updateWhere() ou deleteWhere() sem nenhum filtro. Às vezes acontece porque um when() não aplicou o filtro esperado.

Solução: Adicione o filtro. Se a intenção é mesmo a tabela inteira, chame allowMassOperation() antes.

lockForUpdate() só tem efeito dentro de uma transação.

Causa: A consulta com trava rodou fora de DbTransactionHelper::run(), ou dentro de uma transação de outra conexão.

Solução: Coloque a leitura e a gravação dentro de run(), na mesma conexão da consulta: ['connection' => 'erp'] se a tabela for do ERP.

lockForUpdate() não pode ser usado com count().

Causa: Trava combinada com count, sum, avg, min ou max, o que o PostgreSQL não aceita.

Solução: Trave as linhas com get() e calcule no PHP, por exemplo com count($linhas).

Erro ao criar registro na tabela …: Unknown column 'created_at'

Causa: A tabela não tem created_at/updated_at, e timestamps vem ligado por padrão. No PostgreSQL a mensagem é column "created_at" … does not exist.

Solução: Passe ['timestamps' => false], ou informe os nomes certos em createdAtColumn/updatedAtColumn.

Registro não encontrado na tabela … para o ID …

Causa: findOrFail() não encontrou o id. O código da exceção é 404. Com softDeletes, registros excluídos também contam como não encontrados.

Solução: Trate o código 404 e responda "não encontrado".

current transaction is aborted, commands ignored until end of transaction block

Causa: PostgreSQL: um comando falhou dentro da transação, você capturou a exceção e continuou usando a mesma transação.

Solução: Coloque o trecho que pode falhar num DbTransactionHelper::run() aninhado (savepoint). Veja o guia de PostgreSQL.

FULL OUTER JOIN não é suportado nativamente pelo MySQL/MariaDB.

Causa: Uso de join(…, 'FULL').

Solução: Faça duas consultas (leftJoin e rightJoin) e combine os resultados no PHP.

A condição ON é obrigatória para JOIN do tipo …

Causa: Join sem condição, exceto CROSS.

Solução: Informe a condição: leftJoin('#__x AS x', 'x.id = t.x_id').

Para truncar a tabela, informe true como confirmação explícita.

Causa: truncate() chamado sem argumento.

Solução: Use truncate(true), se tiver certeza.

Nome de tabela inválido para truncamento.

Causa: Tabela com alias ('#__x AS x') ou caracteres fora de letras, números, _ e ..

Solução: Use uma instância com o nome simples da tabela.

Não existe transação ativa para confirmar.

Causa: DbTransactionHelper::commit() sem begin(). Essa mensagem vai para o log; commit() devolve false.

Solução: Prefira run(). No controle manual, confira o retorno de begin().

Quantidade de tentativas inválida.

Causa: setMaxRetries() com valor fora de 0 a 10.

Solução: Use um valor entre 0 e 10.

Comportamentos inesperados (sem mensagem de erro)

Um campo não é gravado, e não aparece erro

Causa: A coluna foi descartada em silêncio: nome digitado errado, coluna ausente em fillable, presente em guarded, ou inexistente na tabela.

Solução: Confira o nome exato da coluna e as listas fillable/guarded.

O filtro foi ignorado no find()

Causa: find(), findBy(), all(), firstOrCreate() e updateOrCreate() descartam os filtros montados antes.

Solução: Use where('id', $id)->where(…)->first(). Veja o ciclo da consulta.

Os filtros "sumiram" na segunda consulta

Causa: É o comportamento esperado: todo método final limpa os filtros.

Solução: Monte os filtros de novo, ou use clone numa consulta base.

Os números vêm como texto ("2.50")

Causa: O banco devolve strings. Sem casts, o ORM não converte.

Solução: Declare casts: ['preco' => 'float', 'estoque' => 'int']. Lembre que value(), pluck() e os agregados não aplicam casts.

create/update falham com tabela "AS x"

Causa: Alias no nome da tabela só funciona em consultas.

Solução: Use uma instância com o nome sem alias para gravar.

O catch da minha exceção não pega

Causa: $orm->transaction() e os métodos de gravação embrulham exceções numa RuntimeException.

Solução: Use DbTransactionHelper::run(), que relança a exceção original, ou inspecione $e->getPrevious().

Uma ação aconteceu duas vezes (e-mail duplicado, chamada de API repetida)

Causa: O callback de run() foi repetido após um deadlock.

Solução: Deixe dentro de run() apenas operações de banco e faça os efeitos externos depois. Ou use ['retries' => 0].

Os logs de transação não aparecem

Causa: As mensagens de início e commit são nível debug. Talvez o seu log descarte esse nível.

Solução: Confira o nível mínimo do LogHelper/JLog e a categoria (db_transaction por padrão).

Limitações conhecidas

Comportamentos atuais que exigem atenção, com a alternativa recomendada:

  • Chave primária não inteira: find, update, delete, increment… convertem o id para inteiro. Para UUID ou códigos texto, use where('chave', $valor) com first(), updateWhere() e deleteWhere().
  • timestamps ligado por padrão e sem verificar se as colunas existem. Desligue em tabelas sem essas colunas.
  • value() e pluck() com select(): a coluna é acrescentada às já selecionadas. Não combine os dois.
  • count() com groupBy() devolve a contagem do primeiro grupo. Para contar por grupo, use select(… COUNT(*) …)->groupBy()->get().
  • Soft delete com join: o filtro deleted_at IS NULL usa a coluna sem prefixo e fica ambíguo se a outra tabela também tiver deleted_at.
  • Datas automáticas usam o fuso horário do PHP (date()).
  • Colunas da tabela são consultadas uma vez por instância. Com OrmTables::table() em laço, isso acontece a cada iteração: crie a instância fora do laço.
// Melhor: uma instância, colunas lidas uma vez
$itens = OrmTables::table('#__loja_pedido_itens', ['timestamps' => false]);

foreach ($linhas as $linha) {
    $itens->create($linha);
}
