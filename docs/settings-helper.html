SettingsHelper

Lê as configurações do componente (Opções / config.xml) já no tipo certo e com padrão, em vez de JComponentHelper::getParams() espalhado; avisa o que falta configurar, guarda segredos cifrados e grava valores pelo código.

Visão geral

require_once JPATH_COMPONENT . '/helpers/SettingsHelper.php';

$limiteMb = SettingsHelper::int('limite_upload_mb', 10);
$pixAtivo = SettingsHelper::bool('pix_ativo');
$taxa = SettingsHelper::float('taxa_cartao', 0);              // aceita '2,5'
$copias = SettingsHelper::array('emails_copia');              // campo múltiplo, JSON ou "a@x.com, b@x.com"
$ambiente = SettingsHelper::oneOf('ambiente', array('producao', 'sandbox'), 'sandbox');
$token = SettingsHelper::secret('erp_token');                 // decifra se estiver cifrado

SettingsHelper::requireKeys(array('erp_url', 'erp_token'));   // RuntimeException: "Configure em Opções do componente: erp_token."
  • Tipo e padrão em um lugar: o rádio Sim/Não do Joomla grava '1'/'0'; um número vem como texto; um campo nunca salvo vem null. Os métodos tipados resolvem tudo isso e usam o padrão quando o valor está ausente ou vazio.
  • Componente da requisição: sem informar, usa o option atual. Em CLI, plugins e módulos: SettingsHelper::setComponent('com_loja') ou o último argumento de cada método.
  • Campos aninhados (subform): SettingsHelper::string('smtp.host').

Métodos

MétodoDevolve
get($chave, $padrao = null, $componente = null)valor cru (padrão se ausente ou vazio)
string($chave, $padrao = '')texto aparado
int($chave, $padrao = 0) / float($chave, $padrao = 0.0)número (padrão se não for número)

Segredos (tokens, senhas de integração)

Tudo que está nas Opções do componente fica em texto puro no banco (#__extensions.params) e aparece em backups. Para tokens de API e senhas de integração, grave cifrado:

// Task do administrador que salva o token (ex.: após o OAuth do ERP)
if (!PermissionHelper::requireToken() || !PermissionHelper::require('core.admin')) {
    return;
}

SettingsHelper::set('erp_token', $tokenRecebido, true);   // cifra com CryptoHelper (contexto 'settings.erp_token')

// Em qualquer lugar
$token = SettingsHelper::secret('erp_token');

Um campo type="password" no config.xml só esconde o valor na tela; o Joomla grava em claro. Se o administrador digita o segredo pela tela de Opções, cifre num evento de salvar ou ofereça uma tela própria que use set(..., true).

O config.xml

administrator/components/com_loja/config.xml
<config>
    <fieldset name="integracao" label="Integração">
        <field name="erp_url" type="url" label="URL do ERP" filter="url" />
        <field name="limite_upload_mb" type="number" label="Limite de upload (MB)" default="10" min="1" max="200" />
        <field name="pix_ativo" type="radio" label="PIX ativo" default="0" layout="joomla.form.field.radio.switcher">
            <option value="0">JNO</option>
            <option value="1">JYES</option>
        </field>
        <field name="emails_copia" type="textarea" label="E-mails em cópia" description="Um por linha" />
        <field name="ambiente" type="list" label="Ambiente" default="sandbox">
            <option value="sandbox">Sandbox</option>
            <option value="producao">Produção</option>
        </field>
    </fieldset>
</config>

O default do XML só vale depois que o administrador salva as Opções pela primeira vez. Repita o padrão no código (SettingsHelper::int('limite_upload_mb', 10)) para o componente funcionar antes disso.

Testes e homologação

SettingsHelper::override('ambiente', 'sandbox');     // só nesta execução
SettingsHelper::override('pix_ativo', '1');
// ... roda o teste
SettingsHelper::override('ambiente', null);
