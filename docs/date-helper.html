DateHelper

Datas e fuso horário: grave em UTC, mostre no fuso do usuário e monte períodos de relatório sem errar as horas.

Visão geral

O Joomla segue uma regra simples: o banco guarda UTC e a tela mostra no fuso do usuário (o campo "Fuso horário" do perfil ou, se vazio, o da configuração global). O DateHelper concentra as conversões entre os dois lados, para que nenhum trecho do código precise lembrar dessa regra.

// Gravar: sempre UTC
$dados['pago_em'] = DateHelper::nowSql();                 // '2026-10-05 02:30:00'

// Mostrar: no fuso do usuário
echo DateHelper::toUser($pedido->created_at);             // '04/10/2026 23:30'

// O que o usuário digitou (no fuso dele) -> UTC para gravar
$entrega = DateHelper::fromUser('25/12/2026 14:30');      // '2026-12-25 17:30:00'

// Período de relatório: "este mês" do usuário, em UTC, pronto para o where
$mes = DateHelper::range('month');
$total = PedidoModel::query()->whereBetween('created_at', $mes['start'], $mes['end'])->sum('total');

Os exemplos desta página consideram um usuário em São Paulo (UTC−3) e o "agora" em 2026-10-05 02:30:00 UTC, que é 04/10/2026 23:30 para ele.

Por que não usar date()

date('Y-m-d H:i:s') usa o fuso configurado no PHP do servidor (date.timezone), que pode ser diferente entre o site e o cron, entre o servidor de testes e o de produção, e quase nunca é o fuso do usuário. O resultado são os bugs clássicos:

  • registros gravados com 3 horas de diferença de outros (ex.: o created_at do pedido e o log de auditoria da mesma operação);
  • o relatório "de hoje" que perde as vendas das 21h às 23h59, porque o filtro BETWEEN '2026-10-04 00:00:00' AND '2026-10-04 23:59:59' foi montado sem converter para UTC;
  • um job agendado "para amanhã às 8h" que roda às 5h ou às 11h.

Os helpers deste repositório gravam datas em UTC. O OrmBase (timestamps e soft delete) e o QueueHelper usam o DateHelper. O scripts/checar.sh da skill avisa quando encontra date('Y-m-d H:i:s') no seu código.

Carregar

require_once JPATH_COMPONENT . '/helpers/DateHelper.php';

// ou, com o IncludeHelper
IncludeHelper::load('DateHelper');
IncludeHelper::registerAutoloader();   // ou carregamento automático no primeiro uso

Não depende de nenhum outro helper. OrmBase e QueueHelper o carregam sozinhos.

Datas aceitas

Todo método que recebe uma data aceita qualquer um destes formatos:

EntradaExemploObservação
Formato do banco'2026-10-05 02:30:00'também sem segundos: '2026-10-05 02:30'
Só a data'2026-10-05'hora 00:00:00
Input datetime-local'2026-10-05T14:30'com ou sem segundos
Brasileiro'05/10/2026', '05/10/2026 14:30'sempre dia/mês/ano; nunca lido como mês/dia
ISO 8601 com fuso'2026-10-05T02:30:00Z', '2026-10-04T23:30:00-03:00'o fuso do texto vale; o parâmetro $timezone é ignorado
Timestamp Unix1791167400 ou '1791167400'texto só com dígitos a partir de 9 caracteres
ObjetoDateTime, DateTimeImmutableo instante é preservado
Relativo'now', 'today', '+30 minutes', '-7 days', 'first day of next month'calculado a partir de agora, no fuso informado; recusado por fromUser() e between()

Datas impossíveis são recusadas, nunca "ajustadas": 31/02/2026 lança InvalidArgumentException em vez de virar 03/03/2026, como faria o PHP.

Vazio é null, '', '0000-00-00' ou '0000-00-00 00:00:00' (a "data nula" do Joomla 3 no MySQL). Os métodos de conversão devolvem null ou '' para vazio, em vez de lançar, para que colunas opcionais não precisem de if.

Fusos horários

Os parâmetros $timezone aceitam:

ValorSignificado
'UTC'UTC, o fuso do banco.
'user'O fuso do usuário atual (veja a ordem abaixo).
nome IANA, ex.: 'America/Sao_Paulo'Esse fuso. Nome inválido lança InvalidArgumentException.
DateTimeZoneEsse objeto.

O fuso do usuário ('user') é escolhido nesta ordem:

  1. o fixado com setUserTimezone(), se houver;
  2. o do perfil do usuário logado (parâmetro timezone);
  3. o da configuração global do Joomla (offset, em Sistema → Configuração → Servidor);
  4. UTC.

Um fuso inválido num nível passa para o seguinte. Funciona no Joomla 3 (JFactory::getUser()) e no 4/5 (getApplication()->getIdentity()). Sem Joomla carregado, o resultado é UTC.

Horário de verão é tratado sozinho: as conversões usam a tabela de fusos do PHP, então datas antigas de São Paulo (que tinha horário de verão até 2019) convertem com a diferença correta da época.

Métodos: agora

now()estático

DateHelper::now(): DateTimeImmutable

Momento atual em UTC, como objeto imutável. Use quando precisar de cálculos com a API do PHP.

Retorna: DateTimeImmutable em UTC.

$prazo = DateHelper::now()->modify('+15 days')->format(DateHelper::SQL);

nowSql()estático

DateHelper::nowSql(): string

Momento atual em UTC no formato do banco. É o que você usa para gravar.

Retorna: 'Y-m-d H:i:s' em UTC.

PedidoModel::query()->update($id, [
    'status' => 'pago',
    'pago_em' => DateHelper::nowSql(),
]);

today()estático

DateHelper::today(string|DateTimeZone $timezone = 'user'): string

Data de hoje ('Y-m-d') no fuso informado. Às 23:30 de São Paulo, o "hoje" do usuário ainda é dia 4, mesmo que em UTC já seja dia 5.

DateHelper::today();        // '2026-10-04' (usuário)
DateHelper::today('UTC');   // '2026-10-05'

setTestNow()estático

DateHelper::setTestNow(mixed $value = null): void

Congela o relógio do helper em $value (interpretado como UTC). Todos os métodos passam a considerar esse "agora", inclusive o OrmBase e o QueueHelper. null volta ao relógio real.

// Teste: o job agendado para "amanhã" ainda não deve sair hoje
DateHelper::setTestNow('2026-10-05 02:30:00');
// ...
DateHelper::setTestNow(null);

Use só em testes e scripts. Esquecer o relógio congelado em produção faz todas as datas gravadas ficarem iguais.

Métodos: converter e formatar

toSql()estático

DateHelper::toSql(mixed $value = 'now', string|DateTimeZone $timezone = 'UTC'): string|null

Converte uma data para o formato do banco, em UTC. $timezone é o fuso em que $value foi escrito.

ParâmetroTipoDescrição
$valuemixedQualquer entrada aceita, inclusive relativa.
$timezonestring|DateTimeZoneFuso do texto. Padrão UTC.

Retorna: 'Y-m-d H:i:s' em UTC, ou null se $value for vazio.

DateHelper::toSql();                                // agora
DateHelper::toSql('+30 minutes');                   // daqui a 30 minutos
DateHelper::toSql('today', 'user');                 // meia-noite de hoje do usuário: '2026-10-04 03:00:00'
DateHelper::toSql('2026-12-25 08:00', 'America/Sao_Paulo');   // '2026-12-25 11:00:00'
DateHelper::toSql('2026-10-04T23:30:00-03:00');     // '2026-10-05 02:30:00' (fuso do texto)
DateHelper::toSql($linha->data_opcional);           // null se vazio

fromUser()estático

DateHelper::fromUser(mixed $value, string|null $format = null): string|null

Converte o que o usuário digitou, no fuso dele, para UTC. Sem $format, aceita os formatos fixos (não aceita relativos como 'tomorrow', que não fazem sentido vindo de um formulário). Com $format, exige exatamente esse formato.

ParâmetroTipoDescrição
$valuemixedTexto do formulário.
$formatstring|nullFormato exigido, ex.: 'd/m/Y H:i'.

Retorna: 'Y-m-d H:i:s' em UTC, ou null se vazio. Data inválida lança InvalidArgumentException.

DateHelper::fromUser('25/12/2026 14:30');           // '2026-12-25 17:30:00'
DateHelper::fromUser('2026-12-25T14:30');           // input datetime-local: '2026-12-25 17:30:00'
DateHelper::fromUser('25/12/2026');                 // '2026-12-25 03:00:00' (meia-noite dele)
DateHelper::fromUser('12-25-2026', 'm-d-Y');        // formato próprio
DateHelper::fromUser('');                           // null
DateHelper::fromUser('31/02/2026');                 // InvalidArgumentException

toUser()estático

DateHelper::toUser(mixed $value, string $format = DateHelper::BR_DATETIME): string

Formata uma data gravada em UTC no fuso do usuário. É o que você usa nas views e nas respostas para a tela.

Retorna: Texto formatado, ou '' se vazio.

echo DateHelper::toUser($pedido->created_at);                      // '04/10/2026 23:30'
echo DateHelper::toUser($pedido->created_at, DateHelper::BR);      // '04/10/2026'
echo DateHelper::toUser($pedido->cancelado_em);                    // '' se a coluna for NULL

// Preencher um input datetime-local para edição
<input type="datetime-local" name="entrega"
       value="<?php echo DateHelper::toUser($pedido->entrega_em, 'Y-m-d\TH:i'); ?>">

format()estático

DateHelper::format(mixed $value, string $format = DateHelper::BR_DATETIME, string|DateTimeZone $timezone = 'user'): string

Igual a toUser(), mas num fuso que você escolhe. $value é interpretado como UTC.

// Horário da filial de Manaus, independente de quem está vendo
echo DateHelper::format($pedido->created_at, DateHelper::BR_DATETIME, 'America/Manaus');   // '04/10/2026 22:30'

// Data para uma API externa, em ISO 8601 UTC
$payload['data'] = DateHelper::format($pedido->created_at, DateHelper::ISO, 'UTC');       // '2026-10-05T02:30:00+00:00'

longDate()estático

DateHelper::longDate(mixed $value, bool $withTime = false, bool $withWeekday = false, string|DateTimeZone $timezone = 'user'): string

Data por extenso em português, sem depender do setlocale do servidor. Útil em contratos, recibos e e-mails.

DateHelper::longDate($pedido->created_at);               // '4 de outubro de 2026'
DateHelper::longDate($pedido->created_at, true);         // '4 de outubro de 2026 às 23:30'
DateHelper::longDate($pedido->created_at, true, true);   // 'domingo, 4 de outubro de 2026 às 23:30'

parse()estático

DateHelper::parse(mixed $value, string|DateTimeZone $timezone = 'UTC', bool $allowRelative = true): DateTimeImmutable

A base dos outros métodos: interpreta $value no fuso $timezone e devolve o mesmo instante em UTC. Use quando quiser o objeto para cálculos próprios.

Retorna: DateTimeImmutable em UTC. Vazio ou inválido lança InvalidArgumentException.

$inicio = DateHelper::parse($evento->inicio);                       // UTC
$local = $inicio->setTimezone(DateHelper::userTimezone());         // fuso do usuário
$fimDoEvento = $inicio->modify('+2 hours');

timestamp()estático

DateHelper::timestamp(mixed $value = 'now'): int

Timestamp Unix do instante.

$expiraEm = DateHelper::timestamp($token->expira_em);

Métodos: validar e comparar

isValid()estático

DateHelper::isValid(mixed $value, string|null $format = null): bool

Indica se $value é uma data válida nos formatos fixos ou, com $format, exatamente nesse formato. Vazio é inválido. Não lança.

DateHelper::isValid('29/02/2024');             // true (ano bissexto)
DateHelper::isValid('29/02/2026');             // false
DateHelper::isValid('2026-10-05', 'Y-m-d');    // true

isEmpty()estático

DateHelper::isEmpty(mixed $value): bool

Indica se o valor conta como "sem data": null, false, '', '0000-00-00' ou '0000-00-00 00:00:00'.

if (DateHelper::isEmpty($artigo->publish_down)) {
    // sem data de expiração
}

isPast() / isFuture()estático

DateHelper::isPast(mixed $value): bool DateHelper::isFuture(mixed $value): bool

Compara com agora. Datas sem fuso são lidas como UTC (o que vem do banco).

if (DateHelper::isPast($cupom->valido_ate)) {
    return ApiResponseHelper::error('Cupom expirado.');
}

diffInSeconds()estático

DateHelper::diffInSeconds(mixed $from, mixed $to = 'now'): int

Segundos de $from até $to: positivo se $to for depois.

$segundosParado = DateHelper::diffInSeconds($job->heartbeat_em);   // até agora

diffInDays()estático

DateHelper::diffInDays(mixed $from, mixed $to = 'now', string|DateTimeZone $timezone = 'user'): int

Dias de calendário entre as datas, contados no fuso informado. Ignora as horas: de 23:00 de um dia a 01:00 do dia seguinte é 1 dia. É o que o usuário espera em "vence em 3 dias" ou "atrasado há 2 dias".

$dias = DateHelper::diffInDays('now', $boleto->vencimento);
echo $dias >= 0 ? "Vence em {$dias} dia(s)" : 'Atrasado há ' . abs($dias) . ' dia(s)';

relative()estático

DateHelper::relative(mixed $value, mixed $reference = 'now'): string

Texto relativo em português: agora (menos de 45 segundos), há 5 minutos, em 3 dias, há 2 meses, há 1 ano.

echo DateHelper::relative($comentario->created_at);   // 'há 5 minutos'
echo DateHelper::relative($evento->inicio);           // 'em 3 dias'

Métodos: períodos para filtros e relatórios

Os três métodos devolvem ['start' => ..., 'end' => ...] em UTC, no formato do banco e inclusivos (o fim é 23:59:59 no fuso do usuário). Encaixam direto no whereBetween().

range()estático

DateHelper::range(string $period = 'day', mixed $reference = 'now', string|DateTimeZone $timezone = 'user'): array

Início e fim do dia, da semana (segunda a domingo), do mês ou do ano que contém $reference, no fuso informado.

ParâmetroTipoDescrição
$periodstring'day', 'week', 'month' ou 'year'.
$referencemixedUma data dentro do período. Padrão: agora. Só data ('2026-02-10', '10/02/2026') é o dia do calendário; data com hora é um instante em UTC, como vem do banco; relativa ('today', '+30 days') é calculada no fuso do período.
$timezonestring|DateTimeZoneFuso em que o período é contado. Padrão: o do usuário.
$hoje = DateHelper::range('day');
// ['start' => '2026-10-04 03:00:00', 'end' => '2026-10-05 02:59:59']

$vendasHoje = PedidoModel::query()->pagos()
    ->whereBetween('created_at', $hoje['start'], $hoje['end'])
    ->sum('total');

DateHelper::range('week');                    // segunda a domingo desta semana
DateHelper::range('month', '2026-02-10');     // fevereiro de 2026
DateHelper::range('year');                    // ano atual
DateHelper::range('day', $pedido->created_at); // o dia (do usuário) em que o pedido foi feito

lastDays()estático

DateHelper::lastDays(int $days, mixed $reference = 'now', string|DateTimeZone $timezone = 'user'): array

Os últimos $days dias contando hoje: lastDays(7) é hoje e os 6 dias anteriores, inteiros. $reference segue a mesma regra de range().

$semana = DateHelper::lastDays(7);
$novos = ClienteModel::query()->whereBetween('created_at', $semana['start'], $semana['end'])->count();

between()estático

DateHelper::between(mixed $from, mixed $to, string|DateTimeZone $timezone = 'user'): array

Intervalo entre duas datas digitadas pelo usuário, como o filtro "de/até" de um relatório: de 00:00:00 de $from a 23:59:59 de $to, no fuso dele. Não aceita textos relativos. Fim antes do início lança InvalidArgumentException.

$de = InputHelper::date('de', DateHelper::today());     // '2026-10-01' (input type="date")
$ate = InputHelper::date('ate', DateHelper::today());

$periodo = DateHelper::between($de, $ate);
// ['start' => '2026-10-01 03:00:00', 'end' => '2026-10-05 02:59:59']

$pedidos = PedidoModel::query()
    ->whereBetween('created_at', $periodo['start'], $periodo['end'])
    ->paginate(20, $pagina);

Métodos: fuso horário

userTimezone()estático

DateHelper::userTimezone(): DateTimeZone

O fuso do usuário atual, escolhido na ordem descrita acima.

echo DateHelper::userTimezone()->getName();   // 'America/Sao_Paulo'

timezoneForUser()estático

DateHelper::timezoneForUser(int $userId): DateTimeZone

O fuso de um usuário específico (perfil, senão configuração global, senão UTC). Para quando o código roda fora da sessão dele, como no worker da fila.

// Job que envia o resumo do pedido por e-mail
$fuso = DateHelper::timezoneForUser($payload['usuario_id']);
$quando = DateHelper::format($pedido->created_at, DateHelper::BR_DATETIME, $fuso);

setUserTimezone()estático

DateHelper::setUserTimezone(string|DateTimeZone|null $timezone = null): void

Fixa o fuso usado como 'user' até ser chamado de novo. null volta ao automático. Útil no worker CLI, onde não há usuário logado, e em testes.

DateHelper::setUserTimezone(DateHelper::timezoneForUser($job->usuario_id));
try {
    // toUser(), range() etc. usam o fuso do dono do job
} finally {
    DateHelper::setUserTimezone(null);
}

timezone()estático

DateHelper::timezone(string|DateTimeZone $timezone = 'user'): DateTimeZone

Converte 'UTC', 'user', um nome de fuso ou um DateTimeZone em DateTimeZone. Nome inválido lança InvalidArgumentException.

$fuso = DateHelper::timezone($params->get('fuso_filial', 'user'));

Receitas

Formulário com data e hora

Controller
// Salvar: o usuário digitou no fuso dele
$entrega = InputHelper::string('entrega', '', 'post');     // '2026-12-25T14:30' (datetime-local)

try {
    $dados['entrega_em'] = DateHelper::fromUser($entrega);   // null se vazio
} catch (InvalidArgumentException $e) {
    return ApiResponseHelper::error('Data de entrega inválida.', 422);
}

PedidoModel::query()->update($id, $dados);

// Editar: devolver no formato do input
$valor = DateHelper::toUser($pedido->entrega_em, 'Y-m-d\TH:i');

Lista para a tela (JSON)

$pedidos = PedidoModel::query()->latest()->limit(20)->get();

foreach ($pedidos as $pedido) {
    $pedido->criado_em_texto = DateHelper::toUser($pedido->created_at);   // '04/10/2026 23:30'
    $pedido->criado_ha = DateHelper::relative($pedido->created_at);       // 'há 5 minutos'
}

return ApiResponseHelper::success($pedidos);

Dashboard: hoje, semana e mês

$totais = [];

foreach (['day' => 'hoje', 'week' => 'semana', 'month' => 'mes'] as $periodo => $chave) {
    $r = DateHelper::range($periodo);

    $totais[$chave] = PedidoModel::query()->pagos()
        ->whereBetween('created_at', $r['start'], $r['end'])
        ->sum('total');
}

Agendar um job no horário do usuário

// "Enviar o lembrete amanhã às 8h" do ponto de vista do usuário
$amanha8h = DateHelper::toSql('tomorrow 08:00', 'user');   // '2026-10-05 11:00:00' (UTC)

QueueHelper::push('enviar_lembrete', ['pedido_id' => $id], [
    'disponivel_em' => $amanha8h,
    'usuario_id' => $userId,
]);

Vencimento e prazo

// Prazo de 30 dias a partir de hoje do usuário, até o fim do dia
$fimDoPrazo = DateHelper::range('day', DateHelper::toSql('+30 days', 'user'));
$dados['vence_em'] = $fimDoPrazo['end'];

// Na tela
$dias = DateHelper::diffInDays('now', $boleto->vence_em);
$situacao = $dias < 0 ? 'vencido' : ($dias === 0 ? 'vence hoje' : "vence em {$dias} dia(s)");

Teste com o relógio congelado

DateHelper::setTestNow('2026-12-31 23:59:00');
DateHelper::setUserTimezone('America/Sao_Paulo');

$r = DateHelper::range('year');   // 2026 inteiro no fuso de São Paulo

DateHelper::setTestNow(null);
DateHelper::setUserTimezone(null);

Integração com os outros helpers

HelperUso
OrmBase / OrmTablesTimestamps (created_at, updated_at) e soft delete (deleted_at) gravados com DateHelper::nowSql(), em UTC.
QueueHelperDatas da fila, disponivel_em, purge() e filtros de data usam o DateHelper. Aceitam os mesmos formatos.
InputHelperInputHelper::date() e dateBr() leem a data do formulário ('Y-m-d'); passe o resultado para between() ou fromUser().
AuditHelperJá grava em UTC (JFactory::getDate()), coerente com o restante.
Atualizando de uma versão anterior

Até a versão anterior, o OrmBase gravava os timestamps e o deleted_at com date(), no fuso do PHP do servidor. Se o seu servidor não está em UTC, os registros antigos estão no horário local e os novos em UTC. Para saber, compare um created_at recente com a hora UTC atual. Se precisar alinhar os antigos, converta com um UPDATE único (ex.: MySQL CONVERT_TZ(created_at, 'America/Sao_Paulo', '+00:00')) para os registros anteriores à atualização.

Erros comuns

SintomaCausa e solução
Datas na tela 3 horas adiantadasA data UTC do banco foi impressa direto. Use DateHelper::toUser().
Relatório "de hoje" sem as vendas da noiteO filtro foi montado com a data local sem converter. Use DateHelper::range('day') ou between().
Data gravada 3 horas atrasadaGravou com date() ou gravou o texto do usuário sem converter. Use nowSql() ou fromUser().
InvalidArgumentException: Data inválidaFormato não aceito ou data impossível (31/02). Valide antes com isValid() ou trate a exceção e responda 422.
Tudo em UTC no worker da filaNão há usuário logado no CLI. Use timezoneForUser() ou setUserTimezone().
fromUser('amanhã') recusadofromUser() não aceita textos relativos. Use toSql('tomorrow', 'user').
