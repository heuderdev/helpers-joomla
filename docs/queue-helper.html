QueueHelper

A fila de jobs em banco de dados: enfileire tarefas demoradas, acompanhe o progresso e trate erros com novas tentativas, em MySQL ou PostgreSQL.

Visão geral

O QueueHelper é a fila em si: uma tabela no banco e os métodos para gravar, reservar, concluir e consultar jobs. Para entender o fluxo completo (job, worker, produção), comece pelo guia da fila. Esta página é a referência de cada método.

require_once JPATH_COMPONENT . '/helpers/QueueHelper.php';

// Produtor (controller)
$r = QueueHelper::push('gerar_relatorio', ['mes' => 5, 'ano' => 2026], ['usuario_id' => $userId]);
$uuid = $r['data']['uuid'];

// Consulta
$situacao = QueueHelper::status($uuid, $userId);    // ['success' => true, 'data' => ['status' => 'processing', 'percentual' => 42.5, ...]]

Como os métodos respondem

GrupoMétodosRetornoEm caso de erro
Produtorpush()array success/mensagem/datasuccess = false e o motivo em erro
Workernext()objeto do job ou nullnull
Workerheartbeat(), progress(), complete(), release(), fail()boolfalse
Gestãocancel(), retry()boolfalse
Consultafind(), status(), list(), count(), stats()objeto, array ou númeronull, array vazio ou 0
ManutençãoreleaseExpiredLocks(), purge()quantidade afetada0

Nenhum desses métodos lança exceção: um erro de banco não derruba a tela nem o worker. O motivo da última falha fica em lastError() e no log. As exceções são os set…() de configuração e o createTable(), que lançam InvalidArgumentException/RuntimeException com valores inválidos.

O objeto do job

Configuração

Chame uma vez, antes de usar a fila (por exemplo, no jobs.php que registra os jobs). Valem para o request ou para a execução do worker.

MétodoPadrãoO que define
setTable($tabela)#__queue_jobsTabela da fila. Útil para filas separadas por componente.
setConnection($driverOuNome)banco do JoomlaOutro banco: um driver já criado ou o nome de uma conexão do DbConnectionHelper. null volta ao padrão.
setDefaultQueue($fila)defaultFila usada quando nem o push() nem o JobRegistry indicam uma.
setDefaultMaxAttempts($n)3Tentativas por job (1 a 100).
setDefaultTimeoutSeconds($s)240Tempo máximo de uma execução.
setDefaultRetryAfterSeconds($s)300Tempo sem sinal de vida para considerar o worker morto.
setDefaultRetryDelaySeconds($s)30Espera base entre tentativas (dobra a cada falha).
setMaxRetryDelaySeconds($s)3600Teto da espera entre tentativas.
setLogDirectory($pasta)loggers do JoomlaGrava o log da fila em <pasta>/queue_helper.php. Caminho relativo a JPATH_SITE; não pode sair dele.
setLogCategory($categoria)queue_helperCategoria (e nome do arquivo) do log.

Para ler: getTable(), getDefaultQueue() e getDatabase() (o driver em uso).

O log nunca mostra senhas: chaves com senha, password, token, secret, session, cookie, api_key, cvv… aparecem como ****. O payload gravado na tabela fica intacto, para o job poder usá-lo. Por isso, evite colocar senhas no payload: guarde uma referência (um id) e busque o segredo dentro do job.

Enfileirando

push()estático

QueueHelper::push(string $tipo, array $payload = [], array $opcoes = []): array

Grava um job novo com status pending.

ParâmetroTipoDescrição
$tipostringTipo do job: letras, números, _, . e -, até 150 caracteres.
$payloadarrayDados para o job, gravados em JSON (até 10 MB). Textos precisam estar em UTF-8.
$opcoesarrayVeja a tabela abaixo.

Retorna: array; em data: id, uuid, queue, tipo, status e duplicado.

$r = QueueHelper::push('enviar_email', [
    'para' => 'cliente@exemplo.com',
    'modelo' => 'boas_vindas',
], [
    'prioridade' => 10,
    'delay_seconds' => 300,          // daqui a 5 minutos
    'max_tentativas' => 5,
    'usuario_id' => $userId,
]);

if ($r['success']) {
    echo $r['data']['uuid'];         // '3f2b8c1e-9a4d-4e6f-b1c2-7d8e9f0a1b2c'
} else {
    echo $r['erro'];                 // 'O campo tipo possui caracteres inválidos…'
}
OpçãoPadrãoDescrição
queuedo JobRegistry, senão defaultFila do job.
prioridade0Maior sai primeiro. Com a mesma prioridade, sai o mais antigo.
max_tentativas3Tentativas antes de failed (1 a 100).
timeout_seconds240Tempo máximo de uma execução.
retry_after_seconds300Tempo sem sinal de vida para considerar o worker morto.
delay_seconds0Só fica disponível depois de N segundos.
disponivel_emagoraOu numa data em UTC: '2026-12-01 08:00:00', DateTime ou timestamp.
usuario_id—Dono do job. Permite status(), cancel() e retry() com checagem de dono.
total, progresso0Valores iniciais da barra de progresso.
unicofalsetrue: se já houver job ativo (pendente, em retry ou em processamento) do mesmo tipo e fila com o mesmo payload, não grava outro e devolve o existente com duplicado = true. Com uma lista de chaves (['importacao_id']), compara só essas chaves.

unico evita o clique duplo e o reenvio do formulário. Não é uma trava absoluta: dois push() no mesmo milissegundo ainda podem gravar dois jobs. Se isso não puder acontecer de jeito nenhum, torne o job repetível (veja erros e novas tentativas).

Processando (worker)

O QueueWorker e o AbstractJob já chamam estes métodos por você. Use-os diretamente só para escrever um consumidor próprio.

next()estático

QueueHelper::next(array $tipos = [], string|null $fila = null, array $opcoes = []): object|null

Reserva o próximo job disponível e o devolve já em processing, com lock_token e com tentativas incrementado. Devolve null se não houver job.

A reserva é atômica sem transação: o UPDATE só vale se o job ainda estiver livre. Vários workers, em várias máquinas, nunca recebem o mesmo job. Se outros workers levarem os primeiros candidatos, ele busca de novo.

ParâmetroTipoDescrição
$tiposarrayTipos aceitos. Vazio aceita qualquer tipo.
$filastring|nullFila. null ou 'all' aceita todas.
$opcoesarraystarted_by: identificação do worker (padrão host:pid).
while ($job = QueueHelper::next(['enviar_email'], 'emails')) {
    try {
        Mailer::enviar($job->payload);
        QueueHelper::complete($job->id, $job->lock_token, ['enviado' => true]);
    } catch (Exception $e) {
        QueueHelper::fail($job->id, $job->lock_token, $e->getMessage());
    }
}

heartbeat()estático

QueueHelper::heartbeat(int $id, string $lockToken): bool

Avisa que o worker continua vivo e renova o prazo do lock. Devolve false se o job não pertence mais a este worker (cancelado, concluído, ou o lock expirou e outro worker o assumiu): nesse caso, pare.

progress()estático

QueueHelper::progress(int $id, string $lockToken, float $progresso, float|null $total = null): bool

Atualiza progresso, total e percentual, e renova o lock como o heartbeat(). Sem $total, mantém o total atual. Um progresso maior que o total é limitado ao total. Devolve false nos mesmos casos do heartbeat().

QueueHelper::progress($job->id, $job->lock_token, 1500, 6000);   // percentual = 25
QueueHelper::progress($job->id, $job->lock_token, 3000);         // total continua 6000 → 50

complete()estático

QueueHelper::complete(int $id, string $lockToken, array $resultado = []): bool

Conclui com sucesso. O resultado (até 10 MB em JSON) fica disponível em find() e status(). Com total definido, o progresso vai a 100%. Devolve false se o job não estiver em processamento com este lock (por exemplo, foi cancelado).

release()estático

QueueHelper::release(int $id, string $lockToken, array $opcoes = []): bool

Devolve o job à fila para continuar depois, mantendo o progresso. É a base do processamento em fatias. Por padrão a pausa não conta como tentativa.

OpçãoPadrãoDescrição
delay_seconds0Só volta a ficar disponível depois de N segundos.
statuspendingpending ou retry.
count_attemptfalsetrue: a execução conta como tentativa. Use para "tentar de novo mais tarde" (serviço fora do ar), para o job não ficar adiando para sempre.

fail()estático

QueueHelper::fail(int $id, string $lockToken, string $mensagem, array $opcoes = []): bool

Registra um erro. Com tentativas restantes, o job vai para retry e volta depois da espera (30s × 2tentativa−1, até 1 hora: 30s, 60s, 120s…). Sem tentativas, vai para failed. A mensagem é guardada em erro (até 50 mil caracteres).

OpçãoDescrição
delay_secondsEspera fixa até a próxima tentativa, no lugar da espera crescente.
permanenttrue: vai direto para failed. Para erros que não se resolvem tentando de novo.

Consultando

find()estático

QueueHelper::find(int|string $idOuUuid): object|null

O job completo, inclusive payload e lock_token. Para mostrar a usuários, use status().

status()estático

QueueHelper::status(int|string $idOuUuid, int|null $userId = null): array

A situação do job para telas e APIs, sem payload e sem lock_token. Com $userId, só o dono consegue consultar.

Retorna: ['success' => true, 'data' => [...]] com as propriedades do job (menos payload, lock_token, lock_em e last_heartbeat_at) e mais finalizado (true em completed, failed e cancelled). Não encontrado ou sem permissão: success = false.

$r = QueueHelper::status($uuid, $userId);

if ($r['success'] && $r['data']['finalizado']) {
    // parar de consultar
}

list()estático

QueueHelper::list(array $filtros = [], int $limite = 50, int $deslocamento = 0): array

Jobs que atendem aos filtros, da maior prioridade para a menor e do mais novo para o mais antigo. Limite de 1 a 500.

$falhos = QueueHelper::list(['queue' => 'emails', 'status' => ['failed', 'retry']], 20);

foreach ($falhos as $job) {
    echo $job->uuid, ' — ', $job->erro, PHP_EOL;
}
FiltroExemplo
queue'emails'
tipo'enviar_email'
status'failed' ou ['failed', 'retry']
usuario_id42
uuid'3f2b8c1e-…'
date_start, date_endData de criação (UTC): '2026-10-01', '2026-10-01 00:00:00' ou '-7 days'

count()estático

QueueHelper::count(array $filtros = []): int

Quantos jobs atendem aos filtros (os mesmos de list()).

stats()estático

QueueHelper::stats(array $filtros = []): array

Quantidade por status, total e a data do job pendente mais antigo: o necessário para um painel ou alerta. Aceita os filtros de list(), menos status.

$s = QueueHelper::stats(['queue' => 'emails']);
// ['pending' => 120, 'processing' => 2, 'retry' => 3, 'completed' => 5400, 'failed' => 7,
//  'cancelled' => 0, 'total' => 5532, 'mais_antigo_pendente' => '2026-10-04 12:58:00']

if ($s['mais_antigo_pendente'] && strtotime($s['mais_antigo_pendente'] . ' UTC') < time() - 600) {
    // há job esperando há mais de 10 minutos: o worker está parado?
}

lastError()estático

QueueHelper::lastError(): string|null

Motivo da falha da última chamada a um método de ação, ou null se ela deu certo.

if (!QueueHelper::cancel($uuid, $userId)) {
    return ApiResponseHelper::conflict(QueueHelper::lastError());
    // 'Não é possível cancelar um job em processamento sem força.'
}

Gerenciando

cancel()estático

QueueHelper::cancel(int|string $idOuUuid, int|null $userId = null, bool $forcar = false): bool

Cancela um job pending ou retry. Um job em processing só com $forcar = true: o worker não é interrompido, mas passa a receber false em heartbeat()/progress() e não consegue mais concluir. Com $userId, só o dono pode cancelar.

retry()estático

QueueHelper::retry(int|string $idOuUuid, int|null $userId = null, array $opcoes = []): bool

Recoloca na fila um job failed ou cancelled: zera tentativas, erro e resultado. O progresso é mantido, para jobs que retomam de onde pararam. ['reset_progress' => true] zera também o progresso.

releaseExpiredLocks()estático

QueueHelper::releaseExpiredLocks(int|null $padraoRetryAfter = null): int

Recupera jobs de workers que morreram: os que estão em processing sem sinal de vida há mais de retry_after_seconds. Voltam para retry ou, sem tentativas, vão para failed. O QueueWorker chama ao iniciar e a cada minuto. $padraoRetryAfter só vale para jobs gravados sem esse valor.

Retorna: quantos jobs foram recuperados.

purge()estático

QueueHelper::purge(mixed $antesDe, array $status = [], int $limite = 1000): int

Apaga jobs finalizados antes de uma data. Por padrão, completed, failed e cancelled; jobs ativos nunca são apagados. Apaga até $limite (máximo 10 mil) por chamada.

ParâmetroTipoDescrição
$antesDemixed'-30 days', '2026-09-01', '2026-09-01 00:00:00' (UTC), DateTime ou timestamp.
$statusarraySubconjunto de ['completed', 'failed', 'cancelled'].
$limiteintMáximo por chamada.

Retorna: quantos foram apagados.

// Concluídos somem em 7 dias; falhas ficam 90 dias para análise.
QueueHelper::purge('-7 days', ['completed']);
QueueHelper::purge('-90 days', ['failed', 'cancelled']);

createTable()estático

QueueHelper::createTable(): bool

Cria a tabela (com índices) no banco em uso, se ainda não existir. Detecta MySQL/MariaDB ou PostgreSQL. Devolve true se criou, false se já existia, e lança exceção em caso de erro. A mesma estrutura está em fila/table.sql e fila/table.postgresql.sql.

Tabela e desempenho

Os índices da tabela atendem às consultas da fila: (queue, status, disponivel_em, prioridade, id) para o next() de um worker por fila, (status, disponivel_em, prioridade, id) para workers de todas as filas, e índices para uuid, usuário e limpeza. Com purge() regular, a tabela fica pequena e as consultas continuam rápidas mesmo com milhões de jobs processados.

O payload aceita até 10 MB, mas o ideal é que seja pequeno: ids e caminhos de arquivo, não o conteúdo. Um CSV enviado pelo usuário vai para uma pasta (veja o UploadMaster), e o job recebe só o caminho.
