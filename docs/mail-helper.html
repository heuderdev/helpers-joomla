MailHelper

E-mails transacionais pelo mailer do Joomla: templates em arquivo com variáveis escapadas, layout comum, texto alternativo gerado do HTML, anexos, cópia e cópia oculta, modo de teste e envio pela fila para a página não esperar o servidor de e-mail.

Visão geral

require_once JPATH_COMPONENT . '/helpers/MailHelper.php';

$r = MailHelper::send(array(
    'to' => array($cliente->email => $cliente->nome),
    'subject' => 'Pedido #{{ pedido.numero }} confirmado',
    'template' => 'pedido-confirmado',                 // components/com_loja/emails/pedido-confirmado.html
    'data' => array('cliente' => $cliente, 'pedido' => $pedido),
));

if (!$r['success']) {
    // $r['mensagem'] e $r['errors']['_system'][0] (motivo seguro para mostrar); detalhes no log "mail"
}
components/com_loja/emails/pedido-confirmado.html
<h1>Olá, {{ cliente.nome }}!</h1>
<p>Seu pedido <strong>#{{ pedido.numero }}</strong> de {{ pedido.total | money }} foi confirmado em {{ pedido.created_at | date }}.</p>
<p>Observações: {{ pedido.observacao | nl2br }}</p>
<p><a href="{{ link }}">Acompanhar pedido</a></p>
  • Usa a configuração global do Joomla (PHP mail, Sendmail ou SMTP, remetente padrão) nas versões 3, 4 e 5.
  • Variáveis escapadas: um nome de cliente <script> chega como texto. Os valores inseridos nunca são reprocessados: um {{ token }} digitado pelo cliente não revela outra variável.
  • Texto alternativo automático a partir do HTML (parágrafos, listas, links como "texto (url)"): melhora a entrega e a leitura em clientes só-texto.
  • Cabeçalhos protegidos: quebras de linha no assunto, nomes e cabeçalhos são removidas (sem injeção de Bcc:); e-mails inválidos são recusados antes de chegar ao servidor.
  • Não lança exceção: devolve o envelope { success, status, mensagem, data, errors }, como o UploadMaster e o CsvHelper.

No layout, {!! conteudo !!} recebe o HTML do template e {{ assunto }} o assunto. Clientes de e-mail ignoram CSS externo e boa parte do <style>: use tabelas e estilos inline, imagens com URL absoluta e largura de até 600 px.

render() / build() / htmlToText()estático

MailHelper::render(string $template, array $data, bool $html = true): string MailHelper::build(array $mail): array MailHelper::htmlToText(string $html): string

build() monta o e-mail sem enviar (lança InvalidArgumentException se algo estiver errado): útil para uma tela de pré-visualização no administrador.

Envio pela fila

O SMTP pode levar segundos (ou cair). Em telas, coloque o envio na fila: a página responde na hora e o worker envia, com novas tentativas se o servidor de e-mail falhar.

$r = MailHelper::queue(array(
    'to' => $cliente->email,
    'subject' => 'Bem-vindo, {{ nome }}!',
    'template' => 'boas-vindas',
    'data' => array('nome' => $cliente->nome),
), array('max_tentativas' => 5));   // opções do QueueHelper::push()

// $r é o resultado do QueueHelper::push()
components/com_loja/jobs/jobs.php (bootstrap do worker)
require_once JPATH_ROOT . '/components/com_loja/helpers/MailHelper.php';

MailHelper::registerJob();   // tipo 'helpers_mail', fila 'emails' (padrão do worker: todas as filas)
  • O conteúdo é montado na hora do queue(): erros de template aparecem para quem chamou, e o worker não precisa da pasta de templates nem do usuário logado (datas já saem no fuso de quem disparou).
  • Anexos são guardados como caminho: não apague o arquivo antes do envio. Para arquivos temporários, apague num job posterior ou deixe uma limpeza periódica.
  • O job é fila/jobs/MailJob.php (o instalar.sh copia junto com o MailHelper). Falha de envio lança exceção e o worker tenta de novo.

Modo de teste e desenvolvimento

MailHelper::fake();                          // nada é enviado

$r = PedidoService::confirmar($pedido);      // código que envia e-mail

$enviados = MailHelper::sent();              // array das mensagens montadas (to, subject, html, text...)
assert($enviados[0]['to'] === array('ana@x.com' => 'Ana'));

Em desenvolvimento, configure o SMTP do Joomla para um capturador (Mailpit, MailHog, Mailtrap) em vez de mandar para clientes reais.

Para os e-mails chegarem (e não caírem no spam)

  • Remetente do próprio domínio, autorizado no SPF e assinado com DKIM; publique DMARC. @gmail.com como remetente de um servidor que não é do Google vai para o spam ou é recusado.
  • Use SMTP autenticado (provedor transacional: Amazon SES, SendGrid, Mailgun, Brevo) em vez da função mail() do servidor.
  • Sempre HTML e texto (o MailHelper gera o texto); evite e-mails só com imagem.
  • Envios em massa (newsletter) não são e-mail transacional: use uma ferramenta própria, com descadastro.
