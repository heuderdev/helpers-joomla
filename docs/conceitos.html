Conceitos

As regras que valem para todos os métodos. Ler esta página evita os erros mais comuns.

Três formas de usar o ORM

As três dão acesso aos mesmos recursos. O que muda é onde fica a configuração da tabela (casts, colunas permitidas, soft delete, conexão…). Você pode misturar as três no mesmo projeto, inclusive na mesma transação.

// 1. Direto: configuração na própria chamada
OrmTables::table('#__loja_produtos', ['casts' => ['ativo' => 'bool']])
    ->where('ativo', true)
    ->get();

// 2. Registro por nome: configura uma vez, usa em qualquer lugar
OrmTables::register('produtos', '#__loja_produtos', ['casts' => ['ativo' => 'bool']]);
OrmTables::get('produtos')->where('ativo', true)->get();

// 3. Model: configuração numa classe, com métodos próprios
class ProdutoModel extends OrmBase
{
    protected $table = '#__loja_produtos';
    protected $casts = ['ativo' => 'bool'];

    public function ativos()
    {
        return $this->where('ativo', true);
    }
}

ProdutoModel::query()->ativos()->get();
SituaçãoForma recomendada
Consulta pontual, relatório, script, tabela de logOrmTables::table()
Mesma tabela em vários lugares, sem regras própriasOrmTables::register() + get()
Tabela central do domínio, com regras e filtros nomeadosModel que estende OrmBase

O ciclo de uma consulta

Uma instância do ORM guarda os filtros que você vai encadeando (where, orderBy, limit…). Nada vai ao banco até você chamar um método final. O método final executa a consulta e limpa os filtros, deixando a instância pronta para a próxima.

$produtos = OrmTables::table('#__loja_produtos');

$produtos->where('ativo', 1);      // só guarda o filtro
$produtos->orderBy('nome');        // só guarda a ordenação
$lista = $produtos->get();         // executa e limpa

$todos = $produtos->count();       // sem filtros: conta a tabela inteira
TipoMétodosO que acontece com os filtros
Montagem (encadeáveis)select, where*, orWhere*, whereGroup, when, join*, orderBy, latest, oldest, groupBy, having, limit, lockForUpdate, allowMassOperationAcumulam.
Finais que usam os filtrosget, first, value, pluck, exists, count, sum, avg, min, max, paginate, chunk, updateWhere, deleteWhereUsam e limpam, com sucesso ou erro.
Finais que descartam os filtrosfind, findOrFail, findBy, all, firstOrCreate, updateOrCreateLimpam antes e montam a própria condição.
Por id (ignoram os filtros)create, update, increment, decrement, touch, delete, restore, forceDeleteNão usam os filtros. Os que devolvem o registro (create, update, increment, decrement, touch, restore) o relêem com find() e por isso descartam filtros pendentes. delete e forceDelete não mexem neles.
Armadilha comum

$produtos->where('ativo', 1)->find(5) não verifica ativo: find() descarta os filtros. Para "este id e mais uma condição", use where('id', 5)->where('ativo', 1)->first().

Reaproveitar filtros

Para manter uma consulta base e derivar várias outras, use clone:

$base = OrmTables::table('#__loja_pedidos')->where('cliente_id', 7);

$abertos = (clone $base)->where('status', 'aberto')->count();
$pagos = (clone $base)->where('status', 'pago')->count();

Sem cast, o banco devolve quase tudo como string ("2.50", "1"). Declare casts para receber float, int, bool ou arrays de JSON.

Prefixo de tabela (#__)

Escreva os nomes de tabela com #__. O driver troca pelo prefixo configurado na conexão: o do Joomla na conexão padrão, ou o prefix que você informar ao registrar outra conexão.

Segurança: o que é escapado

Valores passados aos métodos são sempre escapados. Já os parâmetros que recebem SQL cru são enviados como estão e nunca devem receber dados do usuário.

Seguro para dados do usuárioSQL cru: só texto fixo do seu código
Valores de where, orWhere, whereIn, whereBetween, whereLikewhereRaw($sql)
Valores de create, update, updateWhere, firstOrCreate…having($sql)
Ids de find, update, delete… (convertidos para inteiro)Condição do join($tabela, $condicao)
Itens de select() (permitem expressões como COUNT(*) AS total)
// ERRADO: injeção de SQL
$q->whereRaw("nome = '" . $_GET['nome'] . "'");

// CERTO
$q->where('nome', InputHelper::string('nome'));
Ordenação vinda da tela

Nomes de coluna em where, orderBy e groupBy recebem aspas de identificador, mas mesmo assim não aceite nomes de coluna vindos da tela sem uma lista permitida. Uma coluna inexistente vira erro de SQL. Use InputHelper::sorting():

// ?sort=preco&direction=desc
$ordem = InputHelper::sorting(['nome', 'preco', 'created_at'], 'nome');

$q->orderBy($ordem['field'], $ordem['direction']);

Erros e exceções

ExceçãoQuandoO que fazer
RuntimeException (código 500)Erro do banco: SQL inválido, conexão, constraint, deadlock… A mensagem diz a operação e a tabela, e a exceção original fica em getPrevious().Logar e responder com mensagem genérica.
RuntimeException (código 404)findOrFail() não encontrou o registro.Responder "não encontrado".
LogicExceptionUso incorreto: deleteWhere() sem filtro, lockForUpdate() fora de transação…Corrigir o código. Não é erro de banco.
InvalidArgumentExceptionParâmetro inválido: operador desconhecido, tabela vazia, conexão não registrada…Corrigir a chamada.
try {
    $produto = OrmTables::table('#__loja_produtos')->findOrFail($id);
} catch (RuntimeException $e) {
    if ($e->getCode() === 404) {
        return ApiResponseHelper::notFound('Produto não encontrado.');
    }

    // Detalhe técnico vai para o log, nunca para o usuário
    return ApiResponseHelper::exception($e);
}

Datas e fuso horário

Os helpers seguem a regra do Joomla: o banco guarda UTC e a tela mostra no fuso do usuário. created_at, updated_at e deleted_at do ORM, as datas da fila e a auditoria são gravados em UTC. Para as datas que você mesmo grava ou mostra, use o DateHelper:

$dados['pago_em'] = DateHelper::nowSql();                  // gravar: agora, em UTC
echo DateHelper::toUser($pedido->created_at);               // mostrar: no fuso do usuário
$entrega = DateHelper::fromUser('25/12/2026 14:30');       // formulário -> UTC
$mes = DateHelper::range('month');                         // filtro de relatório, em UTC

Evite date('Y-m-d H:i:s'): ele usa o fuso do PHP do servidor, que pode diferir entre o site, o cron e o ambiente de testes.
