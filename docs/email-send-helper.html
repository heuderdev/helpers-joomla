EmailSendHelper

Envio de e-mails sem dependências e sem o mailer do Joomla: cliente SMTP próprio (Gmail, Outlook/Hotmail, Office 365, Yahoo, Zoho, SendGrid, Brevo, Mailgun, Locaweb, Hostinger ou qualquer servidor), API HTTP da ElasticEmail, mail() do PHP, gravação em arquivo .eml e modo de teste. Várias contas registradas por nome, failover entre elas, views e layouts, anexos, imagens embutidas e diagnóstico da conversa com o servidor.

Visão geral

require_once JPATH_COMPONENT . '/helpers/EmailSendHelper.php';

// 1) Uma vez, no carregamento do componente (credenciais fora do código: veja "Onde guardar as senhas")
EmailSendHelper::register('gmail', [
    'username'  => 'contato@gmail.com',
    'password'  => 'abcd efgh ijkl mnop',   // senha de app, não a senha da conta
    'from_name' => 'Loja Exemplo',
]);

// 2) Em qualquer lugar
$r = EmailSendHelper::make()
    ->to($cliente->email, $cliente->nome)
    ->subject('Pedido {{ pedido.numero }} confirmado')
    ->view('pedido-confirmado', ['cliente' => $cliente, 'pedido' => $pedido])
    ->attach('/caminho/boleto.pdf')
    ->send();

if (!$r['success']) {
    echo $r['mensagem'];        // "Não foi possível enviar o e-mail."
    print_r($r['errors']);      // ['gmail' => ['Falha na autenticação SMTP: ...']]
}
  • Sem dependências: um arquivo só. Não usa PHPMailer, Symfony Mailer nem o JMail do Joomla. Precisa de PHP 8.2+ com openssl (TLS/SSL) e mbstring; usa curl e fileinfo se existirem.
  • Roda no Joomla, no Laravel e em PHP puro. O arquivo só bloqueia o acesso direto pela URL; não exige _JEXEC.
  • Nunca lança exceção em send(): o resultado volta no formato padrão dos helpers, ['success', 'status', 'mensagem', 'data', 'errors']. Se preferir exceção, use sendOrFail().
  • Log automático: se o LogHelper estiver carregado, cada envio e cada falha vai para a categoria mail (conexão, driver, destinatários, assunto e número de anexos; nunca a senha nem o corpo). Carregando pelo IncludeHelper (IncludeHelper::load('EmailSendHelper')), o LogHelper vem junto.

EmailSendHelper ou MailHelper?

Os dois enviam e-mails transacionais com templates. A diferença é quem entrega:

MailHelperEmailSendHelper
EntregaMailer do Joomla (configuração global: PHP mail, Sendmail ou SMTP)Cliente SMTP próprio, API da ElasticEmail, mail() ou arquivo
ContasUma (a do Joomla)Quantas quiser, por nome, com failover
Fora do JoomlaNãoSim (Laravel, PHP puro, CLI)
Envio pela filaSim (MailHelper::queue())Não embutido (veja a receita)
Imagens embutidas (cid:)NãoSim
DiagnósticoLogLog, testConnection() e conversa SMTP completa (debug)

Use o MailHelper quando o e-mail do Joomla já está configurado e basta. Use o EmailSendHelper quando precisa de outra conta (Gmail do cliente, ElasticEmail, SendGrid), de mais de uma conta, de failover, ou de enviar fora do Joomla.

Conexões

Uma conexão é uma conta de envio com nome. Registre todas uma vez, no carregamento do componente (ou no bootstrap do script), e escolha pelo nome ao enviar.

register()estático

EmailSendHelper::register(string $name, array $config = []): void

Registra (ou substitui) uma conexão. O nome também escolhe o provedor pronto: register('gmail', [...]) já sabe o host, a porta e a criptografia do Gmail. Para usar outro nome, informe provider. O que você passar no $config sempre vence o provedor pronto. A primeira conexão registrada vira a padrão.

EmailSendHelper::register('gmail', ['username' => 'conta@gmail.com', 'password' => 'senha-de-app']);

EmailSendHelper::register('vendas', [          // nome livre + provider
    'provider'  => 'office365',
    'username'  => 'vendas@empresa.com.br',
    'password'  => '...',
    'from_name' => 'Comercial',
]);

EmailSendHelper::register('elasticemail', ['api_key' => '...', 'from' => 'nao-responda@empresa.com.br']);

EmailSendHelper::register('servidor', [        // qualquer servidor SMTP
    'host'       => 'smtp.empresa.com.br',
    'port'       => 587,
    'encryption' => 'tls',
    'username'   => 'sistema@empresa.com.br',
    'password'   => '...',
]);

Sem driver nem provedor conhecido, ele deduz: com host vira smtp; com api_key vira elasticemail. Lança InvalidArgumentException se o nome for vazio, se não der para descobrir o driver, se faltar o host no SMTP ou a api_key na ElasticEmail.

Onde guardar as senhas

Nunca deixe senha ou API key no código versionado. Leia de um arquivo de configuração fora da pasta pública e fora do git, das variáveis de ambiente, ou dos parâmetros do componente com o SettingsHelper:

// config.php fora do public_html e no .gitignore
return [
    'EMAIL' => [
        'elasticemail' => ['api_key' => getenv('ELASTICEMAIL_API_KEY'), 'from' => 'nao-responda@empresa.com.br', 'from_name' => 'Empresa'],
        'gmail'        => ['username' => 'contato@gmail.com', 'password' => getenv('GMAIL_APP_PASSWORD')],
    ],
];

// no carregamento do componente
$config = require '/home/empresa/config/config.php';
EmailSendHelper::registerMany($config['EMAIL']);
EmailSendHelper::setDefault('elasticemail');

Montar a mensagem

make()estático

EmailSendHelper::make(string|array|null $connection = null, array $mail = []): EmailSendHelper

Cria uma mensagem nova. Cada chamada é independente: nada passa de um e-mail para o outro. $connection aceita:

  • null: a conexão padrão;
  • 'gmail': uma conexão registrada;
  • ['elasticemail', 'gmail']: failover, tenta na ordem;
  • ['host' => ..., 'username' => ...]: configuração avulsa, usada só neste envio, sem registrar.

$mail é opcional e aceita as mesmas chaves de fill(). Para trocar a conexão depois, use ->via($connection).

to() / cc() / bcc() / replyTo()encadeável

$mail->to(string|array $address, ?string $name = null): $this

Podem ser chamados várias vezes; os endereços se somam (o mesmo e-mail aparece uma vez só). Formatos aceitos:

->to('ana@x.com')
->to('ana@x.com', 'Ana Silva')
->to('ana@x.com, bruno@x.com; carla@x.com')          // separados por vírgula ou ponto e vírgula
->to('Ana Silva <ana@x.com>')
->to('"Silva, Ana" <ana@x.com>')                      // vírgula dentro de aspas não divide
->to(['ana@x.com', 'bruno@x.com'])
->to(['ana@x.com' => 'Ana', 'bruno@x.com' => 'Bruno'])
->to([['email' => 'ana@x.com', 'name' => 'Ana']])     // lista de linhas do banco, por exemplo

Um endereço inválido não quebra a cadeia: o erro fica guardado e o send() devolve success = false com E-mail inválido em "to": ..., sem tentar enviar. Valores vazios ('', null, []) são ignorados. É preciso ao menos um destinatário em to, cc ou bcc.

bcc nunca aparece no cabeçalho do e-mail no SMTP: os endereços vão só no envelope. Use bcc para enviar a muitas pessoas sem expor a lista.

from()encadeável

$mail->from(string $email, ?string $name = null): $this

Remetente desta mensagem. Se não for chamado, vale nesta ordem: from_email (+ from_name) da conexão; depois o username, se for um e-mail. Sem nenhum deles, o envio falha com Remetente inválido ou ausente.

subject() / html() / text()encadeável

$mail->subject(string $subject): $this $mail->html(string $html): $this $mail->text(string $text): $this

Assunto (obrigatório), corpo HTML e corpo em texto puro. Os três aceitam {{ variavel }} com os dados de with()/view(). No HTML o valor é escapado; no assunto e no texto, não (não há HTML ali).

  • Só html() (ou view()): a versão em texto é gerada automaticamente do HTML (htmlToText()). Clientes sem HTML e filtros anti-spam gostam disso.
  • Só text(): e-mail em texto puro.
  • Os dois: cada um vai como você escreveu.

Quebras de linha no assunto viram espaço, o que impede injeção de cabeçalhos.

with()encadeável

$mail->with(string|array $key, mixed $value = null): $this

Dados para o assunto, o HTML, o texto, a view e o layout. Aceita uma chave e um valor ou um array; chamadas seguidas se somam.

->with('pedido', $pedido)
->with(['cliente' => $cliente, 'link' => $urlRastreio])

priority() / header() / unsubscribe()encadeável

$mail->priority(int $priority): $this // 1 alta · 3 normal · 5 baixa $mail->header(string $name, string $value): $this $mail->unsubscribe(string $urlOrMailto): $this
  • priority(1) e priority(2) marcam como alta (X-Priority e Importance: High); 4 e 5, baixa; 3 não muda nada. Valores fora de 1 a 5 são ajustados.
  • header('X-Pedido', '42') adiciona um cabeçalho. O nome só pode ter letras, números e hífen (senão o envio falha com Cabeçalho inválido); quebras de linha no valor viram espaço.
  • unsubscribe('https://empresa.com/sair?t=...') gera List-Unsubscribe e, para HTTPS, List-Unsubscribe-Post: List-Unsubscribe=One-Click (descadastro em um clique). Aceita também um e-mail (sair@empresa.com vira mailto:). O Gmail e o Yahoo exigem isso em envios em massa.

Views, layouts e variáveis

view()encadeável

$mail->view(string $file, array $data = []): $this

Corpo HTML a partir de um arquivo. Tem prioridade sobre html(). O tipo do arquivo decide como ele é lido:

ArquivoComo funciona
.phpPHP normal. Cada chave dos dados vira uma variável ($cliente, $pedido) e $e() escapa um valor para HTML. Você controla tudo: if, foreach, funções.
.html (ou outro)Texto com {{ variavel }} (escapada), {!! variavel !!} (sem escape) e filtros. Bom para quem edita o layout sem saber PHP.
emails/pedido-confirmado.php
<h1>Olá, <?= $e($cliente->nome) ?>!</h1>
<p>Seu pedido <strong>#<?= $e($pedido->numero) ?></strong> foi confirmado.</p>

<table>
    <?php foreach ($pedido->itens as $item): ?>
        <tr>
            <td><?= $e($item->nome) ?></td>
            <td><?= $e(FormatHelper::money($item->total)) ?></td>
        </tr>
    <?php endforeach; ?>
</table>

<p><a href="<?= $e($link) ?>">Acompanhar pedido</a></p>
emails/aviso.html
<p>Olá, {{ cliente.nome }}!</p>
<p>Seu boleto de {{ valor | money }} vence em {{ vencimento | date }}.</p>
<p>{{ observacao | nl2br }}</p>

Onde o arquivo é procurado, nesta ordem: na pasta de setViewDirectory() (se definida) e depois no caminho como foi escrito (absoluto ou relativo à pasta atual). Sem extensão, tenta também .php e .html: view('pedido-confirmado') acha pedido-confirmado.php. Não achou: o envio falha com View de e-mail não encontrada.

Em views .php, sempre escape com $e() o que veio do usuário ou do banco. <?= $cliente->nome ?> sem $e() permite injetar HTML (links falsos, phishing) no e-mail. Nunca monte o nome da view com dado da requisição: ela é um include de PHP.

layout()encadeável

$mail->layout(string|false $file): $this

Arquivo que "envolve" o HTML: cabeçalho com a logo, rodapé, estilos. Recebe os mesmos dados da view e mais content (ou conteudo), com o HTML já renderizado da view, e subject (ou assunto). layout(false) desliga o layout padrão só neste e-mail. Só se aplica quando há HTML.

emails/layout.php
<!doctype html>
<html lang="pt-BR">
<body style="margin:0;background:#f4f4f5;font-family:Arial,sans-serif">
    <table width="100%" cellpadding="0" cellspacing="0"><tr><td align="center">
        <table width="600" cellpadding="24" style="background:#fff">
            <tr><td><img src="cid:logo" alt="Loja Exemplo" width="140"></td></tr>
            <tr><td><?= $content ?></td></tr>
            <tr><td style="font-size:12px;color:#71717a">Você recebeu este e-mail porque comprou na Loja Exemplo.</td></tr>
        </table>
    </td></tr></table>
</body>
</html>

Num layout .html, use {!! content !!} (sem escape, porque já é HTML) e {{ subject }}.

setViewDirectory() / setDefaultLayout()estático

EmailSendHelper::setViewDirectory(?string $directory): void EmailSendHelper::setDefaultLayout(string|null $file): void

Configuração global, normalmente no carregamento do componente: a pasta base das views e o layout aplicado a todo e-mail HTML.

EmailSendHelper::setViewDirectory(JPATH_COMPONENT . '/emails');
EmailSendHelper::setDefaultLayout('layout.php');

EmailSendHelper::make()->to($email)->subject('Bem-vindo')->view('boas-vindas')->embed(JPATH_COMPONENT . '/emails/logo.png', 'logo')->send();
EmailSendHelper::make()->to($email)->subject('Código: {{ codigo }}')->text('Seu código é {{ codigo }}')->with('codigo', $codigo)->send();   // texto: sem layout

Variáveis e filtros ({{ }})

Valem no assunto, em html(), em text() e nos arquivos que não são .php. O caminho usa ponto e entra em arrays, objetos e ArrayAccess: {{ pedido.cliente.nome }}. Variável que não existe vira texto vazio (sem erro).

EscritaResultado
{{ nome }}Valor escapado para HTML (<b> aparece como texto).
{!! html !!}Valor sem escape. Só para HTML gerado por você.
{{ total | money }}R$ 1.234,50
{{ total | number }}1.234,50
{{ criado_em | date }}13/11/2026
{{ criado_em | datetime }}13/11/2026 10:00
{{ nome | upper }} / lowerMaiúsculas / minúsculas (com acento).
{{ observacao | nl2br }}Escapa e troca quebras de linha por <br>.
true / falseSim / Não
  • Um filtro por variável. Arrays e objetos sem __toString() viram texto vazio.
  • O valor inserido nunca é processado de novo: um cliente que se chama {{ senha }} não revela nada.
  • date e datetime usam o fuso do PHP. No Joomla ele é UTC: para mostrar a hora local do usuário, formate antes com o DateHelper e passe o texto pronto.

renderString() / renderFile() / htmlToText()estático

EmailSendHelper::renderString(string $template, array $data = [], bool $html = true): string EmailSendHelper::renderFile(string $file, array $data = []): string EmailSendHelper::htmlToText(string $html): string

Os motores de template e de texto, avulsos. htmlToText() remove estilos e scripts, transforma links em texto (url), itens de lista em - item, parágrafos e títulos em linhas em branco e células de tabela em tabulação.

EmailSendHelper::renderString('Olá {{ nome }}, total {{ v | money }}', ['nome' => 'Ana', 'v' => 99.9]);
// "Olá Ana, total R$ 99,90"

EmailSendHelper::htmlToText('<p>Olá <a href="https://loja.com/p/1">ver pedido</a></p><ul><li>um</li><li>dois</li></ul>');
// "Olá ver pedido (https://loja.com/p/1)\n\n- um\n- dois"

Anexos e imagens

attach()encadeável

$mail->attach(string $path, ?string $name = null, ?string $mime = null): $this

Anexa um arquivo do disco. $name é o nome que o destinatário vê (padrão: o nome do arquivo; acentos funcionam em todos os clientes). O tipo é deduzido pela extensão (PDF, XML, XLSX, DOCX, ZIP, imagens, OFX, remessa/retorno...) ou pelo conteúdo. O arquivo é lido na hora do envio; se não existir, o envio falha com Anexo não encontrado.

->attach(JPATH_ROOT . '/tmp/boleto-123.pdf')
->attach($caminhoXml, 'NF-e 4521.xml')

Nunca passe a attach() um caminho vindo da requisição: attach($_POST['arquivo']) permite anexar configuration.php ou qualquer arquivo do servidor e enviar para fora. Busque o caminho no banco, pelo id, depois de conferir a permissão.

attachData()encadeável

$mail->attachData(string $content, string $name, ?string $mime = null): $this

Anexo gerado em memória (CSV, PDF, XML, ICS), sem gravar arquivo.

$csv = "pedido;total\n1;150,00\n2;89,90\n";
->attachData("\xEF\xBB\xBF" . $csv, 'pedidos-novembro.csv')        // BOM para o Excel abrir com acento
->attachData($pdf, 'contrato.pdf', 'application/pdf')

attachUpload()encadeável

$mail->attachUpload(array $file): $this

Anexa direto o array de um upload ($_FILES['campo'] ou InputHelper::file()), simples ou múltiplo (name="anexos[]"). Campo sem arquivo é ignorado; upload com erro (tamanho, parcial) faz o envio falhar com Falha no upload do anexo "..." (código N).

O helper não valida tipo nem conteúdo do upload. Antes, limite extensões e tamanho com o ValidationHelper (file_extension, file_size), para o seu formulário não virar um disparador de arquivos maliciosos.

embed()encadeável

$mail->embed(string $path, ?string $cid = null): $this

Imagem embutida no corpo, que aparece sem o cliente de e-mail baixar nada da internet (logo, assinatura). No HTML, use <img src="cid:SEU_CID">. Sem $cid, vale o nome do arquivo sem extensão: embed('logo.png') vira cid:logo.

->html('<p><img src="cid:logo" width="140" alt="Loja"></p><p>Olá!</p>')
->embed(JPATH_ROOT . '/images/logo-email.png', 'logo')
  • E-mail só em texto: a imagem vai como anexo comum.
  • Driver elasticemail (API): a API não tem imagens embutidas, então elas vão como anexo e o cid: não aparece no corpo. Para logo embutida na ElasticEmail, use o provedor elasticemail_smtp.

Limite de tamanho

A soma de anexos e imagens embutidas é limitada a 25 MB por padrão (o Gmail recusa acima disso; com a codificação base64, o e-mail fica cerca de 33% maior que os arquivos). Passou: o envio falha antes de conectar, com Anexos somam X MB; o limite é Y MB. Ajuste por conexão com max_size (em bytes; 0 desliga). Para arquivos grandes, prefira mandar um link de download.

Enviar

send()envia

$mail->send(): array

Monta e envia. Nunca lança exceção.

// sucesso
[
    'success'  => true,
    'status'   => 'sucesso',
    'mensagem' => 'E-mail enviado com sucesso.',
    'data'     => [
        'connection'      => 'gmail',
        'driver'          => 'smtp',
        'message_id'      => '<464a5714...@empresa.com>',   // guarde para rastrear

Failover: várias conexões em ordem

Com uma lista, o helper tenta a primeira; se ela falhar, tenta a próxima, e assim por diante. O resultado diz qual entregou (data.connection) ou, se todas falharam, o motivo de cada uma (errors).

$r = EmailSendHelper::make(['elasticemail', 'gmail', 'arquivo'])   // API → SMTP → grava .eml para reenviar depois
    ->to($cliente->email)
    ->subject('Seu acesso')
    ->view('acesso', ['cliente' => $cliente])
    ->send();
Tipo de erroTenta a próxima?Exemplos
Entrega (servidor, rede, credencial)Simconexão recusada, tempo esgotado, senha errada, API key inválida, servidor recusou o destinatário
Mensagem (dados)Não (outra conta não resolveria)e-mail inválido, sem assunto, sem corpo, sem remetente, anexo ou view não encontrados, anexos acima do limite

Se o servidor recebeu a mensagem mas a conexão caiu antes da confirmação, o failover pode entregar o mesmo e-mail duas vezes. É raro; para e-mails em que duplicar é grave, envie por uma conexão só e trate a falha.

Drivers

DriverComo entregaBom para
smtpCliente SMTP próprio: STARTTLS (TLS 1.2/1.3) ou SSL, AUTH PLAIN, LOGIN ou XOAUTH2.Gmail, Outlook, provedores de hospedagem, SendGrid, Brevo, Mailgun, servidor da empresa.
elasticemailAPI HTTP v4 da ElasticEmail (JSON, via curl ou streams).Volume alto, rastreio por transaction_id, servidores que bloqueiam as portas SMTP.
mailmail() do PHP (sendmail no Linux; no Windows, o SMTP do php.ini).Hospedagens que só liberam mail().
logGrava o e-mail completo num .eml (abre no Outlook/Thunderbird).Desenvolvimento, homologação e último recurso do failover.

Detalhes do SMTP

  • Porta 587 com tls (STARTTLS) ou 465 com ssl. Se o servidor não oferecer STARTTLS na 587, o erro sugere trocar para ssl/465.
  • O certificado do servidor é conferido (verify_peer). Em ambiente local com certificado próprio, 'verify_peer' => false; nunca em produção.
  • Falha de login no Gmail ou no Outlook vem com a dica do que fazer (senha de app, SMTP AUTH).
  • Cada envio abre e fecha uma conexão. Para centenas de e-mails, prefira a ElasticEmail (API) ou mande pela fila.

Detalhes da ElasticEmail (API)

  • Só api_key e um remetente de domínio verificado na ElasticEmail.
  • cc e bcc são aceitos; do reply_to, vai só o primeiro endereço.
  • Imagens embutidas viram anexos (veja embed()).
  • Erro 401/403 vira API key inválida ou sem permissão de envio.

Detalhes de mail e log

  • mail: no Linux, o envelope_from vira o Return-Path (-f). Muitas hospedagens marcam mail() como spam; prefira SMTP autenticado.
  • log: arquivo AAAA-MM-DD_HHMMSS_xxxxxxxx.eml, caminho em $r['data']['file']. Inclui o Bcc, para conferência.

O driver log grava por padrão em logs/emails da pasta atual, que no Joomla costuma ser a raiz pública do site. Os .eml têm dados pessoais e links de acesso: sempre informe directory fora da pasta pública, como JPATH_ROOT . '/../emails' ou a pasta de logs do Joomla protegida.

Caixa de e-mail local (Mailpit)

No desenvolvimento, rode o Mailpit e registre EmailSendHelper::register('mailpit'). Todo e-mail cai em http://localhost:8025, com HTML, texto, anexos e cabeçalhos, sem chegar a ninguém.

Segurança

  • Credenciais fora do código e fora da pasta pública (como fazer). connections(), o log e o transcript nunca mostram senha nem API key.
  • Injeção de cabeçalhos bloqueada: quebras de linha no assunto, nos nomes, nos nomes de anexo e nos valores de cabeçalho viram espaço; nomes de cabeçalho só aceitam letras, números e hífen; endereços passam por FILTER_VALIDATE_EMAIL.
  • Escape: {{ }} escapa; {!! !!} e <?= ?> sem $e(), não. Dado do usuário sempre com {{ }} ou $e().
  • Caminhos: view, layout, attach() e embed() só com caminhos do seu código ou do banco, nunca da requisição.
  • Formulários públicos (contato, indicação) são usados por spammers para disparar e-mails: proteja com RateLimitHelper, token CSRF (PermissionHelper) e não deixe o visitante escolher o destinatário.
  • TLS sempre em produção: encryption none e verify_peer => false só no ambiente local.
  • Entregabilidade: remetente do mesmo domínio da conta de envio, com SPF, DKIM e DMARC no DNS. Sem isso, os e-mails caem no spam ou são recusados (o helper não assina DKIM; quem assina é o provedor).

Enviar pela fila

O EmailSendHelper não tem fila própria. Para a página não esperar o servidor de e-mail, crie um job para o QueueHelper (como o MailJob do MailHelper) e use sendOrFail(): a exceção faz o worker tentar de novo mais tarde.

jobs/EmailSendJob.php
class EmailSendJob extends AbstractJob
{
    public function handle()
    {
        // o worker precisa registrar as conexões no bootstrap, como o componente faz
        $r = EmailSendHelper::make($this->getPayload('connection'), $this->getPayload('mail', []))->sendOrFail();

        return ['message_id' => $r['data']['message_id'], 'connection' => $r['data']['connection']];
    }
}
// no arquivo de jobs do worker
JobRegistry::register('email_send', $base . '/jobs/EmailSendJob.php', 'EmailSendJob', 'emails');

// no controller: enfileira e responde na hora
QueueHelper::push('email_send', [
    'connection' => ['elasticemail', 'loja'],
    'mail' => [
        'to'      => [$cliente->email => $cliente->nome],
        'subject' => 'Pedido #{{ numero }} enviado',
        'view'    => 'pedido-enviado',
        'data'    => ['numero' => $pedido->numero, 'rastreio' => $pedido->rastreio],
    ],
], ['max_tentativas' => 5]);

Guarde no payload só dados simples (endereços, números, textos): ele vai para o banco em JSON, e objetos viram arrays. Caminhos de anexo precisam existir quando o worker rodar; anexos gerados em memória, gere dentro do job.

Limitações

  • Sem fila própria e sem nova tentativa na mesma conexão: use failover ou a fila.
  • Uma conexão por e-mail: no SMTP, cada envio abre e fecha a conexão. Para grandes volumes, API ou fila.
  • Sem assinatura DKIM e sem S/MIME: a assinatura fica com o provedor (Gmail, ElasticEmail, SendGrid...).
  • OAuth2: usa o oauth_token pronto; obter e renovar o token é com você.
  • ElasticEmail (API): sem imagens embutidas e só o primeiro reply_to.
  • Estado por requisição: conexões, pasta de views, layout padrão e fake() são estáticos e valem até o fim do request ou script.
  • Templates {{ }}: sem if/foreach e com um filtro por variável. Para lógica, use view .php.
  • Anexos inteiros na memória: cada arquivo é lido por completo; o limite de 25 MB existe também por isso.
