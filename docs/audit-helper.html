AuditHelper

Registro e consulta de trilhas de auditoria (audit trail) de forma totalmente agnóstica de banco, integrada ao OrmBase, com ofuscação automática de dados sensíveis e rastreamento de contexto de requisição.

Visão geral

O AuditHelper registra tudo o que acontece de relevante na aplicação em uma tabela estruturada (#__audit_logs), servindo tanto para análise de falhas operacionais por parte do suporte quanto para fins de conformidade jurídica de segurança da informação (LGPD).

A arquitetura do AuditHelper segue padrões de excelência de nível de produção:

  • Portabilidade por ORM (`OrmBase`/`OrmTables`): Ao invés de usar o driver nativo estático do Joomla, o helper escreve e consulta os logs de auditoria utilizando nosso motor ORM. Isso significa que a tabela de auditoria se torna 100% compatível com qualquer banco (seja MySQL, MariaDB, PostgreSQL ou `SQL Server`) e se adapta de forma transparente às diferenças sintáticas dessas linguagens.
  • Isolamento de Bancos de Dados por Conexão: Com a integração do DbConnectionHelper, você pode definir em qual conexão o log de auditoria deve ser gravado. Isso permite, por exemplo, guardar logs em um banco de segurança apartado do banco principal da aplicação, apenas com configurações simples.
  • UUID de Requisição Unificado: Gera um request_id único no formato de UUID v4 para cada requisição HTTP que chega à aplicação. Mesmo se o ciclo da requisição disparar 15 logs de auditoria diferentes em Controllers, Models e Queues, todos compartilharão o mesmo request_id, permitindo rastrear o fluxo completo de uma única ação do usuário.
  • Máscara Automática de Segredos (GDPR/LGPD): Analisa de forma recursiva todos os arrays de dados passados antes/depois da gravação e substitui valores de chaves sensíveis parametrizadas (como senha, password, token, numero_cartao, cvv) pelo placeholder de segurança "***** [masked]".
  • Rastreamento Completo de Contexto: Coleta e grava de forma segura informações do IP do cliente (atrás de proxies), o User-Agent, a URI acessada, o método HTTP, o referer e dados completos do usuário logado (ID, nome e username).
Estrutura física recomendada da tabela
CREATE TABLE `#__audit_logs` (
    `id` bigint(20) unsigned NOT NULL AUTO_INCREMENT,
    `uuid` char(36) NOT NULL,
    `request_id` char(36) NOT NULL,
    `event` varchar(64) NOT NULL,
    `category` varchar(64) NOT NULL,
    `level` varchar(32) NOT NULL,
    `status` varchar(32) NOT NULL,
    `entity_type` varchar(120) DEFAULT NULL,
    `entity_id` varchar(120) DEFAULT NULL,
    `parent_entity_type` varchar(120) DEFAULT NULL,
    `parent_entity_id` varchar(120) DEFAULT NULL,
    `user_id` int(10) unsigned DEFAULT NULL,
    `user_name` varchar(255) DEFAULT NULL,
    `user_username` varchar(255) DEFAULT NULL,
    `ip_address` varchar(64) NOT NULL,
    `user_agent` varchar(1000) NOT NULL,
    `request_method` varchar(10) NOT NULL,
    `request_uri` varchar(2000) NOT NULL,
    `referer` varchar(2000) DEFAULT NULL,
    `description` text DEFAULT NULL,
    `before_data` longtext DEFAULT NULL,
    `after_data` longtext DEFAULT NULL,
    `metadata` longtext DEFAULT NULL,
    `created_at` datetime NOT NULL,
    PRIMARY KEY (`id`),
    KEY `idx_request_id` (`request_id`),
    KEY `idx_event` (`event`),
    KEY `idx_entity` (`entity_type`, `entity_id`),
    KEY `idx_created_at` (`created_at`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

Configurações globais

Valores que controlam para onde os logs são gravados, mascaramento de chaves sensíveis e comportamento de rastreio.

setConnection() / getConnection()estático

AuditHelper::setConnection(string|null $connection): void
AuditHelper::getConnection(): string|null

Define a conexão alternativa cadastrada no DbConnectionHelper onde os logs de auditoria serão fisicamente guardados (ex: 'seguranca' ou 'erp'). Se nulo, utiliza a conexão padrão do Joomla.

setTable()estático

FileHelper::setTable(string $table): void

Muda o nome da tabela física no banco onde a auditoria será efetuada (padrão: '#__audit_logs').

setRequestId() / getRequestId()estático

AuditHelper::setRequestId(string $requestId): void
AuditHelper::getRequestId(): string

Define ou lê o ID de requisição unificado da sessão atual (UUID v4 padrão gerado de forma pseudo-aleatória forte).

addSensitiveKey()estático

AuditHelper::addSensitiveKey(string $key): void

Registra um nome de campo adicional a ser monitorado de forma recursiva e mascarado nos campos de dados de log, visando proteger dados sigilosos e assegurar conformidade de segurança.

Registro de Eventos

Métodos para auditoria manual de ações do sistema e atalhos semânticos de ciclo CRUD.

log()estático

AuditHelper::log(string $event, array $options = []): int

Método base que processa o contexto, limpa dados de segredo, limita os tamanhos de texto excessivos e realiza a inserção do registro no banco pelo ORM. Retorna o ID do registro inserido ou 0 em caso de falha controlada.

Opções aceitas no array:

Opção Tipo Padrão Descrição
category string 'application' Categoria semântica do log (ex: 'auth', 'payment', 'system').
level string 'info' Gravidade do evento (debug, info, warning, critical, etc.).
status string 'success' Resultado da ação (success, failure, denied, pending).
description string null Resumo amigável em linguagem natural sobre o que aconteceu.
entity_type string null Entidade principal de escopo afetada (ex: 'pedido', 'usuario').
entity_id string|int null Chave primária ou ID único da entidade afetada.
before array [] Array associativo descrevendo o estado dos dados **antes** da alteração.
after array [] Array associativo descrevendo o estado dos dados **depois** da alteração.
metadata array [] Informações auxiliares contextuais livre que se deseja guardar (ex: tempo de processamento, headers, flags).

created() / restored()estático

AuditHelper::created(string $entityType, string|int $entityId, array $afterData = [], array $options = []): int
AuditHelper::restored(string $entityType, string|int $entityId, array $afterData = [], array $options = []): int

Atalhos semânticos para registrar inserção física ou lógica de um registro de banco de dados.

updated()estático

AuditHelper::updated(string $entityType, string|int $entityId, array $dadosAntes, array $dadosDepois, array $options = []): int

Registra alterações em registros. Se a opção 'only_changes' => true (padrão) for mantida ativa, o helper realiza uma verificação recursiva e grava em `before_data` e `after_data` **apenas as chaves que realmente mudaram de valor**, economizando espaço no banco.

// Modificou apenas a coluna de saldo e o status do cliente
AuditHelper::updated(
    'cliente', 
    14, 
    ['saldo' => 150.00, 'status' => 'ativo', 'nome' => 'João'], // Antes
    ['saldo' => 50.00, 'status' => 'bloqueado', 'nome' => 'João'] // Depois
);
// before_data gravado no log:  {"saldo": 150.0, "status": "ativo"}
// after_data gravado no log:   {"saldo": 50.0, "status": "bloqueado"}

deleted()estático

AuditHelper::deleted(string $entityType, string|int $entityId, array $dadosAntes = [], array $options = []): int

Atalho semântico para registrar a exclusão (física ou lógica) de uma linha de dados no sistema.

Consulta e Limpeza

Leitura de dados agregada de logs estruturados e esvaziamento seguro de relatórios legados.

find()estático

AuditHelper::find(int $id): object|null

Localiza e retorna um log de auditoria específico cadastrado pela sua chave primária.

list()estático

AuditHelper::list(array $filters = [], int $limit = 50, int $offset = 0): array

Lista logs de auditoria aplicando filtros flexíveis de forma indexada. Retorna uma lista de objetos.

Filtros aceitos no array:

  • event: Nome do evento (ex: 'login_failed').
  • category: Categoria semântica.
  • status: Estado do evento (ex: 'denied').
  • level: Gravidade do evento.
  • entity_type / entity_id: Escopo de registro.
  • user_id: ID do usuário operador.
  • request_id: Chave de rastreio UUID v4 da requisição.
  • date_start: Data inicial de criação (inclusive, ex: '2026-10-01 00:00:00').
  • date_end: Data limite final de criação (inclusive).
  • search: Busca textual amigável em múltiplos campos ao mesmo tempo (com cláusula de `whereGroup` e `whereLike` em `description`, `event`, `entity_id` e nos nomes do usuário).

count()estático

AuditHelper::count(array $filters = []): int

Retorna a contagem agregada de registros de logs que atendam aos mesmos filtros de pesquisa estruturados.

purge()estático

AuditHelper::purge(string $dateBefore, int $limit = 1000): int

Exclui definitivamente registros de log que foram criados antes da data fornecida ($dateBefore), de forma escalável e segura. O método apaga em lotes limitados por $limit (máximo 10.000) por transação para poupar gargalo e lock de tabelas de produção em bancos de alta concorrência.

// Remover em bloco até 2000 logs de auditoria anteriores a 2025
$logsApagados = AuditHelper::purge('2025-01-01 00:00:00', 2000);

Exemplo prático no Controller

Abaixo, veja um exemplo prático de como utilizar o AuditHelper dentro de um Controller Joomla de CRUD de Clientes. O exemplo ilustra como auditar inserções, exclusões e modificações (fazendo o diff inteligente automático que registra apenas as colunas que mudaram de valor) e como capturar exceções imprevistas de banco.

Exemplo: Controller de Clientes com Trilhas de Auditoria (Audit Trail)
require_once JPATH_COMPONENT . '/helpers/InputHelper.php';
require_once JPATH_COMPONENT . '/helpers/AuditHelper.php';
require_once JPATH_COMPONENT . '/helpers/OrmTables.php';
require_once JPATH_COMPONENT . '/helpers/ApiResponseHelper.php';

class LojaControllerClientes extends JControllerLegacy
{
    /**
     * Salva ou atualiza um cliente e registra a trilha de auditoria correspondente
     */
    public function salvar()
    {
        JSession::checkToken() or jexit('Token inválido.');

        try {
            $id = InputHelper::int('id');
            $dadosForm = [
                'nome' => InputHelper::string('nome'),
                'email' => InputHelper::string('email'),
                'telefone' => InputHelper::string('telefone'),
                'saldo' => InputHelper::float('saldo'),
                'status' => InputHelper::string('status', 'ativo'),
                'senha' => InputHelper::string('senha') // O AuditHelper irá ofuscar esta chave automaticamente!
            ];

            $orm = OrmTables::table('#__clientes');

            if ($id > 0) {
                // --- MODO ATUALIZAÇÃO ---
                // 1. Carregar os dados atuais de antes para passar ao AuditHelper
                $clienteAntes = $orm->find($id);

                if (!$clienteAntes) {
                    return ApiResponseHelper::notFound('Cliente não encontrado.');
                }

                // Removemos o campo senha do update se ele estiver vazio
                if (empty($dadosForm['senha'])) {
                    unset($dadosForm['senha']);
                }

                // 2. Atualizar no banco via ORM
                $clienteDepois = $orm->update($id, $dadosForm);

                // 3. Registrar a trilha de auditoria de atualização
                // Dica: O AuditHelper comparará $clienteAntes com $clienteDepois e guardará 
                // apenas as colunas modificadas (ex.: se só o status mudou, só ele é gravado)
                AuditHelper::updated(
                    'cliente', 
                    $id, 
                    (array) $clienteAntes, 
                    (array) $clienteDepois, 
                    [
                        'category' => 'clientes_management',
                        'description' => 'Atualização cadastral do cliente #' . $id
                    ]
                );

                return ApiResponseHelper::success('Cliente atualizado com sucesso.', $clienteDepois);
            } else {
                // --- MODO CRIAÇÃO ---
                // 1. Criar novo registro de cliente no banco via ORM
                $novoCliente = $orm->create($dadosForm);

                // 2. Registrar a auditoria de criação física de registro
                AuditHelper::created(
                    'cliente', 
                    $novoCliente->id, 
                    (array) $novoCliente, 
                    [
                        'category' => 'clientes_management',
                        'description' => 'Cadastro de novo cliente'
                    ]
                );

                return ApiResponseHelper::success('Cliente criado com sucesso.', $novoCliente);
            }

        } catch (Throwable $e) {
            // Se houver qualquer falha física de banco ou regra de negócio imprevista, 
            // registramos a exceção na tabela de auditoria com nível critical e status de falha
            AuditHelper::exception($e, [
                'category' => 'security',
                'metadata' => [
                    'payload_enviado' => $dadosForm,
                    'cliente_id_tentado' => $id
                ]
            ]);

            return ApiResponseHelper::exception($e, 'Não foi possível salvar o cliente.');
        }
    }

    /**
     * Exclui um cliente e audita a remoção com os dados históricos que sumiram do banco
     */
    public function excluir()
    {
        JSession::checkToken() or jexit('Token inválido.');

        try {
            $id = InputHelper::int('id');

            if ($id <= 0) {
                return ApiResponseHelper::badRequest('ID de cliente inválido.');
            }

            $orm = OrmTables::table('#__clientes');
            
            // 1. Carregar os dados históricos que serão removidos para auditoria de histórico
            $clienteAntes = $orm->find($id);

            if (!$clienteAntes) {
                return ApiResponseHelper::notFound('Cliente não encontrado para exclusão.');
            }

            // 2. Excluir fisicamente do banco
            $orm->delete($id);

            // 3. Auditar a exclusão, salvando todos os dados que deixaram de existir
            AuditHelper::deleted(
                'cliente', 
                $id, 
                (array) $clienteAntes, 
                [
                    'category' => 'clientes_management',
                    'description' => 'Cliente removido permanentemente do sistema.'
                ]
            );

            return ApiResponseHelper::success('Cliente excluído com sucesso.');

        } catch (Throwable $e) {
            AuditHelper::exception($e, [
                'category' => 'security',
                'metadata' => ['cliente_id_tentado' => $id]
            ]);

            return ApiResponseHelper::exception($e, 'Não foi possível excluir o cliente.');
        }
    }
}
