AbstractJob, JobRegistry e worker

Escreva jobs, registre-os e execute a fila pela linha de comando ou de dentro do PHP, no Joomla 3, 4 e 5.

Visão geral

Estas são as peças que executam os jobs. O fluxo completo, com exemplos de ponta a ponta, está no guia da fila.

ClasseArquivoVocê usa para
AbstractJobfila/AbstractJob.phpEscrever jobs.
JobRegistryfila/JobRegistry.phpDizer qual classe processa cada tipo, e em qual fila.
QueueWorkerfila/QueueWorker.phpExecutar jobs de dentro do PHP (controller, tarefa agendada).
Worker CLIfila/cli/queue-worker.phpExecutar jobs pela linha de comando (cron, supervisor).

AbstractJob

Classe base de todo job. Implemente handle(); o restante já está pronto.

class EnviarEmailJob extends AbstractJob
{
    public function handle()
    {
        $para = $this->getPayload('para');

        if (!filter_var($para, FILTER_VALIDATE_EMAIL)) {
            return $this->fail('E-mail inválido: ' . $para, true);
        }

        Mailer::enviar($para, $this->getPayload('modelo'));

        return ['enviado_para' => $para];    // vira o resultado do job
    }
}

handle()

abstract public function handle(): mixed

O trabalho do job. O que acontece depois depende de como ele termina:

  • Devolve um array (ou nada) sem ter chamado complete()/release()/fail(): o worker conclui o job com esse array como resultado. Um valor que não é array vira ['retorno' => valor].
  • Chamou complete(), release() ou fail(): o worker respeita.
  • Lança exceção: o worker chama fail() com a classe, a mensagem, o arquivo e a linha.

MétodoDevolve

Tempo e parada

shouldStop()

public function shouldStop(int $margemSegundos = 10): bool

Diz se o job deve parar agora e devolver o controle. Chame dentro de laços longos.

  • faltam menos de $margemSegundos para o timeout_seconds;
  • o job foi cancelado ou o lock foi perdido (confere com um heartbeat() no máximo a cada 15 segundos);
  • o worker recebeu SIGTERM/SIGINT.
foreach ($lotes as $i => $lote) {
    if ($i < $this->getProgress()) {
        continue;                          // já processado numa execução anterior
    }

    $this->processar($lote);
    $this->progress($i + 1, count($lotes));

    if ($this->shouldStop()) {
        return $this->release();           // continua na próxima execução
    }
}

return $this->complete();
MétodoDevolve
elapsedSeconds()Segundos desde o início desta execução.
remainingSeconds()Segundos até o timeout_seconds.
lostLock()true se algum heartbeat()/progress() já indicou que o job foi cancelado ou assumido por outro worker.
isFinished()true depois de um complete(), release() ou fail() bem-sucedido.

O intervalo mínimo entre os heartbeats automáticos do shouldStop() fica na propriedade protected $intervaloHeartbeat = 15; redefina-a no seu job se precisar.

Ações

MétodoFaz
progress($feito, $total = null)Salva o progresso e renova o lock. false se o job não é mais deste worker.
heartbeat()Só renova o lock. Para trechos longos sem progresso mensurável.
complete(array $resultado = [])Conclui com sucesso.
release($atrasoSegundos = 0, $contaTentativa = false)Pausa e devolve à fila. Por padrão não gasta tentativa.
fail($mensagem, $definitivo = false)Registra erro. $definitivo = true vai direto para failed.

Todos devolvem bool e correspondem aos métodos de mesmo nome do QueueHelper.

JobRegistry

Liga cada tipo de job à classe que o processa e à fila em que roda. O push() usa a fila registrada; o worker usa a classe.

register()estático

JobRegistry::register(string $tipo, string|null $arquivo, string $classe, string $fila = 'default'): void

Registra um tipo. $arquivo é carregado com require_once na primeira vez que um job do tipo for executado; use null se a classe já estiver carregada ou tiver autoload. Registrar o mesmo tipo de novo substitui o registro.

JobRegistry::register('gerar_pdf', JPATH_COMPONENT . '/jobs/GerarPdfJob.php', 'GerarPdfJob', 'relatorios');
JobRegistry::register('enviar_email', null, 'Seucomp\\Jobs\\EnviarEmailJob', 'emails');   // com autoload

registerMany()estático

JobRegistry::registerMany(array $jobs): void

Vários de uma vez.

JobRegistry::registerMany([
    'gerar_pdf' => ['file' => $base . '/jobs/GerarPdfJob.php', 'class' => 'GerarPdfJob', 'queue' => 'relatorios'],
    'enviar_email' => ['file' => $base . '/jobs/EnviarEmailJob.php', 'class' => 'EnviarEmailJob', 'queue' => 'emails'],
]);
MétodoFaz
has($tipo)O tipo está registrado?
getQueue($tipo)Fila do tipo, ou null.
typesByQueue($fila)Tipos de uma fila. 'all' devolve todos.
resolve($job)Cria a instância do job a partir da linha da fila. Lança exceção se o tipo, o arquivo ou a classe não existirem, ou se a classe não herdar AbstractJob.
all()Todos os registros.
forget($tipo), flush()Remove um registro, ou todos.

QueueWorker

run()estático

QueueWorker::run(array $opcoes = []): array

O laço do worker: recupera locks expirados, reserva um job, executa, registra o resultado e repete, até um dos limites. O worker CLI é só uma casca em volta deste método; use-o direto em controllers e tarefas agendadas.

Retorna: resumo: processados, concluidos, liberados, falhas, cancelados, recuperados, motivo (por que parou) e segundos.

$resumo = QueueWorker::run([
    'queue' => 'emails',
    'max_time' => 50,
    'stop_when_empty' => true,
    'output' => function ($mensagem) {
        JLog::add($mensagem, JLog::INFO, 'fila');
    },
]);

// ['processados' => 12, 'concluidos' => 11, 'liberados' => 0, 'falhas' => 1,
//  'cancelados' => 0, 'recuperados' => 0, 'motivo' => 'fila vazia', 'segundos' => 8.4]
OpçãoPadrãoDescrição
queue'all'Fila a consumir.
typesos da fila no JobRegistryTipos aceitos.
oncefalseProcessa no máximo um job e sai.
stop_when_emptyfalseSai quando não houver job disponível.
max_jobs0Sai depois de N jobs (0 = sem limite).
max_time0Sai depois de N segundos (0 = sem limite). O job em andamento termina antes.
memory_mb256Sai quando o uso de memória passar de N MB (0 = sem limite).
sleep3Segundos de espera com a fila vazia.
release_expiredtrueRecupera jobs de workers mortos ao iniciar e a cada minuto.
output—callable que recebe cada mensagem do worker.
started_byhost:pidIdentificação gravada nos jobs.

Proteções

SituaçãoO que o worker faz
handle() lança exceçãofail() com classe, mensagem, arquivo e linha.
handle() termina sem concluircomplete() com o retorno de handle().
Erro fatal (memória esgotada, por exemplo), exit() ou estouro do tempoUm shutdown handler desfaz a transação aberta pelo job e chama fail() antes de o processo morrer: o job vai para retry na hora, sem esperar o lock expirar.
Tempo de execuçãoAntes de cada job, limita o PHP a timeout_seconds + 15 segundos (set_time_limit), e restaura depois.
SIGTERM/SIGINT (com a extensão pcntl)Termina o job atual e sai. Um segundo sinal encerra na hora. O job pode sair antes com shouldStop().
Worker morto sem aviso (kill -9, queda do servidor)Outro worker recupera o job depois de retry_after_seconds (releaseExpiredLocks()).
MétodoFaz
QueueWorker::processar($job)Executa um job já reservado com QueueHelper::next(), com todas as proteções. Devolve a chave do resumo (concluidos, liberados, falhas ou cancelados).
QueueWorker::requestStop()Pede para parar depois do job atual (o mesmo que o SIGTERM).
QueueWorker::stopRequested()Uma parada foi pedida?

Worker CLI

fila/cli/queue-worker.php inicia o Joomla na linha de comando, carrega o QueueHelper e as classes da pasta fila/, carrega o seu --bootstrap e roda o QueueWorker. O mesmo arquivo funciona no Joomla 3, 4 e 5.

php components/com_seucomp/helpers/fila/cli/queue-worker.php --bootstrap=components/com_seucomp/jobs/jobs.php [opções]
OpçãoDescrição
--bootstrap=ARQUIVOArquivo PHP que registra os jobs (e carrega o que eles usam). Praticamente obrigatório.
--queue=NOMEFila a consumir. Padrão: todas.
--onceProcessa no máximo um job e sai. Bom para testar.
--stop-when-emptySai quando a fila esvaziar.
--max-jobs=NSai depois de N jobs.
--max-time=NSai depois de N segundos. Padrão 240. 0 = sem limite (supervisor/systemd).
--memory=NSai acima de N MB. Padrão 256.
--sleep=NEspera com a fila vazia. Padrão 3.
--root=PASTARaiz do Joomla. Padrão: procurada subindo a partir da pasta do script.
--installCria a tabela da fila, se não existir, e sai.
--statsMostra quantos jobs há em cada status e sai (aceita --queue).
--quietNão escreve na saída.
--helpMostra a ajuda.

Código de saída: 0 quando termina normalmente, 1 em erro de inicialização (Joomla não encontrado, arquivo ausente). As mensagens saem com data e hora, prontas para um arquivo de log.

Como ele inicia cada versão

VersãoDetectada porInicia com
Joomla 3não há libraries/bootstrap.phpimport.legacy.php + cms.php e uma JApplicationCli como aplicação.
Joomla 4 e 5há libraries/bootstrap.phpincludes/framework.php, sessão de CLI e a aplicação de console do Joomla. No 5, carrega também os nomes antigos (JFactory, JLog…), que normalmente vêm do plugin de compatibilidade.

Rode o worker com o mesmo usuário do servidor web (por exemplo, www-data), nunca como root: arquivos que os jobs criarem precisam continuar acessíveis pelo site.

Se preferir integrar ao console do Joomla 4/5 (php cli/joomla.php fila:processar), crie um plugin de console cujo comando chame QueueWorker::run(): as opções são as mesmas.
