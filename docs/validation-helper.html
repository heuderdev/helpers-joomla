ValidationHelper

Valide formulários e APIs com regras declarativas e mensagens em português, inclusive listas de itens e regras que consultam o banco.

Visão geral

O ValidationHelper confere um array de dados contra um conjunto de regras e devolve, de uma vez, todas as mensagens de erro, em português e prontas para mostrar ao usuário.

require_once JPATH_COMPONENT . '/helpers/ValidationHelper.php';

$resultado = ValidationHelper::validate(
    array(
        'nome' => 'Ana',
        'email' => 'ana@',
        'cpf' => '52998224725',
    ),
    array(
        'nome' => 'required|max_length:150',
        'email' => 'required|email',
        'cpf' => 'required|cpf',
    )
);

if (!$resultado['valid']) {
    echo $resultado['first_error'];   // "O campo Email deve conter um e-mail válido."
}

O resultado

ChaveTipoConteúdo
validbooltrue se nenhuma regra falhou.
errorsarray['campo' => ['mensagem', …]]. Um campo pode ter várias mensagens. Vazio quando válido.
first_errorstring|nullA primeira mensagem, para avisos curtos ("toast").
// Formato de $resultado['errors']
$erros = array(
    'email' => array('O campo Email deve conter um e-mail válido.'),
    'itens.1.quantidade' => array('O campo Quantidade (item 2) deve ser maior ou igual a 1.'),
);

Em controllers que respondem JSON, ApiResponseHelper::fromValidation($resultado) já monta a resposta de erro, com a lista de erros, a primeira mensagem e HTTP 422.

O helper valida; ele não converte nem limpa os dados. Leia os valores com o InputHelper e valide o array resultante. Veja o padrão no controller.

Como escrever regras

As regras de cada campo podem ser escritas de três formas, que podem ser combinadas:

$regras = array(
    // 1. String separada por |
    'nome' => 'required|max_length:150',

    // 2. Array de regras
    'email' => array('required', 'email', 'max_length:150'),

    // 3. Chave => valor: parâmetros como array, ou uma função
    'status' => array('required', 'in' => array('aberto', 'pago', 'cancelado')),
    'codigo' => array('regex' => '/^(PED|ORC)-\d{4}$/'),
    'email_comercial' => array(
        'email',
        'unique' => function ($email) {
            return !OrmTables::table('#__loja_clientes')->where('email', $email)->exists();
        },
    ),
);
ElementoSignificado
regraRegra sem parâmetros: required, email.
regra:p1,p2Regra com parâmetros separados por vírgula: between:1,10, in:a,b.
'regra' => array(…)Parâmetros como array: permite valores que contêm vírgula.
'regra' => functionRegra personalizada; a mensagem de erro é a da regra (por exemplo, unique).
function sem chaveRegra personalizada com a mensagem genérica callback.
callback:Classe::metodoMétodo estático de uma classe, pelo nome.

regex numa string: como o padrão pode conter | e vírgulas, ela precisa ser a última regra da string: 'required|regex:/^(a|b)$/'. Em caso de dúvida, use a forma 'regex' => '/…/'.

Como a validação funciona

Campos são opcionais por padrão

Um campo vazio (ausente, null, texto só com espaços, lista vazia ou arquivo não enviado) só é verificado pelas regras de presença: required, required_if, required_with e accepted. As demais regras só se aplicam quando há valor.

'telefone' => 'phone'            // vazio: válido.  "123": inválido
'email' => 'required|email'      // vazio: só "obrigatório", sem "e-mail inválido" junto
'cnpj' => 'required_if:tipo,pj|cnpj'   // tipo = pf e cnpj vazio: válido

A regra nullable existe para deixar a intenção explícita, mas não muda nada: todo campo sem regra de presença já é opcional.

0, '0' e false são valores: passam no required. Para "o checkbox precisa estar marcado", use accepted.

Todas as regras são verificadas

Quando o campo tem valor, todas as regras rodam, e o campo pode acumular mais de uma mensagem. Os campos aparecem em errors na ordem em que as regras foram declaradas.

// 'codigo' => 'integer|max_length:5' com "abcdefgh":
'codigo' => array(
    'O campo Codigo deve ser um número inteiro válido.',
    'O campo Codigo deve ter no máximo 5 caracteres.',
)

Campos aninhados e listas

Use ponto para chegar em campos dentro de arrays, e * para validar cada item de uma lista:

$dados = array(
    'endereco' => array('cep' => '01310-100', 'numero' => '100'),
    'itens' => array(
        array('produto_id' => 7, 'quantidade' => 2),
        array('produto_id' => '', 'quantidade' => 0),
    ),
);

$resultado = ValidationHelper::validate($dados, array(
    'endereco.cep' => 'required|cep',
    'itens' => 'required|array|min:1',              // a lista em si: ao menos 1 item
    'itens.*.produto_id' => 'required|integer',     // cada item
    'itens.*.quantidade' => 'required|integer|min:1',
));

// errors:
// 'itens.1.produto_id' => ['O campo Produto id (item 2) é obrigatório.']
// 'itens.1.quantidade' => ['O campo Quantidade (item 2) deve ser maior ou igual a 1.']
DetalheComportamento
Chave do erroO caminho real do item: itens.1.quantidade (índice começando em 0).
RótuloNome do campo + número do item, contando a partir de 1: Quantidade (item 2). Rótulo personalizado por padrão: 'itens.*.quantidade' => 'Quantidade'.
Lista vazia ou ausenteAs regras com * não têm itens para validar e não geram erro. Para exigir itens, valide a própria lista: 'itens' => 'required|array|min:1'.
Vários níveisgrupos.*.itens.*.valor também funciona.
Lista de valores simples'tags.*' => 'max_length:30' valida cada valor da lista.

Catálogo de regras

Presença

RegraParâmetrosVálido quandoExemplo
required—O campo tem valor (não é ausente, null, só espaços nem lista vazia).'nome' => 'required'
required_ifcampo, valor1, valor2…Obrigatório quando o outro campo tem um dos valores.'cnpj' => 'required_if:tipo,pj'
required_withcampo1, campo2…Obrigatório quando algum dos outros campos foi preenchido.'senha_confirmacao' => 'required_with:senha'
accepted—Marcado/aceito: 1, true, on, yes, sim. Ausente é inválido.'termos' => 'accepted'
nullable—Sempre. Apenas documenta que o campo é opcional.'apelido' => 'nullable|max_length:30'

Tipos

RegraParâmetrosVálido quandoExemplo
string—É texto (is_string). Um número inteiro do PHP falha.'nome' => 'string'
integer, int—Inteiro: 42 ou "42", "-3". Não aceita "+5", " 5" nem "4.0".'idade' => 'integer'
numeric—Número no formato do PHP: "10.5", "1e3". Não aceita "10,5".'latitude' => 'numeric'
decimal—Número digitado por pessoas: "10,5", "1.234,56", "1,234.56", "R$ 9,90". Recusa "1.2.3".'preco' => 'decimal'
boolean, bool—true/false, 0/1, on/off, yes/no, y/n, sim/não, s/n.'ativo' => 'boolean'
array—É um array.'itens' => 'array'
json—Texto JSON válido, ou já um array.'config' => 'json'

Tamanho e intervalo

RegraParâmetrosVálido quandoExemplo
minnNúmero ≥ n; texto com ≥ n caracteres; lista com ≥ n itens.'quantidade' => 'integer|min:1'
maxnNúmero ≤ n; texto com ≤ n caracteres; lista com ≤ n itens.'desconto' => 'decimal|max:100'
betweenmin, maxEntre os limites, inclusive (mesma lógica de min/max).'nota' => 'between:0,10'
min_lengthnTexto com pelo menos n caracteres.'senha' => 'min_length:8'
max_lengthnTexto com no máximo n caracteres.'nome' => 'max_length:150'
lengthnTexto com exatamente n caracteres.'uf' => 'length:2'

min, max e between comparam o valor sempre que o texto parece um número, inclusive no formato brasileiro ("1.234,56" = 1234,56). Para tamanho de textos só com dígitos (CEP, código, telefone), use min_length/max_length/length: com min:8, um CEP "9" passaria (9 ≥ 8).

Valores permitidos

RegraParâmetrosVálido quandoExemplo
inv1, v2…O valor está na lista (comparado como texto).'status' => 'in:aberto,pago'
not_inv1, v2…O valor não está na lista.'usuario' => 'not_in:admin,root'

Para valores que contêm vírgula, use a forma com chave: 'faixa' => array('in' => array('0,5', '1,0')).

Formatos

RegraParâmetrosVálido quandoExemplo

urlesquemas (opcional)URL válida com esquema http ou https. Outros esquemas só se informados.'site' => 'url' 'repo' => 'url:https,git'
uuid—UUID versões 1 a 8.'token' => 'uuid'

Documentos e contatos (Brasil)

RegraParâmetrosVálido quandoExemplo
cpf—CPF com dígitos verificadores corretos. Aceita com ou sem máscara.'cpf' => 'cpf'
cnpj—CNPJ com dígitos verificadores corretos. Aceita com ou sem máscara.'cnpj' => 'cnpj'

Sequências repetidas (111.111.111-11) são recusadas.

Datas e horários

RegraParâmetrosVálido quandoExemplo
dateformato (opcional)Data de calendário válida. Padrão Y-m-d.'nascimento' => 'date' 'venc' => 'date:d/m/Y'
date_br—Data válida no formato DD/MM/AAAA.'nascimento' => 'date_br'
datetimeformato (opcional)Data e hora válidas. Padrão Y-m-d H:i:s.'agendado' => 'datetime:Y-m-d H:i'
timeformato (opcional)Horário válido. Sem formato, aceita H:i e H:i:s.'abertura' => 'time'
aftercampo ou dataData posterior à referência.'entrega' => 'after:today'
after_or_equalcampo ou dataData igual ou posterior.'fim' => 'after_or_equal:inicio'
beforecampo ou dataData anterior.'nascimento' => 'before:today'
before_or_equalcampo ou dataData igual ou anterior.'inicio' => 'before_or_equal:fim'

A referência de after/before pode ser o nome de outro campo dos dados, ou uma data: today, now, tomorrow, yesterday, 2026-01-01, 01/01/2026. Datas no formato DD/MM/AAAA são lidas corretamente (e não como mês/dia).

$resultado = ValidationHelper::validate($periodo, array(
    'inicio' => 'required|date',
    'fim' => 'required|date|after_or_equal:inicio',
), array(), array(
    'inicio' => 'data inicial',
    'fim' => 'Data final',
));
// "O campo Data final deve ser uma data igual ou posterior a data inicial."

Comparação entre campos

RegraParâmetrosVálido quandoExemplo
samecampoIgual ao outro campo (comparação exata, inclusive do tipo).'senha_confirmacao' => 'same:senha'
differentcampoDiferente do outro campo.'nova_senha' => 'different:senha_atual'

Por ser exata, same considera "1" e 1 diferentes. Leia os dois campos do mesmo jeito.

Arquivos

O valor é o array de upload (name, tmp_name, error, size), como devolvido por InputHelper::file().

RegraParâmetrosVálido quandoExemplo
file—Upload concluído sem erro.'documento' => 'required|file'
file_sizetamanho máximoAté o tamanho informado: bytes (2048) ou 500K, 2M, 1G.'documento' => 'file_size:5M'
file_extensionext1, ext2…Extensão do nome está na lista (sem diferenciar maiúsculas).'foto' => 'file_extension:jpg,png'
file_mimetipo1, tipo2…Tipo real do conteúdo (lido do arquivo, com finfo).'foto' => 'file_mime:image/jpeg,image/png'
image—O conteúdo é uma imagem (JPEG, PNG, GIF, WebP…).'foto' => 'image'
image_dimensionslargura, altura máximasImagem dentro das dimensões (0 = sem limite).'avatar' => 'image_dimensions:1024,1024'

file_extension olha só o nome do arquivo, que vem do navegador e pode ser falsificado. Combine sempre com file_mime ou image, que leem o conteúdo:

'documento' => 'required|file|file_size:5M|file_extension:pdf|file_mime:application/pdf',
'foto' => 'file|image|file_size:2M|file_extension:jpg,jpeg,png|image_dimensions:2000,2000',

Regras personalizadas

RegraParâmetrosVálido quandoExemplo
uniquefunçãoA função devolve verdadeiro (valor livre). Mensagem: "já está em uso".
existsfunçãoA função devolve verdadeiro (valor existe). Mensagem: "não foi encontrado".
callbackfunção ou Classe::metodoA função devolve verdadeiro. Mensagem: "é inválido".'cupom' => 'callback:Cupons::valido'

Toda função de regra recebe ($valor, $dados, $campo) e pode devolver:

RetornoResultado
verdadeiro (true, 1…)válido
false, null, 0 (inclusive esquecer o return)inválido, com a mensagem da regra
uma stringinválido, com essa string como mensagem (aceita :field)
$id = InputHelper::uint('id', 0, 'post');

$regras = array(
    'email' => array(
        'required',
        'email',
        // unique: o e-mail não pode pertencer a OUTRO cliente
        'unique' => function ($email) use ($id) {
            return !OrmTables::table('#__loja_clientes')
                ->where('email', $email)
                ->where('id', '!=', $id)
                ->exists();
        },
    ),
    'cliente_id' => array(
        'required',
        'integer',
        'exists' => function ($clienteId) {
            return OrmTables::table('#__loja_clientes')->where('id', (int) $clienteId)->exists();
        },
    ),
    'cupom' => array(
        function ($codigo, $dados) {
            $cupom = OrmTables::table('#__loja_cupons')->where('codigo', $codigo)->first();

            if ($cupom === null) {
                return 'Cupom não encontrado.';
            }

            if ($cupom->validade < date('Y-m-d')) {
                return 'Este cupom expirou.';
            }

            return true;
        },
    ),
);

Strings nunca são executadas como função: 'date', 'time' e 'file' são regras, não as funções do PHP. Para chamar um método pelo nome, use callback:Classe::metodo.

Mensagens e rótulos

As mensagens usam o rótulo do campo. Sem rótulo definido, ele é gerado do nome: data_nascimento vira "Data nascimento" e endereco.rua vira "Endereco rua", sem acentos. Defina rótulos para os campos que aparecem na tela:

$resultado = ValidationHelper::validate(
    $dados,
    $regras,
    // 3º parâmetro: mensagens
    array(
        'email.unique' => 'Já existe um cliente com este e-mail.',   // campo.regra
        'itens.*.quantidade.min' => 'Informe ao menos 1 unidade.',    // padrão com *
        'required' => 'Preencha o campo :field.',                     // regra (todos os campos)
    ),
    // 4º parâmetro: rótulos
    array(
        'data_nascimento' => 'Data de nascimento',
        'endereco.rua' => 'Rua',
        'itens.*.quantidade' => 'Quantidade',
    )
);

1campo.regra (por exemplo, email.unique)
2padrão.regra para itens de lista (itens.*.quantidade.min)
3regra, para todos os campos
4mensagem padrão do helper
MarcadorSubstituído porRegras

:valueo parâmetromin, max, min_length, max_length, length, file_size
:min, :maxos limitesbetween
:otherrótulo do outro camposame, different, required_with
:daterótulo do campo de referência, ou a data ("hoje", "amanhã"…)after, before…

Configuração global

Para não repetir rótulos e mensagens em todas as chamadas, configure uma vez no carregamento do componente. Os parâmetros de validate() valem só para aquela chamada e têm prioridade.

setLabels() / setCustomMessages() / reset()estático

ValidationHelper::setLabels(array $labels): void ValidationHelper::setCustomMessages(array $messages): void ValidationHelper::reset(): void

Rótulos e mensagens personalizadas para todas as validações seguintes do request. reset() remove os dois.

ValidationHelper::setLabels(array(
    'cpf' => 'CPF',
    'cnpj' => 'CNPJ',
    'cep' => 'CEP',
    'email' => 'e-mail',
));

setMessages()estático

ValidationHelper::setMessages(array $messages): void

Substitui as mensagens padrão das regras, por exemplo para padronizar o tom do sistema. A mudança vale até o fim do request: reset() não a desfaz.

ValidationHelper::setMessages(array(
    'required' => 'Preencha :field.',
    'email' => 'Informe um e-mail válido em :field.',
));

Métodos

validate()estático

ValidationHelper::validate(array $data, array $rules, array $messages = array(), array $labels = array()): array

Valida $data e devolve ['valid', 'errors', 'first_error']. Nunca lança exceção: se algo der errado internamente (por exemplo, uma função de regra lançar exceção), devolve inválido com o erro em errors['_system'] e registra o detalhe no log (categoria validation_helper).

passes() / fails()estático

ValidationHelper::passes(array $data, array $rules, array $messages = array(), array $labels = array()): bool ValidationHelper::fails(array $data, array $rules, array $messages = array(), array $labels = array()): bool

Só o resultado, sem as mensagens.

if (ValidationHelper::fails($filtros, array('de' => 'date', 'ate' => 'date|after_or_equal:de'))) {
    $filtros = array();   // ignora filtros inválidos da URL
}

firstError()estático

ValidationHelper::firstError(array $errors): string|null

A primeira mensagem de um array de erros. É o mesmo valor de first_error.

cpf() / cnpj() / email() / date() / file() / image()estático

ValidationHelper::cpf(string $cpf): bool ValidationHelper::cnpj(string $cnpj): bool ValidationHelper::email(string $email): bool ValidationHelper::date(string $date, string $format = 'Y-m-d'): bool ValidationHelper::file(array $file): bool ValidationHelper::image(array $file): bool

Validações avulsas de um único valor, com as mesmas regras do catálogo.

if (!ValidationHelper::cpf($cpf)) {
    return ApiResponseHelper::badRequest('CPF inválido.');
}

Padrão no controller

Ler com o InputHelper, validar, gravar e responder:

controllers/pedidos.php
public function criar()
{
    if (!JSession::checkToken()) {
        return ApiResponseHelper::forbidden('Token inválido.');
    }

    $dados = array(
        'cliente_id' => InputHelper::uint('cliente_id', null, 'post'),
        'entrega' => InputHelper::date('entrega', '', 'post'),
        'observacao' => InputHelper::text('observacao', '', 'post'),
        'itens' => InputHelper::array('itens', array(), 'post'),
        'termos' => InputHelper::bool('termos', false, 'post'),
    );

    $validacao = ValidationHelper::validate($dados, array(
        'cliente_id' => array(
            'required',
            'exists' => function ($id) {
                return OrmTables::table('#__loja_clientes')->where('id', $id)->exists();
            },
        ),
        'entrega' => 'required|date|after:today',
        'observacao' => 'max_length:500',
        'itens' => 'required|array|min:1|max:50',
        'itens.*.produto_id' => 'required|integer',
        'itens.*.quantidade' => 'required|integer|min:1',
        'termos' => 'accepted',
    ), array(
        'termos.accepted' => 'Aceite os termos para continuar.',
    ), array(
        'cliente_id' => 'Cliente',
        'entrega' => 'Data de entrega',
        'observacao' => 'Observação',
        'itens.*.produto_id' => 'Produto',
        'itens.*.quantidade' => 'Quantidade',
    ));

    if (!$validacao['valid']) {
        return ApiResponseHelper::fromValidation($validacao);
    }

    try {
        $pedido = PedidoService::criar($dados);

        return ApiResponseHelper::created('Pedido criado.', $pedido);
    } catch (Throwable $e) {
        return ApiResponseHelper::exception($e);
    }
}

Repare em 'termos' => 'accepted' com InputHelper::bool(): false passaria em required (é um valor), mas não em accepted.
