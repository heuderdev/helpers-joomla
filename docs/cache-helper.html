CacheHelper

Guarda resultados caros (dashboards, totais, respostas de APIs, listas de selects) no cache do Joomla com remember(): prazo por item, invalidação por prefixo e um único recálculo quando muitos pedidos chegam juntos.

Visão geral

require_once JPATH_COMPONENT . '/helpers/CacheHelper.php';

$totais = CacheHelper::remember('dashboard:totais', 300, function () {
    return array(
        'pedidos_hoje' => OrmTables::table('#__loja_pedidos')->whereBetween('created_at', ...)->count(),
        'faturamento_mes' => OrmTables::table('#__loja_pedidos')->where('status', 'pago')->sum('total'),
    );
});
  • Usa o cache do site: o handler escolhido na configuração global (arquivo, Redis, Memcached, APCu) e o botão "Limpar cache" do administrador. Funciona mesmo com o cache do site desligado (ele não afeta o CacheHelper).
  • Prazo por item, em segundos, conferido na leitura. null, false e arrays vazios também são guardados: "não encontrado" não vira consulta repetida.
  • Invalidação por prefixo sem percorrer itens: flushPrefix('dashboard').
  • Um recálculo só: com o LockHelper carregado, quando a chave expira e 50 pedidos chegam juntos, um calcula e os outros esperam o resultado (em vez de 50 consultas pesadas ao mesmo tempo).
  • Nunca derruba a página: se o armazenamento falhar, o valor é calculado e a página segue (o erro vai para o log cache).

Métodos

remember()estático

CacheHelper::remember(string $key, int $seconds, callable $callback, array $options = array()): mixed

Devolve o valor guardado ou executa o callback, guarda por $seconds e devolve. Exceção no callback não é guardada (sobe normalmente). Opções: 'lock' => false (não espera outros processos), 'lock_wait' => 10 (segundos esperando o recálculo de outro processo; depois disso calcula também).

rememberForever()estático

CacheHelper::rememberForever(string $key, callable $callback): mixed

Sem prazo: até forget(), flushPrefix() ou limpeza do cache. Para dados que você invalida ao alterar (configurações, listas de categorias).

get() / set() / has() / forget() / pull()estático

CacheHelper::get(string $key, mixed $default = null): mixed CacheHelper::set(string $key, mixed $value, int $seconds = 0): bool CacheHelper::has(string $key): bool CacheHelper::forget(string $key): bool CacheHelper::pull(string $key, mixed $default = null): mixed

Acesso direto. pull() lê e apaga.

flushPrefix()estático

CacheHelper::flushPrefix(string $prefix): bool

Invalida todas as chaves cujo trecho antes do primeiro : é $prefix. Custo constante: troca a "versão" do prefixo; os itens antigos deixam de ser lidos e expiram sozinhos.

flush()estático

CacheHelper::flush(): bool

Apaga tudo do grupo do CacheHelper (não o cache de páginas e módulos do site).

increment()estático

CacheHelper::increment(string $key, int $by = 1, int $seconds = 0): int

Contador simples. Não é atômico entre processos: para limitar tentativas use o RateLimitHelper.

setGroup() / setEnabled() / setController() / stats()estático

CacheHelper::setGroup(string $group): void CacheHelper::setEnabled(bool $enabled): void

Grupo do cache do Joomla (padrão helpers_cache; use com_loja para separar), desligar o cache (ex.: depurando), trocar o controlador (testes) e contadores hits, misses, writes da requisição.

Chaves e invalidação

Use assunto:detalhes. O assunto é o que você invalida junto; os detalhes, tudo que muda o resultado (filtros, página, usuário, idioma):

$chave = 'pedidos:lista:' . md5(json_encode(array($filtros, $pagina, $ordem)));
$lista = CacheHelper::remember($chave, 120, function () use ($filtros, $pagina, $ordem) { /* ... */ });

// Ao gravar um pedido: todas as listas e o dashboard ficam velhos
CacheHelper::flushPrefix('pedidos');
CacheHelper::flushPrefix('dashboard');

Dados de um usuário na chave de todos Se o resultado depende de quem pediu (permissões, "meus pedidos", preços por grupo), o id do usuário ou do grupo precisa estar na chave: 'meus-pedidos:' . $userId. Senão o primeiro a chegar define o que todos veem.

Invalidar ao gravar ou deixar expirar?

DadoEstratégia
Totais de dashboard, relatóriosprazo curto (1 a 10 min); ninguém precisa do número do segundo
Listas de selects (categorias, estados, formas de pagamento)rememberForever + flushPrefix no save do cadastro
Resposta de API externa (cotação, CEP)prazo do próprio dado (CEP: dias; cotação: minutos)
Token OAuthprazo um pouco menor que o expires_in (veja HttpHelper)
Saldo, estoque, status de pagamentonão use cache para decidir; no máximo para exibir

Receitas

// Configurações do componente lidas em toda requisição
$config = CacheHelper::rememberForever('config:loja', function () {
    return OrmTables::table('#__loja_config')->pluck('valor', 'chave');
});

// Model: invalida ao salvar
class ProdutoModel extends OrmBase
{
    protected $table = '#__loja_produtos';

    public static function salvar(array $dados)
    {
        $id = static::query()->create($dados)->id;
        CacheHelper::flushPrefix('produtos');

        return $id;
    }

    public static function vitrine()
    {
        return CacheHelper::remember('produtos:vitrine', 600, function () {
            return static::query()->where('ativo', 1)->orderBy('vendas', 'DESC')->limit(12)->get();
        });
    }
}

Guarde dados (arrays, escalares, objetos simples), não conexões, closures ou recursos. Objetos são serializados: a classe precisa estar carregada na leitura.
