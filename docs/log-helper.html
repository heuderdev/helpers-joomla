LogHelper

Logs do componente por categoria e nível, gravados pelo JLog do Joomla, com contexto da requisição (request_id, usuário, IP, URL) e mascaramento automático de senhas, tokens e cartões.

Visão geral

O LogHelper é a base de log dos outros helpers (ApiResponseHelper, DbTransactionHelper, PermissionHelper, FileHelper) e pode ser usado direto no seu código:

  • Um arquivo por categoria e nível: pagamento.error.php, api.info.php, na pasta de logs do Joomla (administrator/logs ou o log_path do configuration.php).
  • Contexto automático em toda linha: request_id, user_id, método, URL e IP.
  • Segredos mascarados: chaves como senha, token, authorization, cvv, api_key viram ********1234, inclusive dentro de arrays aninhados.
  • Nunca derruba a requisição: se o log falhar (pasta sem permissão, disco cheio), o método devolve false e o código segue.
require_once JPATH_COMPONENT . '/helpers/LogHelper.php';

LogHelper::info('Pedido criado.', 'pedidos', array('pedido_id' => 15, 'total' => 199.9));
LogHelper::error('Falha ao emitir nota.', 'fiscal', array('pedido_id' => 15, 'resposta' => $corpo));

try {
    // ...
} catch (Throwable $e) {
    LogHelper::exception($e, 'pedidos', array('pedido_id' => 15));
}
administrator/logs/pedidos.info.php
2026-10-05T14:30:12+00:00 INFO pedidos Pedido criado. | Contexto: {"request_id":"6f1c2a9e-...","user_id":42,"request_method":"POST","request_uri":"/index.php?option=com_loja&task=pedido.salvar","ip":"200.10.20.30","pedido_id":15,"total":199.9}

Níveis e categorias

MétodoQuando usar
debug()Detalhes para depurar; desligue em produção (setEnabled ou não chame).
info()Eventos normais que você quer poder rastrear (pedido criado, importação concluída).
notice()Algo incomum, mas esperado (cupom expirado usado, nova tentativa).
warning()Problema contornado (API lenta, valor ajustado, permissão negada).
error()A operação falhou.
critical() / alert() / emergency()Falha que exige ação imediata (pagamento sem confirmação, banco fora).

A categoria vira o nome do arquivo: só letras, números, _, . e - (o resto vira _), até 100 caracteres. Sem categoria, vale application (troque com setDefaultCategory()).

debug() … emergency()estático

LogHelper::info(string $message, string|null $category = null, array $context = array(), string|null $directory = null): bool

Grava a mensagem com o contexto. $directory troca a pasta só nesta chamada (relativa a JPATH_SITE ou absoluta dentro dela); também pode vir em $context['log_directory']. Devolve true se gravou.

Dados sensíveis

Toda chave do contexto que contenha um destes nomes tem o valor mascarado (só os 4 últimos caracteres ficam visíveis; valores com até 4 caracteres viram ****):

password, senha, token, csrf, authorization, bearer, api_key, apikey, secret, client_secret, access_token, refresh_token, private_key, credit_card, card_number, numero_cartao, cvv, cvc, security_code, cookie, session, sessid.

A comparação ignora maiúsculas e trata - e espaço como _: X-Api-Key, senha_atual e gateway_token são mascarados. Valores longos são cortados em 10 mil caracteres (...[truncado]).

LogHelper::addSensitiveKey('cpf');            // passa a mascarar cpf, cpf_titular...
LogHelper::addSensitiveKey('chave_pix');

$seguro = LogHelper::sanitize($_POST);       // o mesmo mascaramento, para usar fora do log

O mascaramento olha as chaves. Um segredo dentro de um texto livre ('resposta' => 'token=abc123...') ou na própria mensagem não é detectado: nunca concatene segredos na mensagem.

request_id

Cada requisição recebe um UUID v4, gravado em todas as linhas de log dela. O ApiResponseHelper devolve o mesmo valor em request_id nas respostas de erro, e o Vigia.js o expõe em e.requestId: com o número que a pessoa vê na tela (ou que vem no chamado), você acha todas as linhas daquela requisição.

LogHelper::getRequestId();                         // '6f1c2a9e-...'
LogHelper::setRequestId($_SERVER['HTTP_X_REQUEST_ID']);   // reaproveita o id do proxy/load balancer
grep -h '6f1c2a9e' administrator/logs/*.php

Configuração

MétodoO que faz
setEnabled(bool)Liga/desliga todo o log (ex.: em testes).
setDefaultCategory($categoria)Categoria quando nenhuma é informada (padrão application).
setBaseDirectory($pasta) / getBaseDirectory()Pasta dos logs. Precisa ficar dentro de JPATH_SITE; sem ../. É criada se não existir.
setDirectoryPermission(0750)Permissão das pastas criadas (padrão 0755).
setRequestId($id) / getRequestId()Define / lê o id da requisição.
addSensitiveKey($chave) / sanitize($dados)Mascaramento.
// No início do componente (ex.: loja.php)
LogHelper::setDefaultCategory('com_loja');
LogHelper::setBaseDirectory('administrator/logs/com_loja');   // separa os logs do componente

Os arquivos têm extensão .php e começam com #<?php die('Forbidden.'); ?> (padrão do JLog): mesmo numa pasta pública, não são servidos como texto. Ainda assim, prefira administrator/logs e não aponte o log para uma pasta de uploads.

Boas práticas

  • Uma categoria por assunto (pedidos, fiscal, integracao_erp): os arquivos ficam pequenos e fáceis de vigiar.
  • Contexto em vez de concatenação: info('Pedido pago.', 'pedidos', array('id' => $id)) e não info('Pedido ' . $id . ' pago.'). Fica pesquisável e mascarado.
  • Log não é auditoria: para "quem alterou o quê", com antes e depois, use o AuditHelper, que grava no banco.
  • Rotação: o JLog não apaga arquivos antigos. Use o logrotate do servidor ou um cron que comprima os logs mensais.
