WebhookHelper

Recebe webhooks (gateway de pagamento, ERP, WhatsApp, marketplace) do jeito certo: confere a assinatura, descarta reenvios do mesmo evento, guarda o evento, entrega para a fila e responde rápido com o status HTTP que o remetente entende.

Visão geral

controller.php
public function webhookPagamento()
{
    $params = JComponentHelper::getParams('com_loja');

    WebhookHelper::handle(array(
        'provider' => 'gateway',
        'secret' => $params->get('webhook_secret'),
        'signature_header' => 'X-Signature',
        'prefix' => 'sha256=',
        'job' => 'processar_pagamento',      // QueueHelper::push('processar_pagamento', array('webhook_id' => ...))
    ));
}
jobs/ProcessarPagamentoJob.php
class ProcessarPagamentoJob extends AbstractJob
{
    public function handle()
    {
        $id = $this->getPayload('webhook_id');
        $evento = WebhookHelper::payload($id);

        if ($evento['event'] === 'PAYMENT_RECEIVED') {
            PedidoService::marcarPago($evento['payment']['externalReference'], $evento['payment']['value']);
        }

        WebhookHelper::markProcessed($id);
    }
}

Os cinco erros que este helper evita:

  1. Aceitar qualquer POST: sem conferir a origem, qualquer um marca um pedido como pago. Sem secret, token ou verify, o helper recusa tudo (401).
  2. Processar duas vezes: remetentes reenviam o mesmo evento (timeout, erro de rede). O par (provider, id do evento) é único na tabela; reenvio responde 200 "já recebido" sem processar de novo.
  3. Responder devagar: muitos gateways desistem em 5 a 10 segundos e reenviam. Com job, a resposta sai em milissegundos e o trabalho vai para a fila.
  4. Perder o evento: o corpo cru é guardado antes de qualquer processamento; dá para reprocessar e auditar.
  5. Status HTTP errado: 2xx só quando o evento está seguro; 500 em falha nossa (o remetente tenta de novo); 401 em assinatura inválida; 400 em corpo inválido.

Conferindo a origem

EsquemaOpçõesExemplos
HMAC do corposecret, signature_header, prefix, encoding (hex/base64), algoGitHub (X-Hub-Signature-256, sha256=), Shopify (X-Shopify-Hmac-Sha256, base64), muitos gateways
Token fixo no cabeçalhotoken, token_headerAsaas (asaas-access-token), integrações internas
Outro (timestamp + assinatura, IP de origem, consulta à API)verify => function ($corpo, $cabecalhos)Stripe (t=...,v1=...), Mercado Pago (x-signature com ts)
// Token fixo (Asaas)
WebhookHelper::handle(array(
    'provider' => 'asaas',
    'token' => $params->get('asaas_webhook_token'),
    'token_header' => 'asaas-access-token',
    'type_path' => 'event',
    'id_path' => 'id',
    'job' => 'asaas_evento',
));

// Esquema próprio: assinatura de "timestamp.corpo" com tolerância de 5 minutos (estilo Stripe)
WebhookHelper::handle(array(
    'provider' => 'stripe',
    'verify' => function ($corpo, $cabecalhos) use ($segredo) {
        $partes = array();
        foreach (explode(',', isset($cabecalhos['stripe-signature']) ? $cabecalhos['stripe-signature'] : '') as $par) {
            $kv = explode('=', $par, 2);
            if (count($kv) === 2) { $partes[$kv[0]] = $kv[1]; }
        }
        if (empty($partes['t']) || empty($partes['v1']) || abs(time() - (int) $partes['t']) > 300) {
            return false;   // sem assinatura ou antiga demais (proteção contra reenvio capturado)
        }
        return CryptoHelper::verifySignature($partes['t'] . '.' . $corpo, $partes['v1'], $segredo);
    },
    'job' => 'stripe_evento',
));

Os nomes dos cabeçalhos são comparados sem diferenciar maiúsculas ($cabecalhos chega com chaves em minúsculas). A assinatura é calculada sobre o corpo cru, nunca sobre o JSON decodificado e recodificado.

Na fila ou na hora

OpçãoO que aconteceResposta
jobgrava, faz QueueHelper::push($job, array('webhook_id' => $id)), status na_fila200 em milissegundos
handlergrava e executa function ($payload, $registro); sem exceção vira processado, com exceção falhou200 ou 500 (o remetente reenvia e o evento é reprocessado)
nenhumsó grava (processe depois, por um cron)200

Prefira job: o processamento ganha as novas tentativas da fila e não segura a conexão do remetente. Um evento com status falhou ou recebido (gravado, mas não entregue) é reprocessado quando o remetente reenviar; com na_fila ou processado, reenvio é ignorado.

O job também precisa ser idempotente A fila pode repetir um job (worker interrompido). Faça o efeito depender do estado: "marcar pago se ainda não estiver pago", de preferência dentro de uma transação com lockForUpdate() ou com o LockHelper por pedido. Confira também o valor e o pedido no próprio gateway (pela API) antes de liberar algo caro.

Métodos

handle() / process()estático

WebhookHelper::handle(array $options): array WebhookHelper::process(array $options): array

handle() responde (pelo ApiResponseHelper) e devolve o resultado; process() só devolve. Resultado: status (queued, processed, duplicate, unauthorized, invalid, error), http, message, webhook_id, event_id, type.

Outras opções: id_path (caminho do id do evento no JSON, padrão id; sem id, o hash do corpo identifica reenvios idênticos), type_path (padrão event, depois type), job_options (do QueueHelper::push()), respond (false), body e headers (testes). Corpo em formulário (a=1&b=2) também é aceito.

payload() / find()estático

WebhookHelper::payload(int $webhookId): array|null WebhookHelper::find(int $webhookId): array|null

O evento decodificado; a linha inteira (provider, event_id, event_type, status, attempts, error, datas em UTC).

markProcessed() / markFailed()estático

WebhookHelper::markProcessed(int $webhookId): bool WebhookHelper::markFailed(int $webhookId, string $message): bool

Chame no fim do job (ou deixe a exceção subir para a fila tentar de novo).

verify()estático

WebhookHelper::verify(string $body, array $headers, array $options): bool

Só a conferência de origem, para fluxos próprios.

prune()estático

WebhookHelper::prune(int $days = 30): bool

Apaga eventos processados mais antigos que N dias (num cron). Falhos ficam para análise.

setTable() / setConnection()estático

WebhookHelper::setTable(string $table): void WebhookHelper::setConnection(mixed $connection): void

Tabela padrão #__helpers_webhooks, criada sozinha no primeiro uso (ou rode tables/webhookHelper.sql / .postgresql.sql).

A URL do webhook

  • Use uma task sem login e sem token CSRF (o remetente não tem sessão): index.php?option=com_loja&task=webhooks.pagamento&format=json. A autenticação é a assinatura.
  • Só HTTPS. Não coloque o segredo na URL (fica em logs de proxy).
  • Não use PermissionHelper::requireToken() nem JSession::checkToken() nessa task.
  • Limite por IP com o RateLimitHelper se a URL for pública e o remetente não tiver IP fixo.
