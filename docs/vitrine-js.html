Vitrine.js

O par do Vigia.js para telas de listagem (a página que exibe os seus registros, como uma vitrine): paginação, ordenação e filtros guardados na URL (F5 e "voltar" funcionam), busca com espera e cancelamento da requisição anterior, ações por linha e em lote, estados de carregando, vazio e erro. Fala com ApiResponseHelper::paginated() e InputHelper::pagination()/sorting()/filters().

controller.php
public function listar()
{
    try {
        if (!PermissionHelper::require('core.manage')) {
            return;
        }

        $paginacao = InputHelper::pagination(20, 100);                                     // page, limit
        $ordem = InputHelper::sorting(array('id', 'cliente', 'total', 'created_at'), 'created_at', 'DESC');   // sort, direction (lista branca)
        $filtros = InputHelper::filters(array('busca' => 'string', 'status' => 'cmd'));

        $resultado = OrmTables::table('#__loja_pedidos')
            ->when(isset($filtros['busca']) ? $filtros['busca'] : null, function ($q, $busca) {
                $q->whereGroup(function ($g) use ($busca) {
                    $g->whereLike('cliente', $busca)->orWhere('id', (int) $busca);
                });
            })
            ->when(isset($filtros['status']) ? $filtros['status'] : null, function ($q, $status) {
                $q->where('status', $status);
            })
            ->orderBy($ordem['field'], $ordem['direction'])
            ->paginate($paginacao['limit'], $paginacao['page']);

        return ApiResponseHelper::paginated($resultado);   // data = itens; meta.paginacao = total, por_pagina, pagina_atual, total_paginas
    } catch (Throwable $e) {
        return ApiResponseHelper::exception($e);
    }
}

Contrato com o servidor

A lista envia (GET)Lido por
page, limitInputHelper::pagination($padrao, $maximo)
sort, direction (ASC/DESC)InputHelper::sorting($permitidos, $padrao, $direcao): sempre com lista branca (o nome da coluna vira SQL)
cada campo do [data-vitrine-filters] (vazios não vão; x[] vira lista)InputHelper::filters(array('campo' => 'filtro'))

A resposta esperada é a do ApiResponseHelper::paginated(): data com a lista de itens e meta.paginacao com total, por_pagina, pagina_atual e total_paginas. Uma resposta sem meta.paginacao é tratada como página única.

Paginação no servidor

Cada página é uma requisição ao servidor com page e limit; o controller busca só aquelas linhas (LIMIT 20 OFFSET 260 no paginate()) e devolve o total para a navegação. Com 10.000 registros e 20 por página, o navegador recebe 20 linhas por vez, nunca as 10.000. A troca de página cancela a requisição anterior que ainda não respondeu.

Estilo jQuery Paginate

Uma faixa com um número fixo de páginas, setas que deslizam a faixa sem carregar nada (clique desliza uma página; segurar desliza contínuo, no mouse e no toque), botões Primeira/Última e "Página X de Y". Clicar num número busca aquela página no servidor; depois de carregar, a faixa centraliza a página atual.

Tabelas grandes de verdade 10 mil linhas é pouco para o banco. Acima de centenas de milhares, mantenha ORDER BY por coluna com índice (id, created_at), filtre por período e evite sort por colunas sem índice: o OFFSET das últimas páginas fica caro. Limite o tamanho máximo da página em InputHelper::pagination(20, 100).

controller.php (exportar o que está na tela)
public function exportar()
{
    if (!PermissionHelper::require('core.manage')) {
        return;
    }

    // Mesmos filtros e lista branca de ordenação da task listar()
    $ordem = InputHelper::sorting(array('id', 'cliente', 'total', 'created_at'), 'created_at', 'DESC');
    $filtros = InputHelper::filters(array('busca' => 'string', 'status' => 'cmd'));

    $db = JFactory::getDbo();
    $query = $db->getQuery(true)
        ->select('id, cliente, total, status, created_at')
        ->from('#__loja_pedidos')
        ->order($db->quoteName($ordem['field']) . ' ' . $ordem['direction'] . ', id');

    if (!empty($filtros['status'])) {
        $query->where('status = ' . $db->quote($filtros['status']));
    }

    ExportHelper::download('pedidos.csv', ExportHelper::generatorFromQuery($query), array(
        'id' => 'Pedido', 'cliente' => 'Cliente', 'total' => 'Total', 'status' => 'Status', 'created_at' => 'Data',
    ), array('utf8_bom' => true));

    JFactory::getApplication()->close();
}

No evento vitrine:loaded, e.detail.fromCache diz se a página veio da memória, e e.detail.appended traz só os itens novos no modo "carregar mais". Nos modos "carregar mais" e rolagem infinita, a URL guarda filtros e ordem, mas sempre recomeça da página 1. Template da linha

O <template data-vitrine-template> é clonado para cada item (o primeiro elemento dele vira a linha). Tudo é preenchido como texto: um cliente chamado <img onerror=...> aparece como texto, nunca executa.

AtributoEfeito
data-field="cliente.nome"texto do campo (caminhos com ponto)
data-format="money"money (R$ 1.234,50), number, integer, date, datetime, boolean (Sim/Não), cpf_cnpj, phone, ou um seu (Vitrine.formats.add)
data-href="...?id={id}", data-src, data-title, data-valueatributo com {campo} (em URLs, codificado); data-href="{link}" sozinho usa a URL pronta
data-attr-NOME="... {campo}"qualquer atributo (data-attr-aria-label, data-attr-data-id); atributos on* são ignorados
data-if="pago" / data-unless="pago"mantém o elemento só se o campo for verdadeiro / falso (0, '0', '', null, false e lista vazia são falsos)
data-class-NOME="campo"adiciona a classe NOME se o campo for verdadeiro (data-class-table-warning="atrasado")
data-selectcheckbox de seleção da linha (o valor é o id)
data-action="nome"botão de ação da linha (veja Ações)

Links com javascript:, data: ou vbscript: vindos dos dados viram #.

Filtros e busca

  • Campos de texto (text, search, email, tel, textarea) esperam a pessoa parar de digitar (350 ms; por campo: data-debounce="600"). Enter aplica na hora.
  • select, checkbox, rádio e datas aplicam ao mudar.
  • Ao filtrar, volta para a página 1 e limpa a seleção.
  • Uma busca nova cancela a anterior (AbortController): a resposta lenta de "C" nunca sobrescreve a de "Cli 7".
  • Campos com máscara e data-unmask do Vigia vão sem máscara. data-vitrine-reset volta filtros, ordem e tamanho iniciais.
const vitrine = Vitrine.of('#pedidos');

vitrine.filter({ status: 'pago', cliente_id: 15 });   // de fora do formulário (ex.: clique num gráfico)
vitrine.filter({ status: null });                      // remove o filtro

Estado na URL

Página, tamanho, ordem e filtros vão para a URL (?option=com_loja&view=pedidos&page=3&sort=total&direction=DESC&f_status=pago), só quando diferem do padrão. Recarregar, compartilhar o link e o botão "voltar" do navegador mantêm a tela. Os parâmetros que já estavam na URL (option, view, Itemid) ficam intactos.

  • Mais de uma vitrine na página: cada uma ganha um prefixo na URL automaticamente, o id do contêiner (<div id="pedidos" data-vitrine> → pedidos_page, pedidos_f_status). Sem id, usa a posição na página (vitrine2_page) e avisa no console: dê um id para o link continuar certo se a ordem das tabelas mudar. Para escolher o nome: data-vitrine-prefix="itens". Sem isso, as duas tabelas gravariam page e os filtros com os mesmos nomes e uma apagaria o estado da outra.
  • Sem mexer na URL (lista dentro de um modal): data-vitrine-history="false".

Duas ou mais vitrines na mesma página

Cada vitrine só procura as próprias partes dentro do seu contêiner: linhas, filtros, paginação, seleção, lote, mensagens, cache e requisições ficam separados. Os cuidados são:

  • Prefixo na URL: automático pelo id (veja acima). Para uma tabela que não precisa guardar estado na URL (dentro de um modal ou aba), use data-vitrine-history="false".
  • Preferências: um nome por tabela em data-vitrine-remember; o mesmo nome faria uma herdar o tamanho e a ordem da outra.
  • ids do seu HTML: ao copiar um bloco de filtros, troque os id (f-busca → f-busca-pedidos) para os <label for> continuarem certos.
  • Não aninhe uma vitrine dentro do contêiner de outra.

Ações por linha e em lote

data-action num botão da linha e data-batch-action fora da tabela. Sem código, a ação faz um POST para data-url (com {campo} do item e o token CSRF), mostra a mensagem da resposta em [data-vitrine-message] (ou no Joomla.renderMessages) e recarrega a página atual. Em lote, envia ids[] com os selecionados.

AtributoPadrãoO que faz
data-url—Para onde enviar (obrigatório sem função própria).

data-confirm—Confirmação; {campo} na linha, :count no lote.

controller.php
public function excluirLote()
{
    try {
        if (!PermissionHelper::requireToken() || !PermissionHelper::require('core.delete')) {
            return;
        }

        $ids = InputHelper::arrayOfInt('ids');

        if (!$ids) {
            return ApiResponseHelper::badRequest('Selecione ao menos um pedido.');
        }

        $total = OrmTables::table('#__loja_pedidos')->whereIn('id', $ids)->deleteWhere();

        return ApiResponseHelper::deleted($total . ' pedido(s) excluído(s).');
    } catch (Throwable $e) {
        return ApiResponseHelper::exception($e);
    }
}

O servidor confere a permissão de cada id (não basta a tela só mostrar os registros do usuário): whereIn('id', $ids)->where('user_id', $userId), ou PermissionHelper::canAccessEntity() por item.

Datas no formato do banco (Y-m-d H:i:s, gravadas em UTC pelo DateHelper) aparecem no fuso do navegador; datas só com dia (Y-m-d) não mudam de dia. No Joomla 3 (Bootstrap 2), troque as classes da paginação: classes: { pagination: 'pagination-list', pageItem: '', pageLink: '' } e envolva o <nav> numa div.pagination.

Acessibilidade

  • Cabeçalhos ordenáveis recebem aria-sort, foco pelo teclado e ativam com Enter/Espaço.
  • A lista recebe aria-busy enquanto carrega; a paginação usa aria-current="page" e rótulos nos botões de seta.
  • O checkbox "todos" fica indeterminado com seleção parcial; cada checkbox de linha ganha aria-label.
